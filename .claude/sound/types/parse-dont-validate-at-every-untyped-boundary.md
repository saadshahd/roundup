Data crossing an untyped boundary (HTTP body, DB row, env var, third-party SDK response, `JSON.parse`; in the Daemon a JSON-RPC request's `params`, a SQLite column, a hook payload) must be parsed into the domain type at that boundary and never trusted via a type assertion, or in Rust via `serde_json::Value` indexing, further downstream.
_Avoid_: `as Order`, `as any as Order`, or a generic type parameter on `fetch`/`JSON.parse` standing in for validation; in Rust, `value["field"].as_str()` past the function that received the raw `Value` instead of one `serde_json::from_value::<T>` (`rpc::params`) at that edge, or a text column kept as `String` and matched against literals downstream.
Detect: an `as <DomainType>` cast, or a bare type parameter, applied directly to the output of `fetch`, `JSON.parse`, a DB client call, or `process.env` — with no schema/parse call between the raw value and the cast; in Rust, `Value` indexing (`["…"]`, `.get(`, `.as_str()`, `.as_u64()`) outside the function that received the raw value, or a `String` read from a row and compared to literals away from the row-mapping closure.
Not-when: the value already came from a parse step earlier in the same call chain and is being re-narrowed for convenience (e.g. narrowing `unknown` to a known-good local variable inside the same function that just validated it). An `any`/`unknown`-typed parameter on an INTERNAL function is not a boundary — the rule governs data entering the process (IO), not loosely-typed in-process signatures.
