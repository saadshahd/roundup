**D8 the Daemon samples an Agent's Resource use when asked.** Given a Daemon whose Project holds an Agent (a fake `claude` that starts one child program and sleeps) and an Agent with no Worktree, when a client calls `project.resources` (no params), then the result is `{agents: [{id, memory_bytes, cpu_percent, disk_bytes}], total: {memory_bytes, cpu_percent, disk_bytes}}`, with one entry for each Agent whose program is running and none for an Agent that is `done`, and:

- **Memory and CPU cover the tree.** `memory_bytes` is the resident memory, and `cpu_percent` the share of one core since the previous sample (so 100 is one full core and a busy tree may exceed it), summed over the Agent's program and every program it started, however deep, found by parent links from the Agent's program (the Daemon knows an Agent by the same ancestry). A child that exits drops out of the next sample; one that is still running counts. The first call after an Agent starts reads `cpu_percent: 0`, because there is no earlier sample to subtract.
- **Disk is the Worktree.** `disk_bytes` is the recursive size of the Agent's Worktree directory (G1), and `null` for an Agent with no Worktree, never `0`. A Worktree the Agent no longer has on disk reads `null`.
- **Totals.** `total.memory_bytes` and `total.cpu_percent` are the sums over `agents`, and `total.disk_bytes` the sum of the non-null `disk_bytes` (`null` when every one is `null`). A Project with no running Agent returns `agents: []` and zeros, with `disk_bytes: null`.
- **No work unless asked.** The Daemon samples inside the call and in no other place: no timer, thread or watch runs between calls. Two calls less than one second apart return the first call's numbers. A disk size is recomputed at most once in 30 s for one Worktree, and the walk does not hold the call past 1 s: a size not ready returns the last one, or `null` before the first. The cost is bounded by rule 7 (`AGENTS.md:29`): `just perf` shows no regression above 10% and D4's ten idle Agents still grow the Daemon by under 150 MB, with `project.resources` called once a second for the whole of D4.
- **Reads nothing from the Agent.** The sampler reads the operating system's program table and the Worktree's file sizes only; it sends the Agent nothing and changes no Status, Message or file in the Project (N2).

Tests (`d8_`, in `crates/rup/tests/e2e/`, with the unit tests beside the sampler in `crates/rupd`): `d8_memory_and_cpu_sum_the_whole_tree` (the fake `claude` starts a child that holds 50 MB and spins; the entry's memory exceeds the child's and its CPU exceeds 50), `d8_a_child_that_exits_leaves_the_sum`, `d8_disk_is_the_worktrees_size_and_null_without_one`, `d8_totals_add_the_agents`, `d8_a_done_agent_has_no_entry`, `d8_the_first_cpu_reading_is_zero`, `d8_two_calls_within_a_second_share_one_sample`, `d8_a_disk_size_is_cached_for_30_s_and_the_walk_never_holds_the_call_past_1_s` (block the actual background walks through the sampler's injected walk function and assert cached bytes or `null` within 1 s, then release the walks and read their new sizes, without creating a huge directory; `d8_a_disk_size_is_cached_for_30_s_and_a_missing_worktree_reads_null` separately proves reuse, expiry at 30 s and missing-directory behavior with tiny files), `d8_sampling_sends_the_agent_nothing_and_changes_nothing` (the fake `claude` receives no input, and Status, Messages and the Project's files are equal before and after), `d8_nothing_runs_between_calls` (the Daemon's thread count and CPU time do not grow over 3 s with no call) and `d8_ten_idle_agents_with_sampling_stay_under_the_budget` (D4's body with the call added). The contract test in `crates/contracts` asserts the method's name and the two types; every caller of `contracts/generated/` is regenerated, never hand-edited.

**U408 the Resource strip shows the selected Agent's use.** Narrowed by U444 for icons and missing values and by U469 for the shared bottom bar. #1963 removes the Project label and totals from the App; D8's response, including `total`, remains acceptance. Given an open Project and a selected Agent (U59), when the centre shows its pane, then a one-line strip sits at the right of U469's bottom bar, below the Terminal pane, outside the Rail, the Shelf, the Drawer and the Rail's rows (so no `tree-40` row or width changes, U393):

- **Words.** The strip reads `memory 412 MB · cpu 18% · disk 2.1 GB` for the selected Agent only, in `--font-ui` at one type step (D2) in `--grey` (D5). Sizes are whole bytes read in 1000-based units: below 1000 the number and `B` (`0 B`, `999 B`); from `KB` up (`KB`, `MB`, `GB`, `TB`) the value in the largest unit that keeps it at 1 or more, rounded half up to one decimal below 100 and to none at 100 or above (`4.2 MB`, `2.1 GB`, `812 KB`, `412 MB`), and a value that rounds to 1000 moves to the next unit (`999.9 GB` bytes read `1.0 TB`); `TB` is the largest. CPU is a whole percent, rounded half up. U444 hides a negative, missing or `null` value with its icon; before the first result the strip has no values; after a failed `project.resources` it keeps the last values and adds `Not updating` in `--text` (U80's one line is not used), and the next success removes it. No value is ever `NaN`, `undefined` or a negative number.
- **Which Agent.** Only a selected running Agent shows values, from its own entry in `agents`; a running Door counts as an Agent. A selected `done` Agent, Workstream, Terminal or no selection leaves the resource region empty, even when another Agent runs and the response has nonzero totals. A running Agent absent from the response has no values; never substitute `total`. The shared bar keeps its height and Terminal controls in every case. Asserted by the rewritten `u408_a_done_agent_or_a_workstream_shows_only_the_project` and `u408_the_strip_words_for_an_agent_and_the_project` in `apps/desktop/src/resources/u408_strip.test.tsx`; rename them to describe the new acceptance.
- **Current while shown.** The webview calls `project.resources` when a running Agent is selected and then every 2 s while that Agent remains selected and the window is visible; it stops on hide, on closing the Project's tab and on `daemon-exited` (U25), and no call is pending twice at once. A response that arrives after the selection changed is dropped. With no selected running Agent the webview makes no call, even if other Agents run; it clears stale values and `Not updating` from the resource region. Returning to a running Agent resumes sampling. Asserted by the rewritten selection test above and `u408_no_running_agent_draws_no_strip_and_makes_no_call`, `u408_polls_every_two_seconds_while_shown_and_never_twice_at_once`, `u408_stops_on_hide_tab_close_and_daemon_exit`, and `u408_a_late_response_for_another_selection_is_dropped` in `apps/desktop/src/resources/u408_strip.test.tsx`.
- **Quiet.** The values change in place with no animation and no layout shift: each number sits in a `tabular-nums` span; U444's spacing and U469's stable tab controls apply. The strip is not a click target (D6, D7 do not apply), takes no focus, and is `aria-hidden="false"` with `role="status"` and `aria-live="off"`, so a screen reader reads it on demand and is not interrupted every 2 s. The Agent part's `title` holds the full words (`Resident memory`, `CPU of one core`, `Worktree on disk`).
- **No new surface.** Rail rows, Live lines, Glyphs, the tab strip and the Shelf are unmoved; no Token, shadow, border or hue is added (Checks D1, D3, D8); the Checks of `docs/design-system.md` that pass on `main` still pass in dark and at 1280 by 800 (D10).
