# UI: the Shelf's Todos read as designed (U3729 to U3732)

Module: `apps/desktop` (the webview). Ids: U3729 to U3732. Acceptance for #2900.

Webview only: no RPC method, App seam command, `contracts/` file or Token changes; `todo.update`, `todo.complete` and `todo.create` are called as U461, U361 and U3719 say. The user said of the open header "Test  Saved" with a diamond: "this looks ugly - the icon is pure fluff I don't know or see what it means, the text is not aligned the whole piece needs proper design"; of the scope line and `+ Todo`: "The Workspace Name then button need to be on the same level and visually consistent and the action should be distngushed", "The user should understand the current active scope and be able to add to it", "We don't have to repicate the scope"; of the row: "I don't like this design and we need to redign it"; and "it's not clear that I can add a body even when I open the todo". The header the user pictured, a name beside a diamond with `Saved` after it, is `.pad-head` of `apps/desktop/src/pads/PadDrawer.tsx` (the owner mark, `.pad-head-name`, `.pad-saved`); the Todo Drawer's head (U461) has no save state and keeps U461's tick box, title and delete and close icons. Follows #2896 (U3717 to U3720) and #2897 (U3708 to U3712), so the rows below are their final rows. Looks (position, size, gap, alignment, weight, colour, exact copy) are the design critic's (AGENTS.md rule 10); the tests below assert behaviour, roles and presence only.

**U3729 the open Drawer's head holds a title and a status, and no glyph.** Narrows U461 and the Pad Drawer's head (U17). Given an open Pad Drawer owned by the user whose edit has saved, when it renders, then its head holds the Pad's name and, after it, the save state `Saved`, and no owner mark, diamond or other glyph before the name. The name and the status share one baseline; the status is secondary text (a smaller, quieter Token type than the name) that reads as a state, never a second title, and it is a `role="status"` element. A Pad owned by an Agent shows its owner as words (`owned by <owner name>`, the existing copy) beside the status, with `Make yours` a labelled text button, not an icon; its pointer and keyboard paths and its call are unchanged. While an edit is unsaved or failed, the status shows U17's existing unsaved or failure text in the same place and the same type. The Todo Drawer's head is unchanged. Test: `u3729_the_pad_head_has_no_glyph_and_a_status_after_the_name` (a Vitest case asserting no `svg` or owner-mark element precedes the name, the `status` role and its text, and `Make yours` as a button with that name); `u3729_make_yours_still_takes_the_pad` (the existing call, unchanged).

**U3730 the scope line holds the scope's name and `+ Todo`, once.** _Amended only as listed by U3789e (`ui-shelf.md`); U3789a–d govern those replacement clauses._ Narrows U2744a's Scope line and Add clauses and U15's add control. Given the Shelf's Todos tab, when it renders in Overview, with a Workstream selected, with an Agent selected and with a Terminal selected, then the scope line (`data-shelf-scope`) is one line holding, in order, the scope's current name (U2744a: Overview, the Workstream or Agent by its Rail name, the Terminal owner's scope) and the add control `+ Todo`, which is a button in the line, at its trailing end, with accessible name `add todo to <scope name>`, in the tab order directly after the scope name's element and before the first group. The line is not a second control row: the name is text and the action is the line's only button. Pressing it opens the Shelf's one new-Todo field (U15, U3719) with the scope's Home applied as U2744a's Add clause says, so it files with `todo.create {title, owner: null}` then `todo.move` as before, and focus goes to the field; Esc or an empty commit closes it and returns focus to the button. The scope's name appears on no other element of the list: no group header, row or empty-state line repeats it, so the group of the selected Workstream's own items shows no header (Pads: the same) and U3717's owner groups name owners only. The line follows selection and rename (U2744a) and holds the add control in the Pads tab as it does today (`+ Pad`). Tests: `u3730_the_scope_line_holds_the_name_and_one_add_button`, `u3730_add_files_into_the_scope_and_returns_focus`, `u3730_no_group_or_row_repeats_the_scope_name`.

**U3731 a Todo row is a designed row of tick box, title and body line.** _Amended only as listed by U3789e (`ui-shelf.md`); U3789a–d govern those replacement clauses._ Narrows U361, U359, U3712 and U3726. Given the Shelf's open Todos, when a row renders, then it holds a tick box (U361), the title in regular weight, never bold, and, when the Todo's body is not empty, one body line under the title holding the body's first non-empty line in the quiet secondary type; a Todo with an empty body has no body line and no reserved space for one. The body line never wraps or grows the row: it is cut with `…` and the whole first line is its `title` attribute (narrows U154's no-ellipsis clause for this one element only; the title still wraps). Nothing else is added to the row (U3712's `also waits on` line, owner groups and nesting indent are unchanged), the tick box keeps U361's 24 px hit area and tab order, and Enter or a click on the title opens the Drawer as before. U112 and U154 hold: hovering or focusing the row moves no row's top edge, height or wrapping, and no word or button draws over the title or body line. Done rows (U155's `✓ n done`) use the same row. Tests: `u3731_a_row_shows_the_first_body_line_only_when_there_is_a_body`, `u3731_the_body_line_is_one_line_with_the_whole_text_as_its_title`, `u3731_hover_and_focus_move_no_row` (the existing `u361_nothing_draws_over_a_title_on_hover_or_focus` extended to a row with a body). `u15_`, `u154_`, `u359_` and `u361_` cases that read a row's weight or text are rewritten in the implementing PR, each cut naming the test that still proves its then-clause (AGENTS.md rule 10).

**U3732 an open Todo with no body offers `Add notes`.** Narrows U461 and U17's in-place body edit. Given an open Todo Drawer whose body is empty, when it renders, then under the title a visible line reads `Add notes` (a user label in `copy.ts`), is a button with accessible name `Add notes`, sits where the body will, and is in the tab order after the title; the line is absent once the body holds text, and an unsaved draft in the body counts as text. Clicking it, or pressing Enter or Space on it, opens the body for editing with focus in the body field and the caret at its start, exactly as the U461 in-place edit opens it, and calls nothing. Esc or leaving the body empty closes it back to `Add notes` with no `todo.update` call and focus on the line's button; committing text calls `todo.update {id, title: null, body, expected_change}` once, as U461 says, and the line gives way to the body. A done Todo's Drawer offers the same line. Tests: `u3732_an_empty_body_shows_add_notes_and_a_filled_one_does_not`, `u3732_click_and_enter_open_the_body_with_focus`, `u3732_escape_or_empty_leaves_add_notes_with_no_call`, `u3732_committing_notes_calls_update_once`.

**U3798 an Icon-and-word button centres its Icon on the word.** Narrows U3730's add control and U15. Given the Shelf bar's `+ Todo` and `+ Pad`, when they render, then the `+` is vertically centred on the word's text, not dropped below it: the Icon's and the word's vertical centres differ by at most 1 px. One shared rule serves every `data-button="add"` control that pairs an Icon with a word (the Shelf bar, the Rail's and the Bubbles' add controls), aligning the Icon and the word on one axis, and no such control mixes baseline and centre alignment. Test: `u3798_an_icon_and_word_button_centres_the_icon_on_the_word` (a Vitest case on the shared rule's computed `align-items` for the Icon and the word, in the Shelf bar's Todos and Pads tabs); the centring itself is the design critic's.

**U3797 Triage is an icon-only button in the Shelf bar.** Narrows U35 and U3751. Given the Shelf's Todos tab, when it renders, then Triage is an `IconButton` (`ui/IconButton`, lucide `list-checks`) in line with the close and expand icons, not the word; its accessible name is the existing Triage label, and its Tooltip shows that label with the key chip `T` (the chord that already enters triage). Pressing it enters triage and pressing it again leaves triage as the word did; it keeps `aria-pressed` true while triage is on and false otherwise. Tests: `u3797_the_triage_icon_button_enters_and_leaves_triage_with_aria_pressed`, `u3797_the_triage_tooltip_holds_the_t_chord`.

Policy — implementation boundary: `apps/desktop/src/shelf/`, `todos/`, `pads/` (the head only) and `copy.ts`, and the explicitly named regression callers. Only Tokens provide look values (AGENTS.md rule 8); no new library or interactive machinery (rule 9): the `+ Todo` button and the `Add notes` button use the `ui/` button primitive, and the body edit is U461's existing in-place editor. New user labels (`Add notes`, `add todo to <scope>`) go in `copy.ts`.

Observer (policy): use U26's harness in a dedicated headless `agent-browser` session with a fresh profile, `tree-40` plus a Pad owned by an Agent, a Todo with a 120-character title, a Todo with a 300-character body and one with an empty body, a 60-character Workstream name selected, at 1512×950 in dark mode only (U3725). Read `window.__checks()` on the densest state with a failure visible. Run `just capture U3729 U3730 U3731 U3732 U3798 U3797`; leave the PNGs and videos under `artifacts/ux/<id>/` uncommitted (`.agents/data/harness.md`, Captures).
