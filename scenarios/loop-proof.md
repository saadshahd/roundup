# Loop proof

Module: `loop/`

**L76 unchanged rendering needs an independent attestation, not a proof branch.** Given a component code change with no visible effect, exact-head passing test output for every named scenario in `## Proof`, and `## Shape` as L53 requires, when `loop/rules.sh proof <pr>` or the block lane's `merge-ready` runs, then no `proof/pr-<n>` branch is needed if the newest independent verdict for the current code tree is `VERDICT: approve` with the exact line `Visual: unchanged`. The verdict names the full reviewed commit SHA using the existing reviewed-head rules and has exactly one `Reviewed-by-Agent: <id>` different from every `Author-Agent` in the PR. Its reviewed commit must be an ancestor of the current head with the same Git tree: an empty approval commit preserves the attestation, a code change or a merge that changes the tree does not. Test output still names the exact current head, including an empty approval commit. A newer reject or approval without the attestation cannot reuse an older attestation. An author's claim in the PR body or an author verdict alone fails without images; ambiguous heads, multiple Reviewer ids and stale attestations do too. GitHub failures fail closed through the existing gate helpers.

Given a PR that actually changes what the user sees, when the Reviewer evaluates the diff and scenario, then it must not attest `Visual: unchanged`: L53 still requires before and after images or video at the scenario's window size, with its existing file, caption and size checks. A path is a reason to check visibility, not evidence of a visible effect. L54 approval carry and L57 label requirements are unchanged. The Reviewer verifies the unchanged claim from the diff; the gate verifies the independent verdict and tree binding, not pixels. This serves P5 by retaining the proof gate for landing.
