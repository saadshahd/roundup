# UI verification: real-layout laws and a laws sheet (V1 to V3)

Module: `apps/desktop` (the webview harness and `testing/`), `loop/rules.sh` (the sheet). Ids: V1–V3.

The user asked which UI verification tools to use and to keep every law readable on one page. The research (2026-10-03) found axe-core maintained and runnable in the harness's headless Chromium, Quickstrom dormant since 2024-08, Chromatic and Percy a poor fit (no Storybook, a human approves each diff, screenshots go to a third party), and `@xstate/test` only an alpha on an alpha XState; so V1 and V2 adopt axe-core and plain per-frame measurement, and V3 is the sheet. All three run in the Chromium of `just harness` (U26); none sees WKWebView, the macOS window or the system text rasteriser, which stay the laptop checks of S7 and `just perf`.

**V1 axe-core runs on the harness page.** Given a page of `just harness <seed>` at 1280 by 800, when `window.__axe()` is evaluated, then it runs axe-core's `color-contrast` rule and its `aria-*` rules on what is on screen, and returns `{violations, incomplete}`, each entry `{rule, selector, value}`. Every violation fails V1. An `incomplete` entry (text axe cannot measure, such as text over an image) is returned and listed in the sheet (V3) as not measured; it is never counted as a pass. axe reads the page and changes nothing the user sees. It is one more source beside D1 to D10 (U137), not a second implementation of them: where a D check and an axe rule judge the same text (D5's 4.5:1 and `color-contrast`), a disagreement fails and names both selectors. Tests (`v1_`): a fixture page with a grey-on-white line below 4.5:1 returns one `color-contrast` violation naming its selector; a fixture with text over an image returns an `incomplete` entry and no pass; a page with a button with no accessible name returns an `aria` violation; the shipped harness seeds `first-run`, `agents-10` and `tree-40` return none; a missing axe bundle makes `window.__axe()` throw, never return empty.

**V2 the Drawer's laws are sampled every frame.** Given the harness at 1280 by 800 and at 640 by 400, when a Todo Drawer and a Pad Drawer each open and close, then a sampler that reads at every animation frame from the click to 300 ms after the slide ends records that `scrollLeft` of the element holding the Rail, terminal and Shelf is 0 in every frame, and that the sum of layout-shift values (`PerformanceObserver` of type `layout-shift`, which counts a shift of what is on screen, not of the Drawer itself) for the Rail, the terminal pane and the Shelf is 0. This is the real-window check U111 names. The sampler is one function in `apps/desktop/src/testing/`, so other laws can use it, and it returns the frames it read so a failure shows the first bad frame. Tests (`v2_`): the shipped App passes at both sizes; a fixture stylesheet with the old `overflow: hidden` columns fails with the first frame whose `scrollLeft` is above 0; a sampler that read no frames fails (never passes empty).

**V3 the laws sheet.** Given the scenario files, when `loop/rules.sh laws` runs, then it prints one line for each clause that carries a line `Law: <one plain sentence>. Check: <how it is checked>`, in the form `id | sentence | check`, sorted by id, one page for the whole repo, and prints nothing else. A clause with a `Law:` line and no `Check:` is printed with the check `unchecked`, and `loop/rules.sh laws` exits 1 for it. A `Check:` that names a test prefix (`u111_`, `v2_`) must match at least one test name in the repo or it exits 1 naming the id. Exit 4 when `scenarios/` is missing. The sheet is generated, never edited by hand, so it cannot drift; the user's desk copy is its output. The first three laws are: `U111 | Opening or closing a Drawer never moves the Rail, the terminal or the Shelf | v2_`, `D5 | Every text reads at 4.5:1 or better on its ground | u137_ and v1_`, and `U41 | Exactly one focus ring is visible at a time | u41_` (a DOM has one focused element, so the check is the visible ring, not the count). Tests (`v3_`) use a temporary directory with fixture scenario files: a Law with a matching test, a Law with no Check (exit 1, `unchecked`), a Check naming a prefix no test has (exit 1), and a missing directory (exit 4).

Tests are named `v1_` to `v3_`. A reviewer reads the laws sheet before the diff.
