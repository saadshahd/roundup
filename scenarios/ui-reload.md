# UI: a Terminal after a webview reload (U103, U104)

Module: `apps/desktop` (the webview); the Daemon half, `terminal.snapshot`, is `crates/terminal`. Ids: U103–U104.

Reported by the user: after reloading the app, the selected Agent's Terminal pane was black with a cursor and one status line, while the running Claude Code held a full screen. U11 says `terminal.output` is never replayed, so an emulator created after a reload starts blank. These two scenarios give it the screen back. U103 is the webview half; U104 is the Daemon half and the contract text (rule 4: a new RPC method and a new event field need an architect other than the author).

**U103 a reloaded pane shows the screen.** Given a Terminal that is running or has exited, and a webview that has just loaded (a reload, or a first load against a Daemon that already ran), when the webview creates that Terminal's emulator (U11), then it calls `terminal.snapshot {id}` before it hands the emulator any `terminal.output`, writes the returned `data` to the emulator, and only then hands it the output that follows. Output that arrives while the call is in flight is held, in order. The webview keeps the next expected output offset per Terminal, starting at the snapshot's `after`: it drops an event whose bytes all lie before that offset, writes only the suffix of an event that overlaps it, and writes a contiguous event once. If an event starts beyond the expected offset, the webview holds it and requests a fresh snapshot rather than showing output with a hole. The fresh snapshot replaces that Terminal's emulator screen, then buffered output is reconciled against its new `after`; a failed recovery keeps the last complete screen and shows U80's one failure line. The emulator is built at the snapshot's `cols` and `rows`, then U13 sends `terminal.resize` as it does for any first show; U13 is unchanged. A failed initial call shows U80's one failure line for that pane and the emulator starts blank, as before this scenario. During a Takeover (`CONTEXT.md`) and for an Agent that is `done`, the snapshot is restored the same way; it never types anything (no `terminal.write`).

**U104 the Daemon holds the screen.** Given a Terminal, then `terminal.snapshot {id}` returns `{cols, rows, after, data}`. `data` is base64 of bytes that, written to a fresh emulator of `cols` by `rows`, reproduce the visible screen, its attributes, the cursor position, the terminal modes the program set (bracketed paste, cursor visibility, the alternate screen, application cursor keys and mouse reporting) and the last at most 1000 lines of scrollback (U34's 10 000 stays the emulator's own bound). The Daemon extends the `vt100` parser `crates/terminal` already runs on every Terminal's output for titles: it currently has a fixed 80-by-24 screen and no scrollback, so the snapshot parser must instead track the Terminal's actual size and keep 1000 lines. `data` is at most 1 MiB, and older scrollback is cut first, never the visible screen. `after` is the count of output bytes the Terminal has produced so far, and each `terminal.output` event carries `offset`, the count before its own bytes, so a client can drop what a snapshot already holds. The screen and `after` in one snapshot come from the same cut of output: no byte is counted before it has been applied to that screen, including during a burst. An exited Terminal answers with its last screen; an unknown id is `NOT_FOUND`. Taking a snapshot never changes the Terminal, its size or its Kind, and it does not mark the Agent `blocked` or `working` (A-series Signals only).

Tests (`u103_`, `u104_`): the fake App with a canned snapshot and output in each order (before, during and after the call, a duplicate range, a gap), a failed initial call, a failed gap recovery, an exited Terminal, a Takeover, a `done` Agent and an output event that straddles `after`; for the Daemon a fake Terminal printing a screenful with colour, a cursor move and more than 1000 lines, then feeding `data` to a second, fresh `vt100` parser of the same size and checking its screen, cursor and modes equal the first's, and a Terminal that set bracketed paste and the alternate screen, the 1 MiB cut, `offset` and `after` agreeing across a burst while snapshots are taken, and a resize between two snapshots.
