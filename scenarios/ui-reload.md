# UI: a Terminal after a webview reload (U103, U104)

Reported by the user: after reloading the app, the selected Agent's Terminal pane was black with a cursor and one status line, while the running Claude Code held a full screen. U11 says `terminal.output` is never replayed, so an emulator created after a reload starts blank. These two scenarios give it the screen back. U103 is the webview half; U104 is the Daemon half and the contract text (rule 4: a new RPC method and a new event field need an architect other than the author).

**U103 a reloaded pane shows the screen.** Given a Terminal that is running or has exited, and a webview that has just loaded (a reload, or a first load against a Daemon that already ran), when the webview creates that Terminal's emulator (U11), then it calls `terminal.snapshot {id}` before it hands the emulator any `terminal.output`, writes the returned `data` to the emulator, and only then hands it the output that follows. Output that arrives while the call is in flight is held, in order, and an event whose bytes all lie at or below the snapshot's `after` offset is dropped, and an event that starts below `after` and ends above it has only the bytes from `after` on written (its `offset` plus its length says where it ends), so no byte is shown twice and none is lost. The emulator is built at the snapshot's `cols` and `rows`, then U13 sends `terminal.resize` as it does for any first show; U13 is unchanged. A failed call shows U80's one failure line for that pane and the emulator starts blank, as before this scenario. During a Takeover (`CONTEXT.md`) and for an Agent that is `done`, the snapshot is restored the same way; it never types anything (no `terminal.write`).

**U104 the Daemon holds the screen.** Given a Terminal, then `terminal.snapshot {id}` returns `{cols, rows, after, data}`. `data` is base64 of bytes that, written to a fresh emulator of `cols` by `rows`, reproduce the visible screen, its attributes, the cursor position the terminal modes the program set (bracketed paste, cursor visibility, the alternate screen, application cursor keys and mouse reporting) and the last at most 1000 lines of scrollback (U34's 10 000 stays the emulator's own bound); The Daemon builds `data` from the `vt100` parser `crates/terminal` already runs on every Terminal's output, kept with 1000 lines of scrollback. `data` is at most 1 MiB, and older scrollback is cut first, never the visible screen. `after` is the count of output bytes the Terminal has produced so far, and each `terminal.output` event carries `offset`, the count before its own bytes, so a client can drop what a snapshot already holds. An exited Terminal answers with its last screen; an unknown id is `NOT_FOUND`. Taking a snapshot never changes the Terminal, its size or its Kind, and it does not mark the Agent `blocked` or `working` (A-series Signals only).

Tests (`u103_`, `u104_`): the fake App with a canned snapshot and output in each order (before, during and after the call, a duplicate range, a gap), a failed call, an exited Terminal, a Takeover, a `done` Agent and an output event that straddles `after`; for the Daemon a fake Terminal printing a screenful with colour, a cursor move and more than 1000 lines, then feeding `data` to a second, fresh `vt100` parser of the same size and checking its screen, cursor and modes equal the first's, and a Terminal that set bracketed paste and the alternate screen, the 1 MiB cut, `offset` and `after` agreeing across a burst, and a resize between two snapshots.
