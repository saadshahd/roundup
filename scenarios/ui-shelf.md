# UI: the Shelf reads at a glance and holds still (U112, U151 to U154)

Module: `apps/desktop` (the webview). Ids: U112, U151 to U154. U151 to U154 are from #398 (feedback: the Todos panel is too raw to use).

Rule (#398): Every Shelf row shows, at rest (no hover, no focus, Drawer closed), each fact the user decides on from that list: for a Todo, its status Glyph, `#<id>`, title, each open blocker and its Home. Every action that changes one of those facts (add, edit, block, unblock, complete, reorder, move) is reachable from the panel by a pointer-only path and by a keyboard-only path, in the row or in the item's Drawer, without typing an id from memory. Check: a harness test lists the facts in each row's DOM text with the pointer outside the list, and for each action drives both paths and reads the changed fact from the row.

**U112 hovering a Shelf row never moves a row.** Reported by QA (F7, sweep 2): hovering an open Todo row shows `complete` inline, the title wraps and the next row moves down 15 px. Given the Shelf's open Todos (U35), then showing or hiding `complete` on hover or focus changes no row's top edge, no row's height and no row's wrapping: the same rule U46 sets for the Rail's Live line, here for the Shelf. `complete` takes no width from the title: it overlays the row's right edge or sits in space reserved at rest, and the row's text at rest is unchanged (U35). The same holds for any other word a Shelf row shows on hover or focus. Tests (`u112_`) read the top edge, height and the title's line count of every row before and after hover and focus in the harness, on a list whose longest title nearly fills its row (hover held since #218; these tests pin it).

**U151 a Todo row shows every fact the user acts on, at rest.** Narrows U15 and U35. Given an open Todo in the Shelf's `todos` list (U15) or under its Agent (U60), with the pointer outside the list, no focus in it and the Drawer closed, then its row holds, top to bottom, and nothing else:
1. the row button, whose text is `<glyph> #<id> <title>` (U15), the Glyph being `·` or `⏸` as U15 says;
2. for a blocked Todo only, the `waits on #<id>, #<id>` line (U15, U35), its text unchanged and in its own element, `data-todo-waits`;
3. the Home line, in its own element, `data-todo-home`, plain text `in <home>` where `<home>` is `project root` or a Room's name (`nameOf`, no Daemon read). Until `todo-home-spec` (#496) merges every Todo has the Project root as its Home, so the line reads `in project root`; that Issue's PR adds the Room value, the field it is read from and its own rows to U154's observer. The Home line is not a button and is not in the tab order; changing a Home is `move` (U152).
The light `complete` (U35) still shows only on hover or focus, out of the flow (U112). Amends U15 ("text at rest stays exactly `<glyph> #<id> <title>`" now holds for the row button, not the whole row) and U35's Narrowing the same way: "the second line's text stays exactly `waits on #<id>, #<id>`" holds for `data-todo-waits`, which the Home line never joins. U60's nested copy draws the same three parts. Tests (`u151_`): the three parts for an unblocked, a blocked (two open blockers, one done blocker not named) and a Todo under an Agent; the Home line reads `in project root`; the Home line is no button and no tab stop; `complete` is absent from the row's text at rest. Narrows without contradicting: `u15_open_todos_are_listed_in_id_order_as_glyph_hash_id_title` and `u15_a_blocked_todo_has_the_pause_glyph_and_a_second_line_naming_its_open_blockers_in_id_order` read the row buttons' text and the `waits on` element's text, which do not change; `u35_an_open_rows_text_at_rest_never_includes_complete` reads `rowOf(3).textContent`, which becomes the row button's text in the same PR as the code, with `complete` still absent from the whole row. Observer: Vitest `u151_` cases against the fake App seam read the DOM text and elements above; the U26 harness (`tree-40`, plus `todo.created` Events the page sends for a Todo blocked by #1 and #2) at 1280 by 800 and 700 by 800, light and dark, reads the same parts from `document` with the pointer parked outside `.shelf`.

**U152 every Todo action has a pointer path and a keyboard path from the panel.** Given the Shelf, then each action below is done by the pointer alone and by the keyboard alone, from a row or its Drawer (U17), never by typing an id the user has to remember, and each changed fact is read back from the row (U151) after the Event and refetch of U15:

| Action | Pointer | Keyboard | Scenario |
|---|---|---|---|
| add | click `+` beside `todos`, type, Enter | Tab to `+`, Enter or Space, type, Enter | U16 |
| read | the row at rest | Tab through the rows; Enter opens the Drawer | U151, U17 |
| edit | double-click the title or body in the Drawer | Tab to it, Enter, type, Tab away or Enter on the title | U17, U139 |
| block | Drawer `+ blocker`, then click a Todo in the offered list | Tab to `+ blocker`, Enter, Tab to a Todo in the list, Enter | U17, new here |
| unblock | Drawer `waits on`: click `remove` beside a blocker | Tab to `remove` beside it, Enter or Space | new here |
| complete | hover the row, click `complete`; or the Drawer's `complete` | Tab from the row to `complete`, Enter or Space; or the Drawer's | U35, U138 |
| delete | the Drawer's `delete`, then `delete` in the question | Tab to them, Enter | U150 |
| reorder | pending: `todo-order-spec` (#495) | pending: #495 | #495 |
| move | pending: `todo-home-spec` (#496) | pending: #496 | #496 |

New here: in the Drawer's `waits on` list (U17) each blocker line, done or open, has a light `remove` word beside it (U86's 24 px hit area, visible focus, accessible name `remove blocker #<id>`). Choosing it calls `todo.setBlockers {id, blockers}` with that blocker left out and the others kept in order, once; a `CONFLICT` or any error shows `✕ <message>` in the Drawer as U17 does and changes nothing. The row's `waits on` line changes only when `todo.updated` and `todo.unblocked` refetch the list (U35), and a Todo left with no blocker has no `waits on` line. Offered Todos in `+ blocker` (U17) are reachable by Tab and chosen by Enter; no step needs hover. The reorder and move rows are decided by #495 and #496, whose PRs add their ids to this table. Tests (`u152_`): per row above, one case by pointer and one by keyboard on the fake App seam, each asserting the call (`todo.create`, `todo.update`, `todo.setBlockers`, `todo.complete`, `todo.delete`) with its params, and the row text after the Event; `remove` of a blocker leaves the other blockers; a failed `remove` shows the message and keeps the row. Observer: an agent-browser run in a dedicated headless session on the U26 harness (`tree-40`) at 1280 by 800 and 700 by 800 drives each row of the table by both paths and passes when the row's DOM text shows the change (a new row; `waits on #1` after `+ blocker` #1 on Todo 2 and no `waits on` line after `remove`; the row gone and `✓ n done` one higher) and `document.activeElement` is never `body` after a keyboard step (U138). `u17_` tests stay green: `waits on` still lists each blocker with its Glyph.

**U153 the row has a surface and a rhythm made only of Tokens.** Narrows U15 and U53; changes no Token. Given the Shelf's open Todo rows (U151), then, measured by `getComputedStyle` in the U26 harness:
- a row (`[data-shelf-row]`) has `background-color` equal to `--ground`, border-radius `--radius-row`, padding-block `--space-1` and padding-inline `--space-2`; the Shelf behind it is `--sunken`;
- adjacent rows are `--space-1` apart, and the `todos` list's own padding is `--space-2`;
- the row button's height is at least 28 px (the Rail row's), so the row's hit area is above D6's 24 px;
- the waits-on and Home lines use `--text-caption` and `--grey`, the row button `--text-body` and `--text`; the lines indent `2ch`, under the id (U15);
- under the pointer the row's background is `--hover` over `--ground`, and the row whose Drawer is open is `--selected`; both change in the same frame, with no transition (D6, D7, and U53's rule that nothing else animates);
- no border, shadow or colour other than a Token (D1, D2, D8).
Moves: D1, D2, D4, D5, D6, D7, D8 and D10 (`docs/design-system.md`) for the Shelf's Todo rows; D3 and D9 are unchanged. Amends U53: its distances now include the row padding and gap, and its 150 ms (plus or minus 50 ms) and half-distance rules read on the new tops; the surface and hover changes above are instant. No `u53_` test exists on main; the narrowed text is U53's harness observers, which the PR for this scenario reruns unchanged on the new rows. Tests (`u153_`): the computed values above on an unblocked, a blocked and a hovered row, in light and dark. Observer: `loop/rules.sh delta` on `tree-40` at 1280 by 800 and 700 by 800, light and dark, reads each Check above as `fixed` or `still-passing` for the Shelf's Todo rows; Percy captures of before and after are attached to the PR.

**U154 the row holds on the densest data.** Narrows U112. Given the Shelf's rows holding a 120-character title, a Todo with ten open blockers, and (once `todo-home-spec` merges) a Room whose name has 60 characters, at 1280 by 800 and 700 by 800, light and dark, then no text on a row is clipped or cut with an ellipsis (every element's `scrollWidth` is at most its `clientWidth`), the title wraps under its id (U15), the `waits on` line and the Home line wrap within the row, no row is wider than the list, and hovering or focusing any row (U35) changes no row's top edge, height or wrapping, as U112 says now that a row holds three parts. Failure text (`✕ <message>`, U35) shows in place of the `waits on` line and the Home line stays. Tests (`u154_`): the measurements above on that seed; `u112_hovering_any_row_changes_no_rows_top_edge_height_or_wrapping_at_1280x800` and `_at_700x800` stay green unchanged and now also run with a blocked Todo and the Home line in the list. Observer: the same measurements by agent-browser in the U26 harness (`tree-40` plus the Todos above sent as Events), numbers in the PR.
