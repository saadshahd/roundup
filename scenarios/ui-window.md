# App window width

Policy: U3787e (`scenarios/ui-mac-expectations.md`) replaces U452’s unconditional maximization, absent-height and no-remembered-size clauses with saved size/place restoration. First launch may remain maximized; the 1280 logical-pixel minimum, U453 and window-bar behavior remain. Retire `u452_window_opens_maximized` when implementation adds the saved-bounds observers.

The owner's 2026-10-12 decision in #1236 sets the supported App window width to at least 1280 px. U430 and `scenarios/ui-drawer.md` remain owned by #1109 and PR #1225; this specification changes neither. The final repository-wide absence of narrower viewport assertions includes that owner's slice once it merges.

**U452 the App opens at least 1280 px wide and cannot shrink below it.** Given the App window declared in `crates/desktop/tauri.conf.json`, when its configuration is read, then:

- Its `minWidth` is exactly 1280 and its initial `width` is at least 1280, in Tauri's logical pixels. Test: `u452_window_width_is_at_least_1280`, in `crates/desktop/tests/`, reads the actual config and asserts both fields on the App window, rather than testing a copied fixture.
- The window is declared maximized: `maximized` is `true`, while `height`, `minHeight` and `maxHeight` remain absent. Test: `u452_window_opens_maximized` reads that same config and asserts `maximized` is `true` and the three height fields are absent. It replaces `u452_window_height_is_unchanged`, retaining its assertion that the height fields are absent.

Policy: every launch fills the usable area of the screen it opens on, between the macOS menu bar and Dock, rather than entering full screen in a separate Space. The window bar still restores and re-maximizes (U449–U451); no window size is remembered. Screens narrower than 1280 px retain the 1280 px minimum width. The config test proves the declaration; one Mac observation of `just app .` proves the fill, with a screenshot when available. That observation is not a per-PR Mac gate or a needs-user ask.

Policy: this slice's implementation PR owns `crates/desktop/` only (AGENTS.md rule 3). It leaves #1236 open until U453 also holds.

**U453 layouts and observers use supported window widths.** Given `scenarios/` and `apps/desktop/src/`, when viewport assertions, test fixtures and capture definitions are enumerated, then:

- Layout branches and width caps whose restricting arm can apply only when the window is narrower than 1280 are removed. This includes the window-dependent Rail and Shelf clamps in `apps/desktop/src/resize/widths.ts` and the Shelf span cap in `apps/desktop/src/styles.css`. Keep Rail and Shelf user resize bounds and per-Project persistence, text wrapping, content scrolling and rules that can restrict a layout at a supported width. Drawer rules owned by U430 are settled in #1109. Test: `u453_widths_keep_resize_bounds_without_window_clamps` exercises stored values below, within and above the Rail and Shelf limits, and restoration.
- At 1512×950, the only supported window, the real U26 harness renders `first-run`, `agents-10`, `tree-40`, `decisions` and `conflict` in dark. On `tree-40`, open and close Todo and Pad Drawers; on `decisions`, inject a failed answer and show its full error on the densest seed. Isolated headless Chromium reads the Checks on each, with before/head captures and Check readings under `artifacts/ux/U453/`.
- The rendered change meets D2 (`docs/design-system.md:126`), D5 (`docs/design-system.md:129`) and D6 (`docs/design-system.md:130`), using only Tokens, and regresses no Check passing on main at the same supported viewport. The design critic judges these Checks on the same seed, state and scheme for main and the head (AGENTS.md rule 10); no test. This changes D10's minimum window viewport (`docs/design-system.md:134`) to 1512×950; its contrast and scheme requirements remain. Policy: the one supported size supersedes other observer instructions; their maintained definitions must be migrated in their owning module PRs.
