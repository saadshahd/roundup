# One Ask bar places every ask

Policy amendment — U2539b (`scenarios/ui-worktree-changes.md`, #3786) narrows U504's home composition: an open Project with nothing selected, including an empty Project, mounts Ask and Needs you only. Ask rows/history and other lists open on request. Submission, routing, @ selection, draft preservation and Escape behavior stay required. `u2539b_empty_project_can_submit_an_ask` extends the empty case; retain U504–U506 action/routing/draft proofs.

Module: `crates/agents` (the Ask store, placement and delivery; the Placement call under `claude_code/`), `crates/contracts`, `crates/rupd` (registration), `contracts/generated/`, `crates/rup/tests/` (the real-Claude observers) and `apps/desktop` (U504 to U506). Ids: A39, A40, A41, A42, U504, U505, U506.

Source: the user's choices of 2026-10-15, recorded on the work Issues. Terms: Workstream, Door, Agent, Steer, Work order, Order title, Status, Kind, Adapter, Model, Effort, Rail, Reach (`GLOSSARY.md`). New terms, added to `GLOSSARY.md` by the PR that builds A40: **Ask** (one message the user sends from the Ask bar), **Ask part** (the span of an Ask that one Workstream takes), **Placement** (where an Ask part goes: `routed`, `new` or `unclear`) and **Placement call** (the Adapter's one-shot call that returns an Ask's parts and their Placements). Acceptance only; work ownership and dependencies live in GitHub Issues. No implementation is claimed by this specification.

The user keeps talking to one place, the Ask bar, and sends it unrelated asks in any order. roundup places each ask with the Workstream whose Door already holds that work, starts a new Workstream when none does, or asks back when it cannot tell. The user's exact words then reach that Door's own Claude Code terminal, so every vendor feature, a leading `/skill` included, keeps working. Agents stay in view: the Ask bar places and delivers only; it never answers, summarises or stands in for a Door. Nothing here depends on today's Workstream view, which #1497 removes.

Decided by the user (2026-10-15): one input that only places ("an intake Agent with its own terminal" lost: slow, and its progress is printed text); each Workstream keeps its Door ("every Door triages" lost: off-topic asks would land in a Door's context); the Adapter's cheapest Model decides through one slim call ("local Drex v1.5" lost: size, memory and licence, below); the words travel as a Steer ("send them as a Message" lost: B2's `[from …]` header and B30's batching would break a leading `/`). Kafka and Temporal lost: they move and store messages, and the Daemon already stores and delivers work in SQLite.

## Library selection

The decider is a judgement over the user's Workstreams, so the candidates are models and routing libraries, measured on a spike of 2026-10-15 (Apple M4 Max, 64 GB): 30 asks over 8 Workstreams, and 36 harder asks over 20 Workstreams with near neighbours, follow-ups ("add Arabic captions to it") and two-topic messages.

- **Selected: the Adapter's own program in one-shot mode.** Pinned Claude Code (`@anthropic-ai/claude-code` 2.1.300 in `package.json`, which already has every flag A39 uses) with `--model haiku`. Haiku 5.5 got 28/30 and 36/36 (twice, and 36/36 at medium Effort); Sonnet 5.5 also got 36/36 at about 20 to 80 times the cost. One ask takes 3.5 to 4.5 s, of which the model takes 2.3 to 3.2 s and Claude Code's start the rest, and costs $0.0001 to $0.0006 at API prices; on the user's plan it spends Usage only. No new dependency, no download, no resident process (rule 7).
- **Rejected: Drex v1.5** ([model card](https://huggingface.co/nace-ai/drex-v1.5)), a local decision model. It tied at 28/30 and took 2.0 s on the GPU and 10.5 s without one, but its only published build is 9.5 GB, it held 10.4 GB resident (rule 7 allows 150 MB for ten idle Agents), it needs Nace's own llama.cpp fork, and its modified Open RAIL-M licence excludes entities over $1M in revenue or funding and must pass to every user. Its hosted v2.0 needs an API key (P4).
- **Rejected: Laya** (Convai, 421M, Apache 2.0, [Ollama tags](https://ollama.com/library/laya/tags)): about 0.8 GB resident against rule 7's budget, reported 0.36 accuracy untuned against 0.77 fine-tuned, at most 20 choices, and it writes no title or question.
- **Rejected: semantic-router** ([aurelio-labs/semantic-router](https://github.com/aurelio-labs/semantic-router)): a Python library around an embedding model; the Daemon is Rust, and nearest-route matching cannot write a new Workstream's title, a question back, or split one message into two asks.

**A39 the Placement call.** Given an Ask's text, its five newest earlier Asks' parts with where each went, and every Workstream in `rail.tree` (its id, name, Order title, the order's ask or Clarification question, and its Status Kind), when the Daemon places the Ask, then it runs the Adapter's Placement call once:

- **Cheapest Model, slim.** For Claude Code (`crates/agents/src/claude_code/`) the call is `claude -p --model haiku --effort low --no-session-persistence --output-format json --json-schema <schema> --tools "" --strict-mcp-config --disable-slash-commands --system-prompt <roundup's placement text>` with the inputs as one JSON prompt. It runs the binary every launch runs (`ROUNDUP_CLAUDE_BIN`, A4), with the user's settings and environment extended under A3507a and A3507c (`scenarios/agents.md`), in a folder roundup owns that holds no file. `haiku` is the alias Claude Code points at its newest Haiku, so no Model version is written in roundup. The Model and Effort are the Adapter's, as the user chose: the call is not an Agent, holds no Rail node, Terminal or Role, and no P8 setting changes. `AgentAdapter` keeps its three seams (P4): the call is its own trait in `crates/agents`, implemented under `claude_code/`, and no vendor string leaves that folder.
- **Answer.** The schema allows one shape: `parts`, one or more, each `{text, kind}` where `kind` is `routed` (with `workstream`, one of the given ids), `new` (with `title`, at most six words) or `unclear` (with `question` and `candidates`, at most three given ids). A message holding two or more unrelated asks returns one part for each; any other message returns one part holding all of it.
- **Checked, never trusted.** The Daemon accepts the answer only when each part's `text` is a non-empty span of the Ask's text, byte for byte, no two parts overlap, every `workstream` and `candidates` entry is a given id, and every `title` passes O14. Any other answer, a non-zero exit, output with no `structured_output`, or no answer within 60 s (the process is then killed) makes the Ask one `unclear` part holding all of its text, with no candidates and the question `Couldn't place this: <cause>`. The cause is logged once to the Daemon's stderr with the Ask's id. Nothing is typed.

Tests: `a39_the_placement_call_is_one_slim_request` (pinned real Claude against strict aimock, as E10 in `scenarios/test-real-claude.md`: one Ask makes exactly one model request, whose model starts with `claude-haiku`, whose system text is roundup's placement text, and which offers no tool but the structured-output one; the fixture's parts become the Ask's parts), `a39_an_answer_that_is_not_a_checked_span_is_unclear` (a fake Placement trait returns a paraphrased part, an unknown id, a seven-word title and overlapping parts; each gives one `unclear` part naming the cause, and nothing is typed), `a39_a_failed_or_slow_call_is_unclear_and_logged_once` (a non-zero exit, empty output, and the 60 s bound under an injected clock). If pinned Claude Code's structured output cannot be served from an aimock fixture, that one test uses the stub, and the PR names the missing aimock capability with library evidence (as E10).

**A40 sending an Ask.** Contract change (rule 4, the Contract recipe of `.agents/builder.md`): `ask.send {text}` returns the `Ask`; `ask.list` returns every Ask, newest first; `ask.pick {id, part, target}` is A42's; the event `ask.changed {ask}` follows every change to an Ask or its parts. `Ask {id, text, at, parts}`; `AskPart {text, placement, state, reason?}`; `Placement` is `routed {workstream}`, `new {title, workstream?}` or `unclear {question, candidates}`; `state` is `placing`, `waiting` (on the user), `queued`, `typed`, `failed` or `dropped`. All three methods are the user's: M5 lists them with a reason (each carries a Steer from the user, P9), no MCP tool offers them, and an Agent's call is `FORBIDDEN` (M2). Given `ask.send {text}`, then:

- **At once.** It returns before any Placement call ends, with one `placing` part holding all of the text. The call's answer replaces that part with A39's parts and emits `ask.changed`.
- **Naming a Workstream skips the call.** A text that starts with `@<name>` and a space, where exactly one Workstream's name equals `<name>` ignoring case, gives one `routed` part holding the rest of the text, and no Placement call runs. When no Workstream or more than one has that name, the part is `unclear`, with the question `No Workstream is named <name>` or `<n> Workstreams are named <name>` and those Workstreams as candidates; still no call runs.
- **Bounds.** A text that is empty after trimming, or over 32 768 bytes, is `INVALID_PARAMS` naming the bound, and nothing is stored.
- **Kept.** Asks are stored in the Daemon's SQLite store, survive a Daemon restart, and are never deleted by a bound (P7). A part still `placing` at a restart becomes `unclear`, `roundup restarted before placing this`, and its call does not run again.
- **Usage only when asked (P9).** A Placement call runs only for an `ask.send` that names no Workstream: never for a Message, an Agent's tool call, `ask.pick`, a timer or a restart.

**A41 a routed part reaches its Door verbatim.** Given an Ask part `routed` to Workstream `w`, then:

- **Queued until idle.** The part is `queued`. A stopped Door is started with `rail.startDoor` (A7), and the part waits for the `idle` after the Door's first Steer (H12). When `w`'s Door is `idle` (H11), the Daemon calls `Agents::prompt` with the part's text byte for byte: no header, prefix or join, so neither B2's form nor B30's batch. The caller passes a Steer from the user (P9). A leading `/` stays first, so Claude Code runs that skill. `BUSY` keeps the part `queued` for the next `idle`. `NOT_ACCEPTED` without any H11 acceptance makes it `failed` with H11's error as its reason; a slash command accepted without `UserPromptSubmit` stays `typed` (A2698a). `NOT_FOUND` makes it `failed`, `the Door ended before this reached it`.
- **Sent when written.** Once the Terminal write succeeds, emit `ask.changed` carrying `typed` before waiting for H11 acceptance (A2698a); the pre-write conditional claim below alone must not emit Sent. A failed write makes the part `failed` with its error.
- **One at a time, in order.** Parts for one Door are typed in `ask.send` order, one for each `idle`; parts for different Doors never wait for each other.
- **At most once.** The part is recorded `typed` in a conditional write made only while it is still `queued`, and then typed (B8's rule). A killed Daemon never types a part twice.
- **Gone.** A part whose Workstream is removed before it is typed becomes `failed`, `the Workstream was removed`.

Tests: `a41_the_door_gets_the_users_words_byte_for_byte` (the fake Terminal sees one bracketed paste of exactly the part's text, then `\r`), `a41_a_leading_slash_runs_the_skill` (pinned real Claude against aimock, with a test skill in its isolated config folder: the part `/<skill> x` makes a model request holding the skill's marker text), `a41_a_busy_door_gets_the_part_at_its_next_idle`, `a41_two_parts_for_one_door_go_in_order`, `a41_a_stopped_door_is_started_first`, `a41_a_killed_daemon_never_types_a_part_twice`.

**A42 new and unclear parts.** Given an Ask part, then:

- **New.** A `new` part with `title` makes one `rail.createWorkstream {name: title, parent: null, order: {kind: "work", title, ask: <the part's text>, limits: []}}` and then one `rail.startDoor`, both as the user's (no Agent's Reach gains the Workstream, M7). O2's first Steer for that order is the ask alone, so the Door gets the part's text byte for byte and a leading `/` stays first. `placement.workstream` names the new Workstream, and the part is `typed` once that Steer is accepted, or `failed` with H12's `prompt not accepted`. A failed create or start makes the part `failed` with the error, and leaves no Workstream behind.
- **Unclear.** An `unclear` part is `waiting` and nothing is typed until `ask.pick`. `ask.pick {id, part, target}` takes a `waiting` or `failed` part: `{kind: "workstream", id}` routes it (A41); `{kind: "new", title?}` makes it `new` (the given title, else the part's first six words), as above; `{kind: "drop"}` makes it `dropped`. A pick of any other part, an unknown Workstream or an O14-invalid title is `CONFLICT` or `INVALID_PARAMS` and changes nothing. A pick never makes a Placement call.
