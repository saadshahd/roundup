# Control channel

Module: `crates/agents` (`agent.prompt`, `agent.interrupt`, `ask_user`), `crates/rup`. Ids: every `H` heading in the file.

How the Daemon sends a prompt to an Agent, ends its turn, and lets an Agent ask the user, without timed keystrokes. Read `docs/control-channel.md`, `docs/permission-decisions.md` and `spikes/hooks-permission/REPORT.md` (the recorded behaviour of Claude Code 2.1.287) first. Tests run with a fake `claude` that calls the hook commands in its `--settings` file and reacts to the bytes written to its Terminal the way the report records; no test needs the real one. These ids continue the Decisions series in `scenarios/decisions.md`.

**H11 a Steer waits for a readiness Signal, not for a delay.** Given a running Agent, when `agent.prompt {id, text}` is called, then nothing is written to its Terminal until the Agent's Kind is `idle` from a `SessionStart` or `Stop` Signal, and then `text` is written once, as one bracketed paste (`ESC[200~`, the text, `ESC[201~`) followed by `\r` in the same write. A test with an injected clock that never advances still delivers the text. The call returns `null` when the Agent's `UserPromptSubmit` Signal arrives (H1: it names the text), and fails with `NOT_ACCEPTED` when none arrives within the bound the test names (default 10 s): the Terminal's input line keeps the text, nothing is sent again, and the error names the Agent. An Agent whose Kind is not `idle` when the call arrives fails at once with `BUSY` naming the Kind; an Agent that has ended fails with `NOT_FOUND`. `agent.prompt` is called by the user or by a Meta-agent for one of its children; a call for any other Agent is `FORBIDDEN`. The write path is one Rust function, `Agents::prompt(id, text) -> Result<(), PromptError>` with the variants `Busy`, `NotAccepted` and `NotFound`, which the RPC method and the mailbox series' in-process delivery both call; no other code writes a prompt. Contract change: `agent.prompt {id, text}` returns `null`, and the errors `BUSY` and `NOT_ACCEPTED`.

**H12 the first prompt goes through the same path.** Given `agent.spawn {cwd, prompt}` (A4), then the prompt is written by H11 when the Agent's first `SessionStart` Signal arrives, and the one-second `SUBMIT_DELAY` and the "typed at the first idle" wording are gone. A4 is amended in the same PR: its last clause says "the prompt is sent as a Steer (H11) at the first `SessionStart`". When the Steer fails, `agent.spawn` has already returned, so the Agent's Status is `error` with the label `prompt not accepted`; nothing is dropped silently. The test uses an injected clock that never advances and the fake `claude`.

**H13 an Interrupt is a call with an observable result.** Given an Agent whose Kind is `working`, when `agent.interrupt {id}` is called, then the Daemon writes `ESC` to its Terminal and returns `null` when the Agent's title Observation changes from the spinner glyph to the star (A2) within the bound the test names (default 5 s, H1: about 12 bytes after the Esc); its Kind is then `idle`. Without that change it fails with `NOT_ACKED`, the Kind is left as it was, and nothing else is written. An Agent that is `idle`, `done` or `error` fails with `NOT_RUNNING` and no byte is written. An Agent with an open Decision is Interrupted by the same call and H7(b) clears the Decision. H1 records that no hook event reports an Esc, so the acknowledgement is the title and not a hook; this is the one place the Adapter reads the screen for a result, and it is the title string A2 already reads. `agent.interrupt` is called by the user or by a Meta-agent for one of its children, as in H11. Contract change: `agent.interrupt {id}` returns `null`, and the errors `NOT_RUNNING` and `NOT_ACKED`.

**H14 an Agent asks the user through the MCP server.** Given an Agent and its `roundup` MCP server (A11), when the Agent calls the tool `ask_user {question, answers}` (`answers` a list of one to four short texts), then the tool does not return, a Decision opens whose `tool` is `ask_user` and whose `args` are the question and answers, the Kind is `needs-you` (H2's rules for one Decision per Agent and for `replaced` hold), and when the user answers with one of the `answers` through `decision.answer {id, answer, proof}` the tool returns that text and the Decision clears with outcome `answered`. An `answer` not in `answers` is `INVALID_PARAMS`. The Decision follows H4: only a caller with the `proof` answers it. Where the Decision first appears (the user's Inbox at once, or after the escalation chain of the mailbox series) is that series' rule and not this one; a permission Decision never climbs (H10). When the Agent ends the tool call fails and the Decision clears as in H6. `ask_user` is allowed by the settings that already allow `mcp__roundup__*` (A11), so its call raises no permission dialog. Contract change: the tool, the Decision's `tool` value, and the outcome `answered`.

**H15 a tool-use loop spawns a bounded number of hook processes.** Given a fake `claude` that runs a loop of 100 tool uses, calling the hook command for `PreToolUse` and `PostToolUse` around each, when it runs against a Daemon with the built `rup`, then every `rup signal` answers (exit 0, so 200 calls) and, with the loop opened by a `UserPromptSubmit` and closed by a `Stop`, a subscribed client sees the Agent's Kind go `working` and then `idle` and rail.tree reports `idle` (a Daemon that answers but drops the Signals sends neither event and fails), every `rup signal` runs at most one OS thread (the runtime of `crates/rup/src/main.rs` is single-threaded; observed with `/proc/<pid>/task` on Linux and `ps -M -p <pid>` on macOS, sampled every 5 ms from the spawn while the process waits on a Daemon that never answers, so a 4 ms run cannot slip past; the most threads seen counts, and a test that never read one sample fails), and `just perf` reports `hook_loop_ms`, the wall time of the 200 calls (two per tool use), as a limit-only metric (AGENTS.md rule 7, R13 for load) with its limit in `docs/perf.md`. Which events leave `STATE_EVENTS` is not chosen by hand: the test replays each `spikes/hooks-state/log*.jsonl` and `D2` with one event type removed at a time, comparing the whole Status, and an event whose removal leaves every Status unchanged is removed from `STATE_EVENTS` and from the settings (the list is `STATE_EVENTS` in `crates/agents/src/claude_code/launch.rs`); the measured outcome is that none is, so `STATE_EVENTS` keeps all nine. There is no CPU-time clause: a cut in CPU time needed an event to leave `STATE_EVENTS`, and none can. The same test asserts that a lost Signal (the Daemon not answering) makes `rup signal` print one line on stderr and exit 1 (never 2, as A4 says), and that a Signal which changes the Kind reaches a subscribed client as a Status event within 30 s (`BOUND` in `crates/rup/tests/e2e/daemon.rs`, the wait every e2e test uses) (the keystroke-to-render budget is rule 7's `just perf-keystroke`; a wall-clock assertion of it in a test would measure the CI runner).

**H16 no keystroke is ever a silent fallback.** Given the control channel above, when a Signal the Daemon waits for is lost (H11's `UserPromptSubmit`, H13's title), then the Daemon returns the typed error and writes nothing else to the Terminal; it never retries a prompt by another path, never types a `y` or `n` into a dialog, and never calls `terminal.write` on behalf of an Agent. The test greps `crates/agents/` and `crates/rupd/` for a second caller of `terminals.write` (the one in H11, the one in H13, and the user's Takeover path) and fails on any other. An Agent's own message, MCP call or Signal text never reaches the Terminal as input, except as the text of a Message the mailbox series delivers through H11's write path after its Route rules (`Agents::prompt`); that is the only way a Message becomes input.

**H17 a lost Interrupt acknowledgement is loud.** The title is the one screen read left in the control channel (H1 records that no hook event reports an Esc), so it is the one known limitation, and it fails loudly. Given an Agent whose title never changes after the Esc (the fake `claude` ignores it), when `agent.interrupt {id}` is called, then after the bound the call fails with `NOT_ACKED` naming the Agent, the Daemon logs one line on stderr, the Kind is unchanged, no second Esc and no other byte is written, and a later title change to the star is still folded as A2 says. The test never advances a clock to pass; it names the bound.
