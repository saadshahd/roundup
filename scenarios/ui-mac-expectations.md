# macOS expectations

Specification for #3787. Implementation is separate. X1–X4 are acceptance labels within U3787a–U3787d, not Terminal scenario ids. These clauses are obligations, not claims that main implements them.

Journey: Enter (window, names and prompts), Understand (selection and action feedback), Intervene (Rail actions and Terminal ownership), Review (delete and restore work). Existing App, real Daemon and native Tauri seams are the observers; do not add a parallel command dispatcher, persistence holder, selection machine or clock. Implementation names new public contracts in `GLOSSARY.md` and changes every caller under the Contract recipe; this specification invents no RPC name.

## Precedence

Exact targets, scope, Actor, owner rules, blockers, failure/readback handling and draft protection remain. Irreversible deletion and stopping retain the native confirmation path. Native context menus and U2694a's no-accelerator rule remain unchanged.

Policy: U3787b adds menu discoverability without broadening App key ownership in U2238–U2241 (`scenarios/ui-shortcuts.md`); U3787a adds only focus-scoped deletion undo. U3787c extends U458's row navigation/selection without changing Todo completion, reorder, activation or scope. Existing heights may be persisted rather than forbidden. The supported rendered observer remains 1512×950.

**U3787a X1 deletes immediately and can restore the chosen work.** Given a Todo, Pad, selected Shelf set, Clear done set or reversible Rail item, when the user invokes its existing Delete/Remove control or deletion key, then:

- Capture the exact chosen identities and originating Project; call deletion once immediately, before any animation and without a question. Repeat keys/clicks while pending do not repeat the call. Delete no arrival or unchosen descendant. A group removal records precisely its existing authorized cascade; it cannot acquire a wider cascade for undo. Tests: planned `u3787a_delete_has_no_question_and_freezes_targets` at the App seam, parameterized over these entry points.
- After acknowledged success, show one nonmodal `Deleted · Undo` feedback with an accessible Undo button; it takes no focus, bell, attention Kind or OS notification. Partial success offers undo for successful identities only; failed rows remain visible and selected with their returned errors. An unknown result is reconciled before success/undo is claimed. Tests: planned `u3787a_success_and_partial_failure_offer_only_acknowledged_undo` and `u3787a_unknown_delete_reconciles_before_retry`.
- Undo or ⌘Z restores the latest successful deletion operation in the originating Project exactly once. A bulk operation is one undo step. Restore the same identities, Home, owner, order, Todo completion and blocker edges (including surviving dependents), Pad incarnation/content/Revision and retained Rail metadata/children; never manufacture a same-named replacement or start an Agent/Terminal. Refuse a conflicting restore without overwriting another item, keep the recoverable operation and show its cause with retry. Tests: planned `u3787a_undo_restores_original_graph` on the real Daemon, covering single, bulk, cross-Home blockers, Agent-owned Pads and reversible Rail removal; `u3787a_restore_conflict_keeps_both_items` and `u3787a_undo_failure_is_retryable`.
- Keep undo operations in reverse deletion order per Project until consumed or App quit; hiding feedback, closing a Drawer or switching Project does not consume them. Undo is disabled while its operation is pending. Reopening a Project in that App run recovers its stack. ⌘Z outside an editor/Terminal targets the selected Project; the feedback button always targets its recorded Project. Text inputs, rich editors and vendor Terminals retain their own undo and receive no item-restore call. No cross-restart undo is promised. Tests: planned `u3787a_undo_stays_with_its_project` and `u3787a_editor_and_terminal_keep_undo`.
- An action that ends a live process, discards a Worktree or otherwise cannot restore its pre-action data and relationships is irreversible. Before executing it, one native alert names that consequence and the chosen targets; Keep/Escape calls nothing. It never advertises Undo. An idle/exited Rail item is not automatically irreversible: retained data must be restorable or the alert must name what would be lost. Tests: planned `u3787a_irreversible_actions_require_consent` with running Agent, Terminal close and Worktree discard, extending the existing native-alert observer.

Policy: a backend that currently hard-deletes without restoration is an implementation prerequisite, not permission to leave Todo/Pad/bulk deletion behind a question. Retain an undoable snapshot atomically with deletion; a client read followed by delete cannot establish the acknowledged pre-delete state. Restore permissions and original identity are checked by the owning Daemon, not trusted from a webview payload. P11 applies to unsubmitted work interrupted by deletion. Restoring data never authorizes replaying external effects.

**U3787b X2 every handled chord is discoverable in the menu bar.** Given the App's bound commands, including scoped commands, configured quick-add, Terminal copy/paste/font actions and the ⌘K leader sequence, when the application menu is opened, then every command has an item displaying its current key or sequence and its applicable enabled state. A leader sequence is displayed as a sequence, never registered as several global accelerators. Plain list-navigation/editing keys retain native control handling; represent named list commands in the appropriate menu without stealing typing. Tests: planned `u3787b_menu_covers_bound_commands` against actual menu construction and the command inventory, and `u3787b_menu_tracks_configured_shortcut`.

Given the same focused Project/row/editor/Terminal and command availability, when the user chooses its menu item or invokes its chord, then the same action runs once against the same captured target; unavailable items are disabled. A native accelerator plus webview listener never double-fires. Menu construction and selection do not change the target or lose the prior focus. Tests: planned `u3787b_menu_and_key_share_one_action` and `u3787b_scoped_menu_does_not_steal_terminal_input`, using the real registry and Tauri menu event path.

Policy: baseline `keys/chords.ts` (`CHORDS`, `LEADER`), `keys/registry.ts` (`registerKeys`), `terminal/Pane.tsx` and `terminal/emulator.ts`, all under `apps/desktop/src`, define the inventory; include library/native commands as well as these callers. `crates/desktop/src/menu.rs` (`app_menu`) uses Tauri's standard menu plus Settings and Project entries. Neither ⌘W nor ⌘F has a webview App handler on the inspected baseline: preserve standard Close Window and responder Find where the native menu supplies them, with availability tied to their actual responder. Do not invent Project-close or global-search behavior for these keys. The ordinary Terminal modifier sweep remains passing; context-menu labels still carry no accelerators. Native responder dispatch and displayed key equivalents need the native observer below; a mock menu is not proof of macOS dispatch.

**U3787c X3 lists share navigation and rename cancellation.** Given each list of content rows, when focused, then ↑/↓ moves to the preceding/following visible enabled row without wrapping; Home/End reaches the first/last; typing a name prefix selects the matching visible row using the installed library's typeahead. Hidden, folded and disabled rows are skipped. Typing in an editor or Terminal is never list typeahead. Tests: planned `u3787c_each_list_navigates_visible_rows`, parameterized over the rendered inventory.

Given at least five rows, when ⌘A is pressed on a row, then all visible eligible rows in that list are selected; ⌘-click toggles only its target and sets the anchor; ⇧-click selects the inclusive visible range from the anchor (with no anchor, just the clicked row); ⌘⇧-click uses the same range rule. These gestures call no mutation and open no Drawer. Existing Enter/Space/plain-click activation and Shelf selection lifetimes remain. Tests: planned `u3787c_each_list_selects_only_visible_rows` and the retained U458 behavioral observers.

Given an existing in-place rename with saved text, when the user changes it and presses Escape, then the old text is displayed again, no rename is sent, focus returns to that row and an underlying Escape action does not run. Escape hides the edit without discarding its recoverable draft (`scenarios/unfinished-input.md`, Policy); only a separately labelled explicit discard consumes that selected revision, never another draft or an acknowledged rename. Tests: planned `u3787c_escape_restores_the_name`, parameterized over each rename surface with exact Unicode/whitespace and zero call counts; preserve P11's failure/conflict recovery.

Policy: the implementation inventory covers Rail rows (including Agent Pads), Shelf Todo/Pad rows, Switcher results, Inbox entries and Import candidate rows, plus any other content-row collection found in the mounted App. Project/Terminal tabs, action menus and single-value form pickers retain their library/native semantics rather than becoming bulk-action lists; ⌘A in their text fields still selects text. Do not treat prose, history text or Terminal output as selectable item lists. Use existing Ark tree/listbox/combobox primitives under `apps/desktop/src/ui/`; compare the installed tree library before adding machinery. The inventory names the opening interaction and test case for each collection and rename, not just a role query.

**U3787d X4 prompt, path and name fields disable writing assistance.** Given every mounted prompt, path or name input, textarea or editable root, including fields opened conditionally in dialogs, menus, rename, Capture, import, settings and recovery, when focused and typed into, then spellcheck is false, autocorrect is off and autocapitalize is off on the element that actually edits text. Authored bytes and caret behavior survive input, blur, submit and cancellation. Test: planned `u3787d_each_field_keeps_literal_input`, a parameterized App test with the actual controls and opening interactions; assert these behavioral input contracts, not label spelling or appearance. Rich-editor prompt/name roots are included; ordinary Pad prose retains its editor policy. Source review audits the complete field inventory, including DOM created by dependencies (policy). Do not add DOM clones or synthetic events to override a dependency.

**U3787e the window reopens at its saved size and place.** Given a normal window resized and moved on an available display, when the App is quit normally and reopened, then `tauri-plugin-window-state` restores its logical size and position before revealing it, subject to the existing minimum width. Preserve maximized/fullscreen state separately from normal bounds, so leaving either returns to the last normal bounds. Tests: planned `u3787e_restore_uses_saved_normal_bounds` at the shell seam and the native observer below.

Given no prior state, a corrupt record or a disconnected display, when the App opens, then its window remains reachable on an available display at no less than 1280 logical pixels wide; no invalid coordinates or corrupt state prevent opening. First launch may use U452's maximized default; subsequent valid saved bounds override it. Tests: planned `u3787e_missing_invalid_and_offscreen_state_are_reachable` with missing/invalid state and monitor fixtures; native observer verifies actual placement and zoom/fullscreen transitions. Policy: no second custom window-state store; preserve window-bar drag/zoom and U453's layout observer. Report restore errors without replacing unrelated saved work.
