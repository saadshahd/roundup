# App libraries

Acceptance for #3788; implementation belongs to its dependent work Issue. This specification adds no runtime capability. Scope: `apps/desktop`, in module-sized implementation PRs. Delete replaced custom machinery and dead callers; moving it behind a library-shaped wrapper does not count (policy). Keep the existing App, Terminal and storage owners; add no generic library adapter.

Policy: do not edit `apps/desktop/src/scrollHover.ts`, `apps/desktop/src/ui/Splitter.tsx`, `apps/desktop/src/switcher/Switcher.tsx` or `apps/desktop/src/changes/WorktreeControl.tsx`: #3742 owns them. Ranking changes behind the existing `matching` interface in `apps/desktop/src/switcher/entries.ts`; the existing caller already consumes its returned order. Keep destination/action groups separate. Other #3742 cases, including duration formatting and truncation measurement itself, remain there. A required change outside this ownership becomes a scoped prerequisite Issue, not a silent scope expansion.

Policy: inspect installed dependencies, repository patches and platform capabilities first. Every implementation PR carries `Reuse:` with two maintained candidates, primary source/release links, the selected version, specific rejection reasons and the custom code deleted. A demonstrated unsupported capability is recorded on the implementation Issue with file/symbol, version, probe and output; it does not waive a then-clause or complete an unimplemented feature. No Message, Route, Held or Takeover law changes are ordered. A necessary RPC or persisted-contract change follows the Contract recipe with every caller and glossary entry together.

**Z3788d virtualization follows one measured list gap.** Policy: before adding virtualization, run one observer over the existing Switcher destination list (consumer behavior through its current interface; no edit to the excluded Switcher file). Use deterministic lists of 40, 400 and 4,000 distinct names, fixed query/selection actions, the same host/browser/profile/viewport/build settings, 20 warmups and 200 measured keystrokes at each length. Retain raw samples, p50/p95, list length, seed, revisions and environment on the implementation Issue. Name the interval and observer before changing code: input event to the frame displaying its filtered results, using a rendered-browser trace, not Daemon RPC timing. Chromium results describe Chromium only; a native rule-7 claim needs the native observer in `docs/perf.md`, heading `Perf`. A trace that cannot identify the displayed result is an observer failure, not zero latency.

Policy: if valid observations at all three lengths are below the rule 7 keystroke-to-render limit of 16 ms p95, drop the virtualization implementation row and dependency entirely and retain the measurement as the completed decision. Missing/invalid measurement authorizes no virtualization and is recorded as an observer failure. If a valid observation is at or above 16 ms p95 and attributes the gap to whole-list rendering, file the scoped implementation against `@tanstack/solid-virtual`, with the measured list/length and native dependencies on this specification and #3742 before any edit to its Switcher file. Compare before/after using that same observer, host, lists and actions; the changed list must be below 16 ms p95 and introduce no rule 7 regression above 10%. Keep raw failed runs as well as successful ones. If the gap is not list rendering, file its actual cause instead of adding a virtualizer.

Given virtualization is licensed by that measurement, when the user navigates to the last matching item by keyboard, filters while it is selected, chooses it, then returns and scrolls, then its identity, selection, focus, action call count and accessible option navigation match the unvirtualized behavior. Planned `z3788d_virtual_navigation_preserves_selected_identity` belongs in the existing `apps/desktop/src/switcher/u529_switcher.test.tsx` only if virtualization is implemented. ## Library candidates

Policy: verify these candidates against the actual installed versions before implementation; publication in the same release establishes a compatibility starting point, not a rendered pass. The [xterm 6 source tag](https://github.com/xtermjs/xterm.js/tree/6.0.0/addons) publishes search 0.16.0, serialize 0.14.0, clipboard 0.2.0 and image 0.9.0 together; their [release](https://github.com/xtermjs/xterm.js/releases/tag/6.0.0) is dated 2025-12-22. Search supplies buffer matching; serialize supplies VT buffer output; clipboard supplies OSC 52 with a provider; image supplies SIXEL/IIP. Preserve the existing Daemon screen contract rather than assuming the browser addon replaces Rust screen serialization.

Policy: the requested ranking candidate is [fuzzysort](https://github.com/farzher/fuzzysort) 4.0.2 ([release metadata](https://registry.npmjs.org/fuzzysort), 2026-08-13). Compare [Fuse.js](https://github.com/krisk/Fuse) 7.5.0 ([metadata](https://registry.npmjs.org/fuse.js), 2026-07-13); this work order specifically requires fuzzysort scores, so Fuse is not a substitute. For DOM lifecycle use [event-listener](https://primitives.solidjs.community/package/event-listener/) 2.4.6 (2026-07-04) and [resize-observer](https://primitives.solidjs.community/package/resize-observer/) 2.2.0 (2026-07-05), both compatible with installed Solid 1.9 through their ^1.6.12 peer range. Native EventTarget/ResizeObserver plus Solid cleanup are the current mechanism to remove, not a second custom abstraction. [Storage](https://primitives.solidjs.community/package/storage/) 4.4.0 (2026-07-11) is conditional on its capability probe above; browser Storage plus Valibot remains the existing alternative when the library lacks error semantics. Version dates come from the corresponding npm registry package metadata, not potentially stale documentation badges.

Policy: if the measurement licenses virtualization, compare [TanStack Solid Virtual](https://tanstack.com/virtual/latest/docs/framework/solid/solid-virtual) 3.13.49 ([metadata](https://registry.npmjs.org/@tanstack/solid-virtual), 2026-10-22) with [virtua](https://github.com/inokawa/virtua) 0.53.6 ([metadata](https://registry.npmjs.org/virtua), 2026-10-21). The work order selects TanStack; rejection for a missing capability must name the probe. Neither is installed merely because a long list exists.
