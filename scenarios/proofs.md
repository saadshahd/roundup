# Proofs of the Messages delivery laws (V1 to V6)

Module: `proofs/` at the repository root, plus the pure `step` of `crates/messages` (B1 to B18, `scenarios/messages.md`). Source: the user's decision to split the proof work (2026-10-03): Bend 2 proves the small safety laws M1, M2, M3, M5, M6 and M7; Quint checks M4, M8, M9 and M10, including liveness. Neither tool proves the Rust: each checks a model, and an `inv_` replay test in Rust ties the model to the code (V4). Evidence for the choices and the laws' origin: the user's notes `/tmp/bise-audit.md` and `/tmp/bend-for-loop.md` (not in the repository; V3 restates every law so the repository stands alone). Tests run without Claude, a network or a display; the two checkers are pinned installs under the Project folder, no `sudo` and no shell file edited.

**V1 the toolchains are pinned.** Given a fresh checkout, then `proofs/BEND_VERSION` holds `2.0.34` and `proofs/QUINT_VERSION` holds the Quint version in use, and `just proofs-setup` installs each pinned version into `proofs/.tools/` (git-ignored) from a download whose checksum it checks, with `BEND_NO_TELEMETRY=1`, and fails loudly naming the tool when the version it installed is not the pinned one. A moved pin is a change to those files in a PR, never a floating `latest`. Observed by `loop/rules.sh`-style shell tests with a fake download: a matching version passes, a mismatch exits 1 naming the tool, a missing `curl` exits 1.

**V2 `just proofs` is the observer.** Given the layout `proofs/messages/{LAWS.bend,model.bend,PROOF.bend}` and `proofs/messages/model.qnt`, when `just proofs` runs, then it prints `ALL PROOFS CHECK` from `bend` and the Quint properties' verdict and exits 0 only if both pass; any other output, a missing file or a skipped property exits non-zero naming it. `just check` runs it. It fails on a `PROOF.bend` that holds `@unsafe` or `?TODO`, a `LAWS.bend` law with no `def Laws.<name>`, and a Quint property with no check. Tests: a temporary copy of the layout with each of those broken, and one with a law deleted from `PROOF.bend`.

**V3 the laws, written by a human.** `proofs/messages/LAWS.bend` states these six laws over `model.bend`'s state and `step`, and Builders never edit it; changing it is an Architect's PR approved by a different Architect (rule 4's spirit), and a law may only become stronger.
- `m1_final_and_at_most_once`: over any sequence of `send`, `idle`, `restart` and `takeover` events, a Message is typed at most once.
- `m2_held_leaves_only_by_its_owner`: a Message held for `ask-first` leaves `held` only by the user's `deliver` or `drop`; one held `escalated` only by the user's reply.
- `m3_takeover_isolates`: while a Takeover of `a` holds, nothing typed to `a` came from an Actor but the user.
- `m5_terminal_states_are_absorbing`: `delivered` and `dropped` never change, and Message ids are unique and rise by one.
- `m6_no_silent_loss`: every Message is `delivered`, `dropped` with a reason, or still `pending` or `held`.
- `m7_receiver_gone`: after a Kind of `done` or `error` no `pending` Message to that Agent remains, and a later send is `CONFLICT`.
Each is a statement of `scenarios/messages.md` (B2, B3, B6, B8, B9, B15), not a new rule. The Builder who writes `PROOF.bend` states in the PR which `step` guards each proof uses, and if a proof will not go through, reports the law and the checker's `expected` and `observed` and stops: a failing law may be a scenario defect, and no law is weakened to pass. Tests: `bend proofs/messages/PROOF.bend` prints `ALL PROOFS CHECK`; the same run on a `model.bend` that drops one guard (one mutant per law, kept in `proofs/messages/mutants/`) prints `SOME PROOFS FAIL` naming that law.

**V4 `crates/messages` has a pure `step` that the model mirrors.** Given `crates/messages`, then its transitions are one pure, total function `step(&State, Event) -> (State, Vec<Effect>)` with no I/O, clock or random source (the Daemon applies the effects; B8 and B9's restart and receiver-gone rules are events), and `model.bend` has the same transition names, guards and order as `docs/messages.md`. For each law V3 names there is a Rust test `inv_<law name>` that replays the event sequences the law quantifies over, generated from a fixed seed with at most 6 events and 3 Messages, against `step`, and asserts the law. Observed by those tests and by a check that the transition names in `step` and in `model.bend` are the same set. A model simpler than the Rust (a dropped guard, two transitions merged) is a reject, and a Rust transition with no model transition fails the name check.

**V5 the Quint model checks the interleavings and liveness.** Given `proofs/messages/model.qnt`, a model of B1 to B18 with the actors send, idle, restart, takeover and the user's calls, then Quint checks these properties and each passes:
- `m4_no_overtaking`: typed order is the order in which Messages became deliverable, ties by id, and a held Message never blocks a later one (B7).
- `m8_escalation_terminates`: every question reaches an answer, a drop or `held escalated` within hops + 1 bounds, never loops, and the sender is never a hop (B13 to B17).
- `m9_restart_is_a_replay`: the state after a crash and reopen equals the replay of the stored records (B8, D6).
- `m10_pending_to_idle_is_eventually_typed`: a `pending` Message to an Agent that becomes `idle` is eventually typed, under the stated fairness assumption that an `idle` Agent is eventually delivered to, and the model names that assumption in a comment that says what breaks without it.
Observed by `just proofs`, and by one deliberately broken variant per property in `proofs/messages/mutants/` that Quint rejects with a counterexample trace naming that property; a property the checker cannot reject a mutant of proves nothing and is a defect. The bounds (Messages, Agents, depth) are named constants with the reason beside each.

**V6 the Reviewer checks the proofs.** For a PR touching `crates/messages`, `docs/messages.md` or `proofs/`, `.agents/reviewer.md` tells the Reviewer to: run `just proofs` on the checkout (anything but exit 0 is a reject); run `git diff origin/main -- proofs/messages/LAWS.bend` (non-empty without a cited Architect approval is a reject, and so is a law weakened, deleted or made trivial); grep the diff for `@unsafe`, `?TODO`, `exs` with a fixed witness and a `law` with no matching `def Laws.`; compare `model.bend` and `model.qnt` with the Rust for each changed B scenario (a simpler model is a reject); and state in the verdict that the proofs cover the models, not the Rust. `.agents/architect.md` adds: before approving a Message, Route, Held or Takeover contract change, name which of M1 to M10 it touches and confirm the models and `docs/messages.md` agree. Observed by the reviewer prompt's text (a test greps `.agents/reviewer.md` and `.agents/architect.md` for each rule) and by a PR with a weakened law that the checks reject.
