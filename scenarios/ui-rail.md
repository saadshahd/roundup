# UI: Rail and Drawer polish

Module: `apps/desktop` (the webview): Rail and Drawer. Ids: every `U` heading in the file (U61 to U79 are the squad's range).

Gaps found by reading `ui.md`, the open PRs and the Rail code, for what a daily user meets first: naming a Group, a name that does not fit, an empty Group, and a Drawer hiding the Terminal the user just selected. Every clause is observed in Vitest against the fake App, in the Chrome fake-Daemon harness (U26) or in a Rust or e2e test. Rail changes are instant (`docs/motion.md`): nothing here animates except U64's Drawer, which uses U5's slide as it is. Text meets U4's 4.5:1, and a word called "light" is `--grey`. No contract, App seam command or token changes.

**U61 a name edit keeps what the user typed.** Given a Rail row whose name is being edited in place (U9, and U41's `F2`), then Enter, or clicking anywhere outside the field (blur), commits the trimmed text with exactly one `rail.rename {id, name}`; Esc never commits, not even when a blur follows it; and a text that is empty after trimming, or equal to the current name, closes the field and calls nothing. A click outside the field that lands on `+ agent`, `+ terminal` or `+ group` commits first and then does that click's own work. The field opens in the same frame as the double-click and closes in the same frame as the commit, with no animation. When `rail.rename` fails, the field is closed, the row shows the name it had, and U9's `✕ <message>` line shows above the actions until the next click. Found: today a click elsewhere silently throws the typed name away. Owns `apps/desktop/src/rail/RailRow.tsx` (its name field) and the rename call in `Rail.tsx`; keeps green `u9_double_clicking_a_name_edits_it_and_enter_renames`, `u9_escape_keeps_the_old_name_and_calls_nothing` and `u9_an_empty_name_keeps_the_old_name_and_calls_nothing`, and narrows none (U9 says nothing of blur). It stacks on no open PR.

**U62 a new Group is named at once.** Given `+ group` (U9), when `rail.createGroup {name: "group", parent}` succeeds, then the new Group's row becomes selected once `rail.tree` holds it, as U9 does for an Agent and U47 for a Terminal, and its name opens for editing in place in the same frame, with the text `group` fully selected and focus in the field, so typing replaces it. Enter, Esc, blur, an unchanged name and a failed call behave as U61 says; Esc leaves the Group named `group`. A Group that the tree never returns never opens a field, because rows come only from `rail.tree` (U9). Once the field has closed, the Group is the selected parent for `+ agent`, `+ terminal` and `+ group` by U9's parent rule. The call and its params are unchanged. Owns `Rail.tsx` (the `+ group` action and the wanted-selection effect) and the edit trigger in `RailRow.tsx`; keeps green `u9_plus_group_creates_a_group_named_group_under_the_selected_group` and gains the selection and field checks; narrows none. After U61.

**U63 an empty Group says so.** Given a Group with no children, then its row shows a light `empty` where U8 puts the child count, whether it is expanded (`▾`) or collapsed (`▸`), and it does not show a count. The word appears and goes in the same frame as the tree change that empties or fills the Group (a Terminal exits and is removed, a row is dropped in), with no fade; it is in `--grey` and meets U4's 4.5:1 on the ground and on the selected-row band. A Group with one child or more is unchanged: the count shows only when collapsed. An empty Group can be a drop target: a drag whose drop line sits below it at one depth deeper (U22) calls `rail.move {id, parent: <the empty Group>, index: 0}`, and the drop line is drawn at that depth. `promote` on hover and U9's click behaviour are unchanged. Owns `apps/desktop/src/rail/RailRow.tsx` (the count position), and `rail/styles.css`; keeps green `u8_a_collapsed_group_shows_a_light_child_count`, `u8_the_child_count_counts_direct_children_not_descendants`, `u8_a_collapsed_group_with_no_agent_below_shows_a_right_triangle` and the U22 tests; narrows none. After U62.

**U64 choosing a row closes the Drawer.** Given an open Drawer (U5) that covers the Terminal, when the selection changes to a different row, by click, by `↑`/`↓` plus Enter (U31), by `⌘J` (U30), by `⌘K` (U51) or because a spawned Agent or Terminal became selected (U9, U47), then the Drawer closes as `close` closes it, sliding out in about 180 ms with ease-out and instantly under `prefers-reduced-motion` (U5), and the chosen row's Terminal shows. Found: the Rail stays visible beside a Drawer (U24), so the user selects an Agent and still looks at a Todo. Selecting the row that is already selected, a selection that clears because its node left the tree (U3), and opening a Drawer, including from a Rail row's Pad (U58) or Todo (U60), do not close it and do not change the selection. Focus after the close follows U40 and U27 as they are written: a focus the user moved elsewhere is left alone, and the pane's size never changes (its size observer reports nothing). It calls no method of its own. Owns `apps/desktop/src/drawer/**` and one effect where the selection is held; keeps green every test of U5, U27, U28 and U40 (`mountPaneWithDrawer` in `u27_drawer_keys.test.tsx` selects before it opens the Drawer, so it does not change). After U40 and U58 merge.

**U65 the whole name is one hover away.** Given a Rail row whose name is longer than the Rail allows (U23), then the name keeps one line and ends in `…`, and its `title` is the full name, as U29 does for a Pad; a name that fits has no `title` of its own. On a Group the child count (U8) and `empty` (U63), and on hover `promote`, stay inside the Rail's right edge, and the row's height equals a row with a short name, so nothing moves (U46). In the Chrome harness (U26) at 252px, a row with an 80-character name has its right edge inside the Rail, and every other row's top edge is where it was before the name changed. While the name is edited (U61) the field holds the full name, never the cut one. The Live line's own `title` stays as U49 says. Owns `apps/desktop/src/rail/RailRow.tsx` (the name's `title`) and `rail/styles.css`; keeps green the `u6_` tests and U49's and narrows none. After U63, since both touch the same row.

**U66 rendered Pads and a source Editor.** Given a Pad Drawer (U20) at 1280 by 800, then its body initially renders markdown headings, paragraphs, emphasis, lists, links, blockquotes and fenced code in a scrollable reading view that fills U50's remaining height. The Pad's stored and exported source stays byte-for-byte unchanged. Script elements, event attributes and unsafe link schemes in source never execute or make a live link. A user-owned Pad offers `edit`: choosing it focuses a syntax-highlighted markdown Editor in the same width, with `Preview` to see the rendered draft and `edit` to return to the Editor; neither view switch writes. `done` returns to the reading view. Blurring the Editor outside the Pad editing controls, or choosing `done`, calls `pad.write` once only if the source changed; there is no timed write. An Agent-owned Pad has no Editor, keeps U20's `append`, and shows appended text at the end on success; another Actor's `pad.changed` preserves the reader's scroll position, and a failed append preserves both text and scroll (U141). U36's dirty draft, conflict line, `keep mine`, `use theirs`, handover and in-flight write rules apply in the Editor and Preview, including when a view switch blurs the Editor. Opening still makes U20's single `pad.read` Touch, and `pad.changed` refreshes a clean view from `pad.list`. The renderer loads only when a Pad Drawer opens, the Editor only when `edit` opens; cold start and keystroke-to-render meet the performance budget in AGENTS.md. Observers: `u66_` Vitest cases cover each render kind, unsafe content, ownership, view switching and focus, exact source round-trip, changed and unchanged blur/`done` call counts, conflict and handover, U141 scroll outcomes, and lazy module loading; browser proof shows the reading view, Editor and Preview at 1280 by 800. This narrows U20's monospace-source test to the Editor, U50's textarea-specific tests to the body and Editor, and U141's textarea scroll assertions to the rendered reader; the other U20, U36 and U141 outcomes stay. Owns `apps/desktop/src/pads/**` and the needed desktop package and lock files; no Daemon or contract change.
