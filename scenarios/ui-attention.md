# UI: attention, jumping and the Thread's input (U105 to U110)

Module: `apps/desktop` (the webview); begins when the Door scenarios land. Ids: U105–U110.

Source: the user's $anchor rules on attention, navigation and ergonomics (2026-10-02/03). The Thread is the user's conversation with a Meta-agent (`GLOSSARY.md`); "Main" in those rules is the Thread's Agent, and "main agent" is an _Avoid_ word. The Thread's input and feed have no scenario on main yet, so each clause says "the Thread's input" and its Builder starts only when the Door scenarios land. Webview only: no App command and nothing under `contracts/`; U108 is a spike. Every clause is read on the injected emulator, the fake App and the U26 harness, with a fake clock.

**U105 typing dims the periphery.** Given an open Project, when the Thread's input has focus and the user types a character, then within 120 ms (the crossfade row of `docs/motion.md`) every Rail row except a row of Kind `needs-you`, every Shelf row and every Live line is at an effective opacity of 0.35 (the product of its own and its ancestors' opacity, which a test reads from the harness); when the input is submitted (Enter) or loses focus they are back at 1.0 in the same time. Reduced motion changes both at once. The dim is a look only: every row and button still takes clicks. A `needs-you` row stays at 1.0 so the one Kind that blocks an Agent is never hidden. It changes no contrast value: U4's 4.5:1 test and U130 to U137 run with the input unfocused, as today. Tests: both ends of the fake clock, a `needs-you` row among others, Enter, blur, reduced motion.

**U106 agent-to-agent Messages are one line.** Given `message.*` events for Messages between Agents (not to or from the user), then the Thread's feed shows each as one line, `<from> → <to> <kind> <first 60 characters>…`, and no body. While focus is in the Thread's input or feed, `⌃O` expands every such line to its full body and `⌃O` again folds them; the webview takes it there and in no other place. With focus in a Terminal pane `⌃O` goes to `terminal.write` as U12 says, so a Takeover keeps the Agent's own binding and U12 is unchanged. The chord appears in U54's help and is not saved (U100's storage never holds it). Digest in `GLOSSARY.md` means a child's state entry (B19), so this says "folded line". Tests: three Messages, the toggle both ways, a long body, a Message to the user (not folded), `⌃O` in the pane (reaches `terminal.write`, no toggle).

**U107 jump to an Agent.** Given an open Project, when the user presses `⌥1` to `⌥9`, then the n-th Agent row as the Rail shows it, top to bottom (a Meta-agent row counts; Groups and Terminals are skipped; the Agents of a collapsed Group are not shown and so not counted), is selected, its Terminal takes keyboard focus and `takeover.begin {agent}` is called (B6); `⌥0` calls `takeover.end {agent}` and returns focus to the Thread's input; a jump to a second Agent ends the first Takeover before the next begins. The chords are read by key position, not by the character `⌥` produces, and the webview takes them wherever focus is, so this narrows U12: with focus in a pane these chords do not reach `terminal.write`. A number with no Agent does nothing. When `takeover.begin` answers `CONFLICT` (B6: the Agent is `done` or `error`) the selection still moves and U80's one failure line shows. After a Daemon restart the webview calls no `takeover.end` for a Takeover that B8 says no longer exists. Tests use the fake App, record the order of calls and name the U12 test that is narrowed. Typing `@` for the switcher belongs to U51's owners and is not here.

**U108 (spike) the shell as a Drawer that becomes a Rail node.** Question: can `⌃\`` toggle a slide-out shell that, when minimised, stays alive as a Rail Terminal node (a Terminal is already a Rail node, `terminal.spawn`) without a fixed split pane? Pass: a prototype on the fake App that shows toggle, minimise and reopen with its process alive and one `terminal.resize` per U13, plus a written answer on whether it needs a new App seam command. Fail: it needs a seam command, so the spike ends with a seam proposal for the committee. No Builder starts on this id.

**U109 an image pasted becomes an Attachment.** Given the Thread's input, when the user pastes or drops an image, then a compact Attachment (its name and size) appears inline at the caret, and hovering it shows a floating preview of the image at its own size up to 480 px wide, which hides when the pointer leaves or `Esc` is pressed. What an Agent receives from an Attachment is a spike: the Adapter has no channel for image bytes, so the Attachment shows in the feed and nothing is typed into a Terminal. Tests: a stubbed clipboard and drop event, two Attachments, hover and `Esc`, a file that is not an image (refused with U80's one line).

**U110 select-to-quote.** Given text selected in the Thread's feed or in a Terminal's output, when the user then types a printable character in the Thread's input, then one Quote block is attached before the typed text, and the selection is used up: the next character typed adds no Quote. The block holds the selected text, up to 2000 characters (a longer selection is cut and marked `[cut]`), and its source, the name the Rail shows for that Agent or Terminal (or the Message id for a Message). The typed character lands after the block. A selection of no characters, or one made in the input itself, adds nothing. Whether a quote is true to its transcript is the Evaluator spike (B27). Tests use the injected emulator selection and the harness: a first and a second character, a long selection, a plain Terminal, an empty selection.

Tests are named `u105_` to `u107_`, `u109_` and `u110_`; U108 has a pass condition and no test.
