# Worktrees

Module: `crates/agents` (`src/worktree.rs`, which runs the `git` command; `git` on `PATH` is the one requirement), with end-to-end tests in `crates/rup/tests`. Terms: Worktree, Base, Landing (`CONTEXT.md`). Principles served: P2 (`PRINCIPLES.md`), P4 (provisioning is vendor-neutral, in `crates/agents`, never in `claude_code/`) and P5. Design: `docs/worktrees.md`. Tests use a real `git` in a temporary repository, a fake `claude` (`ROUNDUP_CLAUDE_BIN`, A4), no network. Contract change (the committee approves it in its own PR, rule 4): the methods and fields named below are new, and the contract PR changes every caller of `RailNode`.

**G1 the `worktrees` setting.** Given a Project, when `project.setWorktrees {on, check}` arrives (`on` a boolean, `check` a command line or `null`), then the setting is stored in the Project's database and `project.get` returns it; a Project that never had it set returns `{on: false, check: null}`. It survives a Daemon restart. With `on: false`, `agent.spawn` behaves exactly as A4 says and the Agent's node has `worktree: null`. A `check` that is the empty string is `INVALID_PARAMS`.

**G2 spawn provisions a Worktree.** Given `worktrees` on and a Project that is a git repository on a branch with at least one commit, when `agent.spawn {cwd, prompt}` arrives (A4), then before the Agent starts the Daemon makes the branch `roundup/agent-<id>` at the Project's current commit and a git worktree for it at `<Project folder>/.roundup/worktrees/agent-<id>`, adds `.roundup/` to the repository's `.git/info/exclude` if it is not there, and starts the Agent with that Worktree as its working directory (the same subpath of it when `cwd` was a subfolder of the Project). The node's `worktree` is `{path, branch, base}` where `base` is the branch that was checked out in the Project. It is stored with the node and `rail.tree` returns it. Two Agents spawned back to back have different working directories (P2's observer). A Terminal spawned with `agent.spawnTerminal` is not given a Worktree. When any step fails, then `agent.spawn` fails with its own error code and nothing is left: no node, no branch, no worktree directory, and `git worktree list` and `git branch` equal what they were before the call. The codes are `not_a_git_project` (the folder is not a git work tree, or has no commit), `no_base` (HEAD is detached) and `worktree_failed` (git failed; the message holds git's own text).

**G3 a Worktree's status.** Given an Agent with a Worktree, when `agent.worktreeStatus {id}` arrives, then it returns `{ahead, behind, dirty}`: `ahead` is the number of commits on the Agent's branch that the Base does not have, `behind` the number on the Base that the branch does not have, and `dirty` is true when the Worktree has any staged, unstaged or untracked change outside `.roundup/`. A fresh Worktree is `{0, 0, false}`. After one commit in it the result is `{1, 0, false}`, after one commit on the Base `{1, 1, false}`, and writing an untracked file makes `dirty` true with the counts unchanged. The call changes nothing: the branch, the Base and the files are the same after it. For an Agent or Terminal with `worktree: null` it fails with `no_worktree`; when the directory is gone from disk it fails with `worktree_missing` naming the path, and the node stays.

**G4 landing.** Given an Agent with a clean Worktree (`dirty` false), when `agent.land {id}` arrives, then the Daemon rebases the Agent's branch onto the Base's current commit, runs the Project's `check` command in the Worktree if one is set, and fast-forwards the Base to the branch; it returns `{base: <commit>}` and the Agent's status is then `{0, 0, false}`. It never writes the Base any other way, and it never commits for the Agent. Each failure leaves the repository as it was before the call, and names its code: `worktree_dirty` (the Worktree has changes; nothing ran), `landing_conflict` (the rebase hit a conflict; the Daemon aborts it, the branch is where it was, and the error's message lists the conflicted paths; it never picks a side), `check_failed` (the check exited non-zero; the message holds its last 20 lines of output; the Base is unchanged and the Daemon resets the branch to the commit it had before the call), and `base_dirty` (the Project's own checkout has changes and the fast-forward would touch them; nothing changed). An Agent with `worktree: null` fails with `no_worktree`. The tests make a conflict between the Base and the branch, a failing check (`false`), a passing check (`true`) and a dirty Project checkout, and compare `git rev-parse` of both branches and `git status` before and after each failure.

**G5 removal never loses work.** Given an Agent with a Worktree, when `rail.remove {id}` arrives (A16), then if the Worktree is clean and the branch has no commit the Base lacks (`ahead` is 0), the Agent is stopped and removed as A16 says, and its worktree directory and its branch are deleted, so `git worktree list` and `git branch` equal their state before the spawn (P5's observer). If the Worktree is dirty, or the branch is ahead of the Base, then `rail.remove` fails with `worktree_unlanded` before it stops anything: the node, the Agent's status, the directory, the branch and every file are unchanged, and the message says `dirty`, `ahead` or both with the counts. `agent.discard {id}` is the deliberate way to drop work: it stops the Agent, deletes the node, the directory and the branch whatever their state, and returns `null`; a Terminal or an Agent with `worktree: null` fails with `no_worktree`. A directory that is already gone from disk is not an error for either call: the node goes and git's record of it is pruned. A Group or Meta-agent removed with `rail.remove` follows A16 for its children and leaves their Worktrees alone; only the removed node's own Worktree is considered.

**G6 the Daemon finds its Worktrees again.** Given Agents with Worktrees, when the Daemon is stopped and started again on the same Project, then `rail.tree` returns each node's `worktree` as before, `agent.worktreeStatus` answers for each from the directories on disk, and no Worktree, branch or file changes. A worktree that git lists but that no node names (made by the user or another tool) is never reported as an Agent's, never touched by G4 or G5, and never deleted. A node whose directory the user deleted keeps its node and answers `worktree_missing` (G3).
