# UI: icons on a Rail row (U426 to U429)

Module: `apps/desktop/src/rail/` (the webview) and `crates/desktop` (U429's one App seam command). Ids: U426, U427, U428, U429. Found by the user's report #1098 (Solo's Project list shows a folder and a `</>` icon on a hovered row: "tasteful and meaningful and needed"). Decided by the user: the Workstream row shows add an Agent, clear, open folder and open in editor; the Agent row shows stop, open folder and open in editor; the Project tab shows none, because every Agent and Workstream can have its own Worktree. Decided here: the icons are Rail-only, the right-click menu is unchanged, and the App learns the editor as U429 says. U426 to U429 ship together so every rendered editor icon has its App seam caller (rule 4). U416 governs the controls’ sentence case.

**U426 a hovered, focused or selected Rail row shows its icons without moving.** _Amended only as listed by U3789e (`ui-shelf.md`); U3789a–d govern those replacement clauses._ Narrows U46, U392 and U404; changes no Daemon method and no Token. > U466 replaces Trailing room: zero list sides, 16 px row content sides, and actions inside the trailing inset.

- **When.** The group is visible while the row is hovered, holds keyboard focus within it, or is selected (U7's rule for the Live line), and is otherwise hidden but still in the Tab order. Each icon is a `data-button="icon"` button (`docs/design-system.md`, _Button kinds_), 16 px mark in a 24 px square, all from one icon set, with an `aria-label` and a `title` that repeats it, with U427’s shortcut or Clear qualifier where specified. Asserted in `u426_the_group_shows_on_hover_focus_and_selection` and `u426_every_icon_is_an_icon_button_with_label_and_title`.
- **Trailing room.** Narrows U58’s count control, U161’s rhythm, U172’s Rail density and U404’s owned control: the scrolling list keeps its leading `--space-4` inset and zero trailing inset. When an Agent’s group shows, it replaces the Pads count, hovered or selected in dark. The design critic judges this placement (AGENTS.md rule 10); U389’s no-horizontal-scroll and width tests remain.
- **Stopped Door.** U403 and U387’s Start Door or Retry Door remains an icon target with Lucide `play` at the start of the group, with its name as the accessible label and tooltip, rather than a squeezed word button. It keeps U403’s selection and start behavior. Asserted in `u426_the_stopped_door_keeps_a_readable_control_beside_the_group`.
- **Keyboard.** Every U427 and U428 icon is reached by Tab from its row; `railStep` still steps rows only, and `Enter` or `Space` on an icon runs it and does not select the row. Asserted in `u426_railstep_skips_icons` and `u426_an_icon_runs_without_selecting_its_row`.
- **Menu kept.** The row menu (U56) still offers stop, resume and remove. Asserted in `u426_the_row_menu_keeps_stop_resume_and_remove`.

**U428 an Agent row's icons: stop or resume, open folder, open in editor.** _Amended only as listed by U3789e (`ui-shelf.md`); U3789a–d govern those replacement clauses._ Narrows U56, U404 and U427; changes no Daemon method and no Token. Given a Door or Subagent row, then:

Other stopped Agents show neither. Asserted in `u428_resume_replaces_stop_on_a_resumable_stopped_agent`.
- **Open folder.** The icon after them calls `open_target {kind: "path", path}` with the Agent's Worktree path (`RailNode.worktree.path`) when it has one, else the Project folder. Asserted in `u428_open_folder_prefers_the_worktree` and `u428_open_folder_falls_back_to_the_project_folder`.

**U429 the App opens a directory in the user's code editor.** Adds one App seam command, `open_in_editor {path}` (Contract recipe: `scenarios/app.md`'s table, `GLOSSARY.md` gains **open_in_editor**, the webview's `seam.ts` and `tauri.ts` and the fake App change in the same PR); changes no Daemon method and no Token. Decided here (the Issue left it to the spec): the App finds the editor itself, so the user sets nothing. In order, the first that applies: the app named by `ROUNDUP_EDITOR` (a bundle id or an application name, for a user who wants another), then `com.microsoft.VSCode`, then `com.todesktop.230313mzl4w4u92` (Cursor), the two `open.rs` already knows (`LINE_APPS`); an app counts when the system finds it installed. Given an absolute path to an existing directory, then:
- **Opens.** The App launches the chosen editor on the directory (`open -b <bundle id> <path>`, or `open -a <name> <path>`, on macOS) and returns `null`. Asserted in `u429_opens_the_directory_in_the_first_known_editor` and `u429_roundup_editor_wins_over_the_defaults`.
- **No editor is said, not silent.** When none is found it fails `NOT_FOUND` with the message `no code editor found; install VS Code or Cursor, or set ROUNDUP_EDITOR`, and the Rail shows it as U80's `✕ <message>`. Asserted in `u429_no_editor_is_not_found_with_that_message` and `u429_the_rail_shows_a_missing_editor_in_one_failure_line`.
- **Refusals.** A relative path is `CONFLICT`, a path that does not exist is `NOT_FOUND`, a file is `CONFLICT` (a directory only), as `open_target`'s checks (U365) refuse. Nothing is launched. Asserted in `u429_a_relative_path_is_conflict`, `u429_a_missing_path_is_not_found`, `u429_a_file_is_conflict`.
- **Seam.** The command is in the webview's `seam.ts` list and the fake App, and `scenarios/app.md`'s table has its row. Asserted in `u429_the_command_is_in_the_seam_list`.
