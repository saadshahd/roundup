# UI: a Terminal running worktrunk lists the Project's worktrees (U2543a to U2543c)

Module: `crates/contracts`, `crates/rupd`, `crates/terminal`, `contracts/generated/` and `apps/desktop`. Ids: U2543a to U2543c. Source: the owner's words on #2543 (2026-10-18): "we could enrich it by using worktrunk in a terminal view to help the user stay on top" and "i also like worktrunk cli to manage worktrees". Terms: Terminal, Bubble, Workstream, Worktree, Project (`GLOSSARY.md`). Acceptance only; work ownership and dependencies live in GitHub Issues. No implementation is claimed by this specification.

`wt` ([worktrunk](https://github.com/max-sixty/worktrunk), v0.80.0 released 2026-09-27, installed by `brew install worktrunk` per its README) lists every git worktree of a repository with its branch and state, roundup's own Worktrees (`<Project>/.roundup/worktrees/agent-<id>`, G2) included, because they are plain git worktrees. roundup adds no list of its own and never requires `wt`.

Decided here (numbered engineering calls, changed only by a later scenario):

1. **Reuse, not a pane.** The view is `wt list` itself in a Terminal. The Terminal is a Bubble (U164) owned by the selected Workstream, so it moves, resizes, minimises and closes as any Bubble; no pane, Rail row or list component is added (rule 9: worktrunk is MIT or Apache-2.0 and maintained; a custom list failed on cost, since git state per worktree is what it already renders).
2. **What the Daemon runs.** `terminal.open` gains an optional `program` of the closed set `shell` (default, today's behaviour) or `worktrunk`. `worktrunk` starts the user's login shell (as `shell` does) with `wt list` typed as its first command, in the Project folder, so the table stays on screen and the Terminal remains a usable shell afterwards. Any other value is `INVALID_PARAMS`. `GLOSSARY.md` gains **Worktrunk Terminal** in the same PR.
3. **Availability.** `wt` is found on the login shell's `PATH` when the Daemon starts a `worktrunk` Terminal, never cached. If it is missing, `terminal.open {program: "worktrunk"}` answers `NOT_INSTALLED` with the message `wt is not installed: brew install worktrunk`, and starts no Terminal.
4. **The entry.** The leader (U2239) gains the key `T`, "list worktrees". It stays in the table and in Help (U480) whether or not `wt` exists, so the panel of U2240 lists seven keys.

**U2543a the entry opens the worktrunk Terminal in one step.** Given an open Project with a selected Workstream and a fake `wt` on the Daemon's login `PATH`, when the user presses `⌘K` then `T`, then one `terminal.open {workstream, program: "worktrunk"}` is sent; one Bubble opens focused at the default place (U165) showing the output of `wt list`, one row per git worktree, including every roundup Worktree of the Project. With nothing selected, while a call is in flight or after `daemon-exited`, the key does nothing. Tests: `u2543a_leader_t_opens_one_worktrunk_bubble_for_the_workstream`, `u2543a_the_table_lists_roundup_worktrees` (a real Daemon over a git repository with two Agent Worktrees and a fake `wt` that prints `git worktree list`; asserts both `agent-` paths appear on the Terminal screen), `u2543a_leader_t_does_nothing_without_a_workstream`.

**U2543b it is a Terminal like any other.** Given the Bubble of U2543a, then it appears in `terminal.list` with the Workstream as owner and no Message receiver, takes `⌘K M` and `⌘K W` (U165), accepts typed keys (`terminal.write`) after the table, ends with `terminal.close`, and is not stored across a Daemon restart. The App adds no pane, no Rail row and no component that lists worktrees itself. Tests: `u2543b_the_bubble_minimises_restores_and_closes_like_any_bubble`, `u2543b_typed_keys_reach_the_shell_after_the_table`, `u2543b_nothing_besides_the_bubble_is_added` (the DOM holds no worktree list outside the Terminal emulator).

**U2543c without `wt`, the entry says how to install it.** Given no `wt` on the login `PATH`, when the user presses `⌘K` then `T`, then the Daemon answers `NOT_INSTALLED`, no Terminal and no Bubble starts, and U80's failure line shows `wt is not installed: brew install worktrunk` (accessible text, the line of U9). Every other feature works unchanged and nothing else requires `wt`. Tests: `u2543c_missing_wt_answers_not_installed_and_starts_nothing` (Daemon), `u2543c_the_failure_line_names_the_install_command` (Vitest against the fake App).
