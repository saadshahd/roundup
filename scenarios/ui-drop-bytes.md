# UI: the bytes of a File drop (U175)

Module: `apps/desktop` (the webview). Ids: U175.

**U175 a dropped image writes the bytes a native terminal sends, or the difference is named.** Found by #603: an image dropped on an Agent's pane takes a few seconds to attach, a little longer than in a native terminal. Narrows U162 (`ui-daily.md`); changes no contract, App seam command or Token, and no Daemon method. Given the selected Terminal runs an Agent whose program asked for bracketed paste (`ESC [ ? 2004 h`), when a `drop` of one image at `/Users/me/My Pics/it's.png` reaches the pane, then:

- `terminal.write` receives, in order, exactly `ESC [ 200 ~`, `'/Users/me/My Pics/it'\''s.png' ` (the quoted path and one trailing space, no newline) and `ESC [ 201 ~`, as one paste and no other write; roundup reads no file and adds no byte for the image's size or format. Test: `u175_a_dropped_image_writes_one_bracketed_paste`, on the real xterm emulator built by `createXtermEmulators` (`apps/desktop/src/terminal/emulator.ts`, as `u102_emulator.test.ts` builds it), not the injected fake, whose `paste` has no bracketed-paste mode. The test writes `ESC [ ? 2004 h` to the emulator, drives the drop through the fake App's `onFileDrop`, and asserts the bytes `onInput` yields and then the bytes and the count of `terminal.write` calls.
- With the program not in bracketed-paste mode, the same drop writes the quoted path and its trailing space with no marker. Test: `u175_without_bracketed_paste_the_path_has_no_marker`, the same setup without the `ESC [ ? 2004 h` write, asserting the same three facts.
- Policy: the native side. The same image dropped on Terminal.app, iTerm2 and Ghostty in the same `claude --version` is observed on the user's Mac with a byte recorder (`cat -v` after `stty raw -echo`, or `script`) and recorded on #609 in two columns, roundup's and the native terminal's, each with: marker bytes, quoting or escaping of the space and `'`, trailing space, newline and the number of writes. The Linux harness cannot send a native drop, so the user adds the native column.
- Policy: each difference is named as one of *Claude Code waits on it* or *Claude Code ignores it*, with the evidence (Claude Code's reaction timed with the same image in both). A difference Claude Code waits on is filed as its own work Issue, scenario-first, blocked by nothing in this one; a comparison with no such difference is recorded as that and the wait is Claude Code's own.

#609 stays open until its comment holds the comparison; this scenario's PR closes nothing.
