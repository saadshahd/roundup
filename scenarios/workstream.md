# Workstream: the Room's new name and its one entry point (A25, U162, U163)

Module: `crates/agents`, `crates/contracts`, `crates/rupd`, `crates/rup`, `contracts/generated/` and `apps/desktop`. Ids: A25, U162, U163. Found by the user's report #369: the word `Room` confuses, the Rail offers `+ agent  + terminal  + room` as three equal adds, and a Terminal is among the first things a new user meets. Decided by the user: **Workstream** replaces **Room** everywhere at once; the unit of work is opened first and staffed after; one add action opens it; an Agent or a Terminal is added inside a Workstream; Agents come before Terminals wherever both appear. `Door` keeps its meaning, now "of one Workstream". `Project` stays the repository.

The Room's behaviour is unchanged: A6, A7, A8, A16, A18, A23, A24, O3, O6, U6, U8, U9, U62, U143, U145, U160 and the rest keep every clause, read with `Workstream` for `Room`. This file changes the name, the entry point and the order only. The implementing PR is the atomic one that A25 describes (rule 4: every caller changes in the same PR); it then rewrites the word in every scenario file, doc and test name (`u160_room_scope` becomes `u160_workstream_scope`), so no scenario keeps the old word except where it is quoted as the old name.

**A25 Room becomes Workstream on the wire and on disk.** Contract change (the Contract recipe of `.agents/builder.md`). Given the Daemon, then:
- `NodeKind::Room` is `NodeKind::Workstream` and serializes as `"workstream"`; `CreateRoomParams` is `CreateWorkstreamParams`; `rail.createRoom` is `rail.createWorkstream {name, parent, order?}` with A6's and O3's behaviour. The method `rail.createRoom` and the value `"room"` no longer exist: a call to `rail.createRoom` fails with `METHOD_NOT_FOUND`, and a node of Kind `"room"` is never produced. `contracts/generated/` is regenerated from `crates/contracts`, never hand-edited.
- A Rail stored by an earlier Daemon (A8) holds `kind: "room"`. `Agents::open` reads it as a Workstream with the same id, name, parent, order, Door and children; the next write stores `"workstream"`. Nothing else in the stored Rail changes, and a Rail that never held a Room opens as before.
- O3's default Door question for a Workstream created without an `order` is `What is this Workstream for?`. A stored order keeps the text it was stored with. B24's Door Brief and the Door's system prompt say `Workstream` for `Room` (policy, read in the real-Daemon run). Every `rup` tool description, error message and `--help` line that named a Room names a Workstream.
- Every Rust module, file, public item, test and doc names it `Workstream` (`room_door.rs` becomes `workstream_door.rs`); `GLOSSARY.md` replaces **Room** by **Workstream** (`_Avoid_: room, folder`) and rewrites **Project**, **Home**, **Door**, **Rail**, **Shelf**, **Thread** and **Route**'s sentences with it, so `loop/rules.sh vocab` (rule 6) fails any public name that still uses `room`. A `GLOSSARY.md` entry for **Workstream** says "The persistent place for one body of work, named for the work", never "place" as a location, and keeps the sentences on Door, nesting and cross-Workstream dependencies. The same PR changes `docs/wireframes.md`, `docs/messages.md`, `docs/design-system.md`, `PRINCIPLES.md` and `proofs/` wherever they name a Room, and keeps `proofs/messages` and `docs/messages.md` agreeing (M1 to M10 are untouched in meaning: the laws weaken nowhere).
- Not rewritten: the committed captures under `artifacts/ux/*/observer.txt` and `loop/plans/`, which record what was observed.

Tests (`a25_`, Rust, in `crates/agents/tests/scenarios/`, `crates/rupd/tests/` and `crates/contracts`): `a25_create_workstream_returns_a_node_of_kind_workstream`, `a25_the_old_method_and_kind_do_not_exist`, `a25_a_stored_rail_with_kind_room_opens_as_workstreams_with_ids_and_children_intact`, `a25_the_next_write_stores_workstream`, `a25_the_default_door_question_names_the_workstream`, `a25_a_stored_order_keeps_its_text`, and a generated-contract case that regenerating changes nothing. Existing tests change only in name and word, and each keeps its assertions. Observer: `just check`, `loop/rules.sh vocab`, `bend proofs/messages/PROOF.bend` printing `ALL PROOFS CHECK` (`just proofs` once it exists), and a real-Daemon run (the U144 harness) that opens a Project whose Rail file was written with `"room"` and shows its Workstream, Door and children.

**U162 one add opens a Workstream; Agents and Terminals are added inside it.** Narrows U9, U32, U44, U62, U143 and U145; changes no App seam command and no Token. Decided: the Door starts as U62 already says (creating a Workstream selects it and starts its Door once, with no name field and no prompt), so the unit is opened and its first staff is the Door; and the Agent and Terminal adds stay visible only inside a Workstream, which keeps P1 (direct access to any Agent) through the adds below and through `⌘N` and `⌘T`. Given an open Project, then:
- **One entry.** The Rail's pinned line holds exactly one add, `+ new Workstream`. It does what `+ room` did (U9, U62) with the method of A25: one `rail.createWorkstream {name: "workstream", parent: null}`, select the returned row once `rail.tree` has it, one `rail.startDoor {id}`. No `+ agent` or `+ room` is in the pinned line, in the Rail's other elements, or anywhere outside a Workstream. The pinned line stays at the Rail's bottom edge as U32 and U44 say, now with the one add.
- **Empty.** U143's centre says `no Workstream yet` with one button, `new Workstream`, which runs the same path and the same pending, disabled and failure rules (`creating Workstream…`). With no Workstream on the Rail, the Rail itself offers only `+ new Workstream`: a new user sees one add action, named Workstream.
- **Inside a Workstream.** While the selection resolves to a Workstream (U145's resolution: a Workstream row, or a row under one), that Workstream's group holds, after its last child and indented as a child, one line `+ agent`. It is one native button, not a Rail row: it has no selection, no drag and no Live line, `railStep` (U41) skips it, and Tab reaches each button. `+ agent` runs `agent.spawn` with that Workstream as its parent and U32's `✕ <message>` line on failure, and selects its new row. _`+ terminal` is gone (U165, `scenarios/quick-terminal.md`, #391): `⌘T` opens a Terminal bubble._ A collapsed Workstream (U8) shows no line. A Workstream that is not the resolved one shows no line, so the Rail never holds more than one.
- **Direct access.** `⌘N` keeps U32's chord and its parent rule (the selected Workstream, else `null`), and `⌘T` is U165's; an Agent at the Project root, a root Terminal and every existing row stay reachable and selectable. A stopped Door does not hide the line (U143); policy, proved by the `door-stopped` capture.
- **The words.** No visible text, `title`, `aria-label` or placeholder in the App contains `Room` or `room` as a word, on any seed.

**U163 Agents come before Terminals wherever both appear.** Rule: a Terminal is never the first call to action, and an Agent is never listed after a Terminal that is listed with it. Narrows U32, U33 and U56; changes no contract and no Token. Given the App, then in every control, line, menu, shortcut list, tooltip, empty state and document in which both kinds are named or offered, the Agent comes first: the inside line of U162 (`+ agent` alone since #391), `⌘N` before `⌘T` wherever the chords are listed (U32; U33's `⇧⌘N` stays beside `⌘N`), `GLOSSARY.md`'s and `docs/wireframes.md`'s wording and wireframe lines, and any `rup` help that names both. The Rail's tree order is the user's `order` (A6) and is untouched: this scenario orders offers, never rows. Where a surface offers a Terminal with no Agent beside it (`⌘T`'s Terminal bubble, U165), it is not the first thing offered on an empty Project: U162's `+ new Workstream` is.

Tests (`u163_`, Vitest in `apps/desktop/src/rail/` and `apps/desktop/src/keys/`): `u163_the_inside_line_lists_agent_alone`, `u163_the_chord_list_names_cmd_n_before_cmd_t`, `u163_on_an_empty_project_the_first_tab_stop_in_the_rail_is_new_workstream`, and a document case that `docs/wireframes.md`'s add lines name `+ agent` before `+ terminal`. Observer: the `artifacts/ux/U162/` captures show the order. Moves: D2, D6.
