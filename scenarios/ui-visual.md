# UI: the visual system (U130 to U137)

Module: `apps/desktop` (the webview). Ids: U130–U137.

Webview only. No App command, no Daemon method and nothing under `contracts/` changes. `docs/design-system.md` holds the Tokens, the six rules and the checks D1 to D10; each scenario below is the test that proves some of them, and its test name starts with its id. Every check runs on every visible element, in light and in dark, and fails when it cannot measure. `docs/motion.md` is unchanged.

These scenarios narrow U4 (ink): its Glyph tones for `working`, `idle` and `done`, its hex values and its `--light` and `--lightest` colours are replaced by `docs/design-system.md`. Its contrast ratios stay, as D5. Any `u4_`, `u5_` or `u20_` test that asserts a replaced colour is changed in the PR that replaces it, and the PR names each such test.

**U130 tokens.** Given every stylesheet under `apps/desktop/src` and every inline style a component sets, when a test reads them, then `tokens.css` is the only file with a colour, font-size, radius, box-shadow or duration literal; every other file reads `var(--…)` for those properties; and each Token in the table in `docs/design-system.md` is defined there, with a light and a dark value (a Token without both fails). xterm's options in `terminal/emulator.ts` are outside the literal scan; U131 moves its font size. Computed on a rendered Rail, Shelf, Drawer and pane, every colour, background, border-color, shadow, radius and duration is the value of a Token (D1). `loop/rules.sh tokens` (L41) repeats the literal scan in CI. Test: `u130_`. Built in slices, so no merged PR breaks the App in either scheme, and each says in its body which clauses of this scenario hold after it and `Moves: none` until D1 can pass: (1) `tokens.css` with each Token's light value, imported by `main.tsx` and the harness before `styles.css`; a Token that `styles.css` defines today moves out of it with the same value, so no name has two definitions (`u130_styles_css_does_not_shadow_a_shared_token`); the same PR adds `../tokens.css` to the stylesheet list in `u4_text_colour_rules_outside_glyph_tones_never_use_light_or_lightest`, makes `testing/contrast.ts` and `u4_the_word_hover_colour_is_text` resolve Tokens from `tokens.css`, and names both tests; the tests are one that each Token of the table is defined in `tokens.css` with a light value (`u130_every_token_has_the_tables_light_value_except_the_named_differences` asserts each Token's light value is the table's, except the differences it names in its `KNOWN_DIFFERENCES`; the table's values take effect where slice 2 moves a stylesheet, so `--text` becomes `#1d1d1f` in `styles.css`'s PR with the `u4_` tests that read it, and that PR deletes `--text` from `KNOWN_DIFFERENCES`; `testing/contrast.ts` reads `:root` from `tokens.css`) and a visible `it.todo` for the dark value; every stylesheet other than `styles.css` is untouched, and `u130_no_stylesheet_sets_a_dark_scheme_before_slice_3` reads each stylesheet's text and fails on `prefers-color-scheme` or `color-scheme`, which is what keeps the App light, and slice 3 deletes it. After slice 1 only "each Token is defined with a light value" holds: the literal scan, "every other file reads `var(--…)`" and D1 do not, and no test claims them. (2) One PR for each stylesheet that moves its literals to `var(--…)` and the inline styles of the components in its directory, and one more PR for the inline styles in directories with no stylesheet (`drawer/`, `pads/`, `todos/`, for example the Drawer's slide duration); the `PadDrawer` `color: var(--light)` is U50's, as U4 says. The Rail stylesheet's PR reads the selected-row band as `var(--selected)`, whose light value is U4's `rgba(0,0,0,0.05)` until a value that passes D5 replaces it (that PR sets `--selected`'s light value in `tokens.css` to `rgba(0,0,0,0.05)`, adds `--selected` with that value to the `KNOWN_DIFFERENCES` of `u130_every_token_has_the_tables_light_value_except_the_named_differences` so the test stays green, and `testing/contrast.ts` resolves the band through `var(--selected)`; the PR that settles the table's value deletes the entry) (the table's `.07` gives `--grey` text about 4.34:1 on the band, below U4's 4.5:1, so an architect settles the table's value before slice 3). Each has the slice-1 tests green. The PR whose merge leaves no literal outside `tokens.css` (the `tokens` scan passes on its head) also adds L41's `tokens` step to `.github/workflows/loop.yml` with L41's tests, so the order of these PRs is free and the step lands exactly once; the literal scan holds from it (`u130_no_look_literal_outside_tokens_css`, added in that PR), "every other file reads `var(--…)`" once every slice-2 PR has merged, and D1 holds from slice 3. (3) The dark block with a dark value for every Token (`--light` and `--lightest` are gone, replaced as the preamble says), `color-scheme`, and the dark assertion turned from `it.todo` into a test, once every stylesheet reads Tokens and U50 has merged (it removes the `PadDrawer` read). Slice 3 itself changes every other read of `--light` and `--lightest`: the `light` and `lightest` Glyph tones go to the tone `docs/design-system.md` assigns their Kind, the `--lightest` borders to `--hairline`, and the spawn field's hover and pressed to `--hover` and `--selected`; it then deletes both definitions; the same PR runs U4's computed-colour contrast tests a second time with the dark block's values (each `u4_` contrast test also resolves Tokens from the dark `:root` of `tokens.css`: text 4.5:1 and Glyph tones 3:1 on the ground and on the dark band, `done` exempt, and U25's greyed Rail) and names them, so dark is tested from the PR that turns it on; U135's `u135_` later adds more contrast, reduced transparency and 700 by 800. Slice 3 replaces U4's colours, so its PR names each U4 Token it replaces and each `u4_`, `u5_` or `u20_` test it changes, and needs an architect's approval other than its author's (`AGENTS.md` rule 4). D1 and the clause "a light and a dark value" hold from slice 3, and D10 from U135.

**U131 type and space.** Given the same rendered screens, when a test reads computed style, then every font size is one of 11, 12, 13 or 15 px; every font family is `--font-ui` except the Terminal, a path, an id and code, which are `--font-mono`; and every margin, padding and gap is `0` or one of 4, 8, 12, 16, 24 or 32 px (D2). A Rail row is 28 px high at rest, hovered and selected (U46 still holds). So is the `✓ <n> done` fold line (U8): found at 15 px beside 28 px rows on `tree-40` at 252 px. Test: `u131_`.

**U132 colour and Kind.** Given a Rail with every Kind (seed `agents-10`) and a Rail with none of `error` and `needs-you`, when a test reads computed style, then each Glyph is the one `docs/design-system.md` assigns its Kind, in the tone it assigns; only `needs-you` and `error` rows are bold (Ink); every colour with saturation above 15% is `--red`, `--amber` or `--accent`; the second Rail draws no red and no amber (D3); and each row in the Rail, the Shelf and a Drawer shows one of the six Glyphs, so no Kind is drawn by colour alone (D4). Test: `u132_`.

**U133 click targets.** Given every element in the Rail, the Shelf, a Drawer, the header and the pane's pinned actions that is a click target (`docs/design-system.md`, "Click targets"), when a test drives it by `pointerenter`, `pointerdown` and `focus-visible`, then its hover style differs from its rest style in background or colour and its cursor is `pointer`; its pressed style differs from hover, takes effect at `pointerdown` and has `transition-duration: 0s`; its focus style is a 2 px `--accent` outline at 3:1 against its ground; and its hit area is at least 24 px high (D6, D7). `stop`, `close`, `promote`, `collapse` and `export .md` are buttons by this rule. A disabled one has `--grey` text, cursor `default` and `aria-disabled` (U25). Test: `u133_`.

**U134 surfaces and depth.** Given the main workspace with a Drawer open, when a test reads computed style, then the Rail and the Shelf use `--sunken`, the pane and the Drawer use `--ground`, no border is wider than 1 px or any colour but `--hairline`, only the Drawer has a `box-shadow` (`--shadow-drawer`), no `backdrop-filter` element has another inside it, and the Terminal's size does not change when the Drawer opens (U5) (D8). Test: `u134_`.

**U135 schemes.** Given `prefers-color-scheme: dark`, `prefers-contrast: more`, `prefers-reduced-transparency: reduce` and `prefers-reduced-motion: reduce`, each alone, when a test renders the main workspace, then in dark every Token takes its dark value; under more contrast every `--grey` text computes as `--text` and every `--hairline` as 40% opaque; under reduced transparency no element has a `backdrop-filter`; under reduced motion every duration but the instant changes is `0s` (D9); and in every case text keeps 4.5:1 and every Glyph tone and focus ring 3:1 against its own ground (`done` exempt, as U4 says) (D5). D1 to D9 hold in each, and at 700 by 800 (D10). Test: `u135_`.

**U137 one module measures the checks.** Given the App in the harness (U26), when `window.__checks()` is evaluated, then it returns an object from each id `D1` to `D10` to `{"status": "pass" | "fail", "value": …, "selector": …}` for what is on screen now, in the colour scheme and media the page is in, computed by the same module the `u130_` to `u135_` tests call, so a check has one implementation. A check it cannot measure returns `fail` with the `value` `"not measurable"`, never `pass`. It reads the page and changes nothing the user sees: the state it drives to read a hover, press or focus style is restored. Test: `u137_`, which also asserts that every id is present, that a stylesheet with a literal colour makes D1 `fail`, and that the object parses under the `checks.json` shape `loop/rules.sh delta` reads (L42).

**U136 the existing screens pass.** Given the seeds `first-run`, `agents-10`, `tree-40`, `daemon-exits` and `conflict` (U26), when D1 to D10 run on each, then every check passes. This is the visual pass's finish line: it merges when `u130_` to `u135_` pass on those seeds, and QA's baseline (`docs/design-system.md`, "Baseline protocol") shows each check `fixed` and none `regressed`. Test: `u136_`.
