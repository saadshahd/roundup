### U130 Token ownership and lint extension (D9)

Zero is unitless. The dimensional rule includes custom properties, function arguments, media queries and keyframes; it does not exempt a value because it is a fallback. Colour includes hex, named colours and numeric colour-function arguments; `currentColor` is inherited ink, not a literal colour. A colour function composed only from Tokens remains allowed. Existing U130 inline-style ownership still holds. Only the unit/colour ownership rules exempt `tokens.css`; importance and selector rules apply there too. No per-file allowlist, lint-disable comment or warning downgrade is permitted (policy).

### U133 press and row states extensions (D4, D7)

Given any enabled roundup control, when pointerdown or its native activation key begins a press, then colour, opacity or scale changes through a Token by the first subsequent animation frame; no wait for the action’s reply is allowed. A control with no background at rest gains none while hovered or pressed. A control already filled at rest may retain or change that ground. Hover remains ink-only. Release, cancellation and blur clear the transient press state; normal activation still calls its action exactly once. Disabled controls retain U25 and do not activate. Text-entry editing is not a control press: fields retain their caret and text-selection semantics (policy for paint/timing; planned behavioral test `u133_press_releases_and_activates_once` for activation and cancellation).

Given one selectable or draggable item row, when selected, keyboard-focused or dragged, then compare each state to the same plain row with the same Kind and content: exactly one changed cue is allowed, either text colour or one selected ground. A combined selected+focused+dragged row still has one cue, not one per flag. No added outline, border, shadow, weight, radius, offset or second wash. Selection uses the selected cue, focus on a selected row reuses it and dragging preserves it; Kind and failure Ink keep their independent meanings. A drop destination is not the dragged row. These clauses supersede any earlier dragged-row outline only for the row itself; they do not redesign drop placement or animate row moves (policy; rendered design critic observer).

Policy: press feedback and persistent selection are distinct. Prefer instant ink/opacity for frequently used controls and under reduced motion; this pass requires no scale tween, new animation engine or duration change. A later motion work order may choose scale while keeping the first-frame response and no-new-background rules. Behavioral observers use Ark’s existing controls and App seam. No synthetic input machinery is added to production to obtain a painted state.

### U134 materials, colours and depth extension (D10)

Given a Drawer, Shelf, floating menu, popover, dialog or Terminal Bubble, then replace `--shadow-drawer` and `--shadow-shelf` with a shared elevation recipe containing two shadow layers: a tight contact layer and a wider, softer ambient layer, plus a 0.5 CSS px ring Token. Each layer has light and dark values; the ambient blur radius exceeds the contact blur radius. The ring belongs to the floating surface edge, not descendants. Keep scroll shadows as scroll cues. Update every consumer, including U137’s shadow recognizer and U130’s Token-table observer; no alias keeps either old shadow Token alive (policy; design critic observer for appearance, existing `u130_every_token_has_a_dark_value` updated for the replacement Tokens).

Given either colour scheme, then App neutral colours and semantic red, amber and accent fallbacks resolve from the corresponding Radix light/dark scales; `--accent` follows the macOS system accent when available and changes with that preference. Preserve D5 in both schemes and increased contrast, including foreground on accent fills. Terminal ANSI and program-authored colours retain U3517’s exception. Shadows, scrims and alpha compositing are defined only in `tokens.css` (policy; rendered design critic observer, planned `u130_system_accent_updates_without_changing_kind` for preference delivery and fallback, without asserting exact colour literals).

Given a macOS App with Rail and Shelf visible, then both reveal native AppKit vibrancy beneath their neutral tint; the centre, Terminal output and floating panels remain opaque. Use the installed Tauri window-effects API/configuration before a direct `window-vibrancy` dependency. Transparent native window and transparent webview backing are required; `titleBarStyle: Overlay` alone does not supply them. Under reduced transparency, both regions become opaque Token grounds and native effects are disabled; no CSS blur imitates native material (policy; Mac observer for actual native effect, existing `u135_reduced_transparency_removes_every_backdrop_filter` retained for web fallback).

Policy: native implementation stays in desktop window setup and webview Tokens. If accent delivery needs an App command or contract, its implementation follows the Contract recipe with every caller; this specification invents no public identifier. No Daemon method, Message law or vendor setting changes. Native material never stacks beneath another translucent region or beneath Terminal pixels. Unsupported platforms use opaque Token grounds and do not claim native vibrancy.
