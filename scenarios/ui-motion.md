# UI: motion contract

Acceptance for #3790 and its dependent implementation. This specification changes no production effect, dependency, Token, Check implementation or performance baseline. U3010a–d below replace their previous clauses; U3010e onward retain their recorder obligations. Existing App/fake-App and U26 rendered observers remain the seams. No RPC, renderer, loop or permission change is authorized.

## Specification

**U3010a one Motion engine and one inventory.** Given the App's accepted surfaces, when the implementation is delivered, then every App-owned timed effect uses the vanilla `motion` package, with one small Solid integration owning shared motion cleanup and live preference selection; no `motion/react`, React migration, second animation scheduler, custom spring or custom FLIP engine (policy). Ark owns interactive semantics, existing drag machinery owns drag/mutations, and existing owners retain focus, content, drafts and business actions. Inventory every existing CSS transition/keyframe and programmatic effect; every effect has a surface/source/purpose/preset/exit/acceptance row in `docs/motion.md` or is deleted (policy). This includes the currently unlisted Order context width/fade, Todo comment entrance and tool-call fold, not just Drawer and Todo motion.

M1–M11 in `docs/motion.md`, heading **Motion requirements**, are the acceptance authority: #3790's referenced `docs/quality-target.md` does not exist on origin/main. Do not invent a citation to it (policy). Only transform and opacity interpolate. Layout takes its final geometry once and Motion animates the visual projection; no width/height/color/stroke-dashoffset animation, height keyframes or `transition: all`. Duration, delay, curve, scale and spring settings come from Tokens; scripts resolve the same source, converting milliseconds to seconds at the boundary (policy, source review and rendered observation, never copied-value tests).

Precedence (policy): M1 supersedes U156's animated keyboard swap; M2 adds scale to U133/U510 while U3528's no pressed background remains; M3 supersedes U2580a's pointer Bubble exemption and the Drawer/Shelf 180 ms CSS curve; M5/M7 replace U53/U156/U3770/U3770e structural/finishing timings; M9 permits a glyph-change crossfade while U446's five non-working Kinds remain still at rest; M10 replaces reduced-motion zeroes, including the Toast time-bar exception; M11 replaces U430/U371's interpolated-width exception with final-layout projection. U2579a is in `scenarios/ui.md`, heading **U2579a one easing Token**: Token ownership survives, its requirement that every effect use the single CSS cubic-bezier does not. Other action, identity, no-hover-movement, cancellation, permission and P3/P11 clauses remain.

Checks (policy): D1 (Tokens), D2 (type/spacing), D5 (contrast), D6 (immediate interaction), D7 (no pressed background), D9 (timing/reduced motion) and D10 (scheme/contrast), defined in `docs/design-system.md`, heading **The checks**, observed by `apps/desktop/src/testing/checks.ts`, function `runChecks`. The implementation updates D9's zero-only observer to accept the M10 fade and Motion-owned effects; no passing Check regresses. D2/D5/D6 pass on the densest seed with a refused action visible. Geometry, timing, continuity, exact label copy and appearance belong to the rendered observer/design critic (AGENTS rule 10); behavioral tests assert actions, roles, focus, identities and calls.

Library acceptance (policy): use Motion's public vanilla `animateLayout`, documented since 14.1.0, instead of assuming layout needs React or writing measured FLIP. `docs/motion.md`, heading **Library decision**, records registry/source evidence and the published-export probe. Before shipping, run the U3010c measured Solid integration probe for insertion, removal, nesting and interrupted reordering; an actual capability gap is recorded on the work Issue, investigated or repaired under rule 9, never hidden by a React dependency or a second engine. Motion does not supply vanilla AnimatePresence: existing Solid owners must retain inert exiting content until the current completion and cancel on disposal. No new generic animation DSL or parallel legacy interface (policy).

## Layers and controls

**U3010b pointer motion never delays input or changes ownership.** Given the existing Drawer, Shelf, Bubble, menus and popovers:

- Key-driven actions, including keyboard list moves, tab switches, Return/Space activation and Escape during pointer motion, reach final visibility/focus by the next frame with no timed effect (M1). Extend existing `u2580a_key_close_and_interrupted_slide_leave_no_stale_content` and `u2580a_key_layers_open_and_focus_in_the_next_frame` in `apps/desktop/src/testing/u2580a_key_layers.test.tsx`; add `u3010b_keyboard_list_moves_and_tabs_act_once` only for uncovered action/call/focus behavior. Key-generated clicks do not start pointer press or entrance motion.
- Enabled pointer press scales its control to 0.97 over 100 ms and returns to 1 over 100 ms on release, cancellation, lost capture or blur (M2); it changes no background. Disabled controls do not scale or act. `u3010b_pointer_cancel_never_activates_a_control` checks action count only; scale/timing and release appearance are policy, judged by the rendered observer. Retain U510 disabled behavior and Ark interaction ownership.
- Pointer-open each Drawer, both Shelf modes and the Terminal Bubble. Reverse at 50% displacement, reopen at 50% of the return, then press Escape. M3 uses a Motion spring, duration target 0.25 s, bounce at most 0.1, retaining displayed position and velocity on each reverse (rendered policy). By next frame Escape closes it, removes exit content and restores the existing focus destination. A previous completion cannot remove newly opened content. Tests: `u3010b_latest_action_owns_layer_lifetime` and `u3010b_stale_completion_has_no_new_layer_effect`, extending the existing App-seam lifetime tests rather than duplicating their proof.
- App-rendered menus/popovers enter from their resolved trigger corner, scale 0.96→1 and opacity 0→1 in 150 ms; exit reverses scale/fade in 100 ms (M4, rendered policy). Ark still owns placement, focus containment, dismissal and keyboard activation. `u3010b_menu_interruption_keeps_ark_focus_and_action_ownership` checks focus, one activation and absence of actionable retained exits.
- With exact multiline drafts and a pending submit, reverse, switch Project and dispose mid-slide. Original text, Project/object/recipient and pending/newer revisions survive; closure immediately prevents new activation/submission in retained content. Dispatched work reconciles authoritatively; success consumes only its submitted revision and failure cannot overwrite a newer draft. Old completions cannot affect a new incarnation. Tests: `u3010b_exit_preserves_draft_and_submit_identity` and the stale-completion test above, extending unfinished-input coverage. Keep `u2580a_instant_actions_release_slide_and_fit_once` and `u430_terminal_gets_one_resize_per_slide`: one Terminal fit at settled reserved geometry, none for overlay, no per-frame fits. U430/U371 final centre geometry remains correct (rendered policy).
- Toggle reduced motion at the measured halfway point of opening, closing, reversal and the working arc. Translation/scale/rotation stop by next frame; final geometry and focus settle then, with only the 150 ms opacity fade permitted (M10). Turning it off replays nothing. Test `u3010b_preference_change_preserves_destination_and_focus` checks lifetime/focus/calls; the rendered observer checks the fade and absence of movement/loops.

Rendered observer (policy): `docs/motion.md`, heading **Rendered continuity protocol**, on dark 1512×950 `tree-40`, both Shelf modes, Bubble, menus/popovers and the densest refused-action screen; three normal-speed runs, quarter-speed inspection and reduced motion. Retain raw timestamps, positions, velocity, opacity, action sources and failures under `artifacts/ux/U3010b/` via `just capture U3010b`; no committed PNG/video. D2/D5/D6 pass, no Check regresses. Intervene/Review journey keyboard destinations remain; this work makes no new journey-completion or native-performance claim.

## Rows and feedback

**U3010c structure and feedback follow the selected identity.** Given final owner-grouped/nested Todo rows and other App rows under their existing mutation contracts:

- Pointer or incoming reorder, nest, add and remove animate through Motion layout for 200 ms (M5). The Solid probe commits final layout once, records distinct intermediate visual samples, interrupts at 50% and reaches authoritative final geometry without an endpoint restart (rendered policy). Existing keyboard mutations remain immediate under M1. Keep final order, owner, blockers, focus identity, draft revisions and scroll; reconcile refusals and do not let stale completion remove a replacement. Retain existing behavior tests: `u138_completing_a_middle_todo_focuses_the_next_open_row` in `apps/desktop/src/todos/u138_complete_focus.test.tsx`; `u155_alt_down_on_the_first_row_calls_reorder_before_the_third_and_focus_stays_on_it` in `u155_reorder.test.tsx`; `u3709_tab_nests_under_the_row_above_and_calls_set_blockers_once` and `u3711_a_refused_move_returns_the_row_and_shows_the_cause` in `u3708_nesting.test.tsx`; `u3718_a_drop_on_another_group_assigns_once` and `u3718_a_refused_assign_keeps_the_row_and_shows_its_cause` in `u3718_owner_drop.test.ts`; `u2773b_todos_late_failure_settles_original_project_only` and `u2773b_todos_discard_removes_only_selected_revision_across_reopen` in `u2773_unfinished_input.test.tsx`. Add no test that repeats their proof.
- During a drag the lifted row retains an accent outline, a dashed slot marks the landing place and other rows remain stationary (M6, policy/rendered observer; #3540 owns shared drag implementation). On committed drop, M5 applies. No new drag engine or mutation ownership is authorized; preserve cancellation/refusal and U112/U154 hover/wrapping behavior.
- A non-key completion (pointer acknowledgement or incoming authoritative finish) draws the Todo tick through transform/opacity, holds its row until 300 ms after the acknowledged completion, then folds it with M5's 200 ms projection (M7). Counts/data update at acknowledgement, not after animation; refusal shows its cause and keeps the row. Keyboard completion is immediate; reduced motion uses M10 with no 300 ms hold. Test `u3010c_completion_acknowledgement_precedes_visual_retirement` uses the existing fake App/clock to assert acknowledgement, current count, retained row lifetime and no action from an exit; extend existing U35/U138 tests for refusal/focus instead of repeating them. Tick drawing/timing is rendered policy. No old delayed ring/strike/bar/count cascade is retained unless represented by a conforming inventory row.
- Each copy control uses one shared success/failure helper: Order field copies, Pad draft, both ProjectTab copies, Reaction draft, import failure details, Rail draft, Todo history and context-menu link (source inventory in `docs/motion.md`, heading **Copy controls**). Each successful clipboard acknowledgement changes that control's own visible label to “Copied” for 1.5 s, then restores it (M8, exact copy rendered policy); another control's label never changes. Repeated success restarts that control's deadline. Rejection shows the existing failure line, no success state; older completion/timer cannot alter a replacement control or clear a newer failure. For native context-menu Copy Link, the menu closes normally before its action runs; use `linkEntries`' existing copied callback to show the same local feedback in the originating visible item's label for 1.5 s. Preserve U2694a/U2694c native menu ownership; do not reopen/retain the menu, replace it with a web menu or change the App seam. Test `u3010c_copy_feedback_belongs_to_the_acknowledged_control` covers success, repeated copy, independent controls and rejection through the fake App clipboard seam; `u3010c_copy_disposal_cancels_feedback` covers disposal/stale timer. Existing owners retain failure wording and clipboard payload/permissions. Other copy controls already providing success feedback migrate to the same helper (policy); no global success Toast or save/file success label is commissioned by M8.
- A Kind change crossfades its glyph in 150 ms; at rest only `working` rotates, the other five Kinds are still (M9, rendered policy). P3 still forbids routine progress alerts; no pulse, bell or new attention path. `u3010c_kind_change_does_not_raise_attention` checks attention calls only if existing U446/P3 coverage leaves this path unproved.

Rendered observer (policy): extend `apps/desktop/src/todos/u490a_browser.test.ts`'s rendered sampler for the Solid layout probe and interruption/refusal cases. Use `docs/motion.md`'s continuity protocol on densest nested `tree-40`, dark 1512×950, raw row tops, identities, scroll and opacity; include key swaps, drag hold/drop, completion, every listed copy caller (including failures) and all Kinds. Run `just capture U3010c`; retain normal/quarter-speed/reduced-motion PNGs/videos/traces under `artifacts/ux/U3010c/`, never commit images/videos. D2/D5/D6 pass; D1/D6/D7/D9/D10 regress none, using U3010a's Check definitions. Behavioral UI tests assert no geometry, duration, styles or exact copy; geometry and feel require the critic's verdict. Retired U3010c tests remain retired where existing coverage above proves the clause.

## Engine and performance

**U3010d the migration is complete and its cost is measured.** Given the final layer/row/feedback implementation, then one live reduced-motion source replaces all CSS/JS preference layers: one media query or one shared JS read/subscription, no `!important`. Every non-key movement becomes a 150 ms opacity fade; loops stop, final geometry/focus is immediate, completed motion never replays. Keys stay instant under M1 (M10, policy/source and rendered review; extend existing `u5_a_change_of_the_preference_is_followed` in `apps/desktop/src/app/reducedMotion.test.tsx` for the live switch and cleanup behavior only).

The production dependency is `motion`, vanilla imports only. Inventory/source review confirms no competing App CSS animations/transitions or direct WAAPI scheduler remains, and all animated properties are transform/opacity; native system animation and third-party editor/Terminal internals are outside the App-owned inventory. Report the before/after gzip byte count of the production entry and its eager import closure, identical build/compression settings and immutable commits, including Motion's incremental bytes and all moved chunks; total entry budget is 400 KB (400,000 bytes) from #3790. C10 is not a scenario heading on origin/main; do not cite it as an existing test. Also report lazy Motion chunks so a budget pass cannot conceal the engine cost (policy; built-artifact observation, no copied-budget test).

Preserve `docs/perf.md`, headings **Perf**, **What is enforced, and what is not**, **macOS baseline** and **Keystroke-to-render in WKWebView**: cold start <300 ms, keystroke-to-render <16 ms p95, ten idle Agents <150 MB extra RSS, existing 10% regression/noise/load rules, unchanged baselines. Run the existing qualified observers and read existing macOS CI evidence where applicable. An invalid/busy observer is retained as incomplete, never a pass (policy).

Actual renderer acceptance remains the **Native performance protocol** in `docs/motion.md`: final `tree-40` layers/Todos/ten-working-Glyph workloads, 64 KiB/s Terminal stream, ten-second warmup, 60-second samples, three alternating immutable base/head pairs, 30-second settled idle, same release-profile Mac/display/power state. Preserve raw scheduling/style/layout/paint and separately measured presentation stages, tools/settings, hashes, load, failures and cleanup. For P=1000/Hz, each run has scheduling p95 ≤1.5P, p99 ≤3P, at most 5% >1.5P and none >50 ms; paired median regression ≤10% with existing resolution floors. Apply the thresholds independently to measured presentation. Unsupported presentation is “unmeasured”, never zero/pass; native acceptance stays incomplete. `just perf` is Daemon work, `just perf-keystroke` Terminal echo, Chromium is not WKWebView (policy; required native observation, no unit timing test).

An automated observer reports one result per failure using the result table in `docs/motion.md`, **Native performance protocol**, with exits 0/1/2. Repair measured regressions without relaxing thresholds. No new report-consumer tests unless a real consumer has uncovered validity behavior (policy). Only the owner's explicit Mac instruction authorizes native window/input observation under `ROUNDUP_ALLOW_WINDOW`; this specification needs no native observation and claims no FPS result. U3010e onward retain recorder/runbook obligations; no loop machinery changes (policy).

## Native recorder

**U3010e a frame-interval recorder reports its stage and never a false pass.** Given the App built for the measurement (`VITE_ROUNDUP_PERF`, as K1 in `scenarios/perf.md`) and a workload named in `docs/motion.md`, heading **Native performance protocol** (Layers, Todos, ten working Glyphs, each under the 64 KiB/s Terminal stream), then:

- **Opt-in.** A normal build's bundle holds no trace of the recorder and no query or flag turns it on; a build made with `VITE_ROUNDUP_PERF` carries it. Test `u3010e_a_normal_build_carries_no_trace_of_the_recorder` and `u3010e_a_measurement_build_carries_it`, in `apps/desktop/src/perf/`, as `k1_opt_in.test.ts` does for the keystroke probe.
- **Samples.** After the ten-second warmup the recorder records each `requestAnimationFrame` interval of the 60-second sample, then the 30-second settled idle phase separately, and stops; it records nothing outside a named workload run. Test `u3010e_only_the_named_workload_window_is_sampled`, against a fake frame clock.
- **Report.** One file per run holds the workload name, fixed refresh Hz and P, the raw intervals in order, `n`, p50, p95, p99 and max by nearest rank, the count and rate of intervals above 1.5P, the timer resolution and the user agent. It names the frame stage measured: `scheduling` for `requestAnimationFrame` callbacks. Test `u3010e_the_report_holds_raw_intervals_and_nearest_rank_percentiles` and `u3010e_the_report_names_the_scheduling_stage`.
- **Unsupported.** Every stage the webview does not expose (style, layout, paint, compositor, presentation) is written as `"unmeasured"` with the reason, never as zero, an empty series or a pass; a report whose presentation stage is unmeasured carries no pass verdict and exits 2, as the `docs/motion.md` result table says. A run is invalid, retained and exits 2, when the frame clock stopped (an interval over 1 s), the window was hidden during the run, the sample ended early or the actions did not complete. A run that meets the thresholds of U3010d on a measured stage exits 0 for that stage only; a miss exits 1. Test `u3010e_an_unmeasured_stage_is_never_zero_or_a_pass` and `u3010e_a_stalled_or_hidden_run_is_invalid`.
- **Webview proof in CI.** The same report code runs in the existing Chromium harness on `tree-40` and produces a valid `scheduling` report with the presentation stage unmeasured; that report states it is a Chromium run and implies no WKWebView or displayed-frame result (policy; Linux/Chromium never substitutes for the Mac, per U3010d). Test `u3010e_the_chromium_harness_produces_a_valid_scheduling_report`.
- **No new permission.** The recorder starts no native window, OS input or process by itself; the Mac run uses `ROUNDUP_ALLOW_WINDOW=1` exactly as R12 in `scenarios/perf.md` and `docs/perf.md` require, and no agent, Reviewer, CI job or `just check` sets it (policy). Thresholds and the protocol in `docs/motion.md` stay as they are (policy).

**U3010f the owner's Mac run is one command and one paste.** Given the recorder of U3010e, then `docs/motion-native-runbook.md` gives the owner: the base and head commits to build, the single build-and-run command, the preconditions (AC power, Low Power Mode off, fixed display refresh, no concurrent build, window uncovered), where the report file lands, the exit codes 0, 1 and 2 with what each decides, and the exact text to paste back into #3013 (the report file's contents, the commits, the hardware, macOS and WebKit versions, display Hz and power state) (policy; a document, held by review). It claims no result and says that an unmeasured presentation stage leaves U3010d incomplete (policy).

**U3010g the frame recorder drives every U3010d workload.** Given the frame recorder (U3010e, `just perf-frames`) in a measurement build and a workload named `layers`, `todos` or `glyphs` in `docs/motion.md`, heading **Native performance protocol**, then:

- **Layers.** Every 2 s the run performs the protocol's Drawer and Shelf open, close and reopen sequence, alternating the two, and counts each performed action. Test `u3010g_layers_perform_the_drawer_and_shelf_sequence_every_two_seconds`, against a fake clock.
- **Todos.** Every 2 s the run performs one insertion, completion, done-fold toggle or reorder on the temporary Project's owner-grouped rows, one action per cycle in that order, and never leaves the list empty or completed away. Test `u3010g_todos_cycle_one_structural_action_every_two_seconds`.
- **Glyphs.** Before the sample starts the temporary Project holds ten working Glyphs (the `tree-40` fixture or ten working Terminals) under the one 64 KiB/s stream; the run is invalid when fewer than ten work. Test `u3010g_glyphs_need_ten_working_glyphs`.
- **Invalid stays invalid.** A workload whose actions did not all complete is invalid and exits 2, as the `docs/motion.md` result table says; a driver that cannot find its target counts as not completed, never as skipped. Test `u3010g_a_missing_target_leaves_the_run_invalid`.
- **Runbook.** `docs/motion-native-runbook.md` states as preconditions only what the command does, naming no workload as undriven (policy; a document, held by review).

Policy: no threshold, protocol or fixture changes; no Linux or Chromium result stands for the Mac numbers, and no native window is started by this scenario, which keeps `ROUNDUP_ALLOW_WINDOW` as `docs/perf.md` requires.
