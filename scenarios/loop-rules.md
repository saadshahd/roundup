# Loop rules

Module: `loop/rules.sh`, `loop/runs.sh`, `loop/retro.sh`, `loop/status.sh`, `loop/percy.sh` for L36, and the workflows each id names. Each id's cases are its `L<n>` tests in `loop/rules.test.sh`, `loop/merge-ready.test.sh`, `loop/percy.test.sh`, `loop/runs.test.sh`, `loop/retro.test.sh` and `loop/status.test.sh`.

| Exit | Means |
|---|---|
| 0 | holds |
| 1 | a rule is broken; stderr names it |
| 2 | bad input or usage, before any network call |
| 4 | `gh`, `git` or Jev failed, or `gh` exceeded `LOOP_GH_TIMEOUT` (20 s, fractions allowed); never read as a pass |

**L2 authorship.** `ci-trailers <pr>` passes when every commit carries `Author-Agent`, except a clean merge of `main` (L54) or a Copilot Autofix commit (L37), and no commit carries `Reviewed-by-Agent`: an approval is a verdict comment.

**L3 vocabulary.** `vocab` fails naming the word when a public Rust item, TS export or `contracts/` name holds a `GLOSSARY.md` _Avoid_ word, except under `crates/agents/claude_code/`.

**L23 build.** `build.yml` runs on each push to `main`, when a Builder run ends, each hour, and on dispatch. `runs.sh queue [max]` prints the `ready` and `unspecified` rows of L34 as `[{ids, file, slug, spec}]`, `spec` true for an unspecified row, at most `max` (4) less the Builder jobs (`build (…)`) still queued or running in any `build.yml` run, whose slugs `runs.sh builders` prints, skipping `scenarios/loop-*.md`, any row whose Claim, the branch `build/<slug>`, exists, and every row while the spend cap is reached (L83); `ready`, `git ls-remote` or `gh` failing exits 4, and a `max` that is no number exits 2. One queue job runs at a time, while earlier Builders keep running. `runs.sh claim` pushes each queued row's Claim at the `main` commit its rows came from and prints the rows it claimed; a branch that exists, which git reports as up to date or as a lease miss, is no Claim and its row is skipped; any other push result exits 4, a remote rejection included. The queue job dispatches one `build.yml` run per claimed row, so each Claim frees when its own run ends. That run is one Builder run on `macos-latest`, `ubuntu-latest` once L84 holds, with Sonnet and the Claude App's token, its prompt `.agents/builder.md` byte for byte and then the task (`runs.sh prompt`); an unspecified row's task asks for its spec, and for its code too when its `After` ids are done. Branching from `origin/main` fast-forwards the Claim. The Builder opens its PR as a draft and marks it ready when done, so `check` runs on that head and starts its review (L24). When the run ends, however it ends, `runs.sh unclaim` deletes its Claim if it has no PR, so a later queue builds that row again, and dispatches the queue; a `gh` or `git` failure exits 4. A dispatch with a PR number makes that PR's fix run (L82), one at a time per PR.

**L24 review.** `check` skips a draft's heads, so a Builder's red pushes hold no macOS runner, and runs on push to `main`. After `check` succeeds on a same-repo PR head, `runs.sh review-due <pr> <head>` exits 0 and prints the review run's task only when the PR is open at that head, is not a draft, has fewer than two rejects and has no verdict covering the head; else 1 naming why, and 4 on a `gh` failure. The task holds the body's `Scenarios:`, `Moves:` and `macOS:` lines, for `apps/desktop/src/`, `percy-review` on the head's Percy build (`percy.sh build <sha>`, waiting up to 10 minutes; none is a `NOTE`, a Percy API failure exits 4) against the scenarios' then-clauses and the `Moves:` checks, never the author's intent, and earlier verdicts; never the rest of the body. The review run is a Builder run, `.agents/builder.md` byte for byte and then the task, on Opus with a read-only token, answering `{verdict, findings}`. Its checkout of the head holds `main`'s `AGENTS.md`, `CLAUDE.md`, `.claude/`, `.agents/` and `loop/` in place of the head's, and no other `CLAUDE.md` or `AGENTS.md`, so no PR instructs its own review; it reads the PR's changes to them through `gh pr diff`. `runs.sh verdict` posts the answer as `VERDICT:`, `Head:`, the findings and `Reviewed-by-Agent: reviewer-<run id>`, drops any findings line that would forge one of those fields, dispatches merge-ready, and on a first reject starts a fix run (L82). A review run that ends with no verdict runs once more on that head, counted by one comment marked `<!-- review-rerun <head> -->`; a second with none stops the PR (L81).

**L27 retro.** `retro.yml` runs daily. `retro.sh due` exits 0 when 20 PRs merged since the last merged `retro/` PR (or since `loop/retro.sh` was committed) and no `retro/` PR is open, else 1 naming the count. `report` prints the Retro's input: merged PRs by kind (product touches code, loop touches loop machinery, the rest spec), Ledger runs, failures, turns and weighted tokens by role and model (input 1, cache write 1.25, cache read 0.1, output 5), weighted tokens per merged product PR, each reject of a product PR classified, each PR whose verdicts it could not read, and the five costliest runs. `classify` asks Jev (`jev-1.13.0`) two Choices per reject, its kind (real defect, wording, process rule) and its failure class, each time with the options in a fresh random order, and prints each choice with its confidence; a Jev failure or an answer without choices exits 4. The Retro opens one PR on a `retro/` branch; the user merges it.

**L29 ledger.** Every Builder, Reviewer and Retro run, finished or not, leaves the artifact `ledger-<run id>-<attempt>-<role>-<slug>-<weighted tokens>` holding one row `{role, subject, run, model, turns, exit, input, output, cache_write, cache_read}` written by `main`'s `retro.sh ledger`: from the run's `result` entry, else from its assistant messages, each message id once; a run that never started reads `no-run` with no tokens.

**L33 base.** `base <pr>` passes only when the PR's base is `main`.

**L34 ready.** `ready` prints each `## Work` row of `scenarios/*.md` as the first that holds of `done` (every id has a test), `in-flight #<pr>` (the leading id list in an open PR's title names an id; ids mentioned later in the description reserve no work; gh missing, failing or slower than `LOOP_GH_TIMEOUT` exits 4, and `--offline` skips gh), `unspecified` (an id has no heading, or the `After` cell holds anything but ids and `—`), `waiting` (an `After` id is not done) or `ready`.

**L36 Percy build.** On every PR touching `apps/desktop/src/`, and on each such push to `main` as Percy's baseline, the `visual` workflow's `percy` job (`percy.sh snapshot`) pins the build's commit to the PR head (`PERCY_COMMIT`), so L24 finds it by that SHA, serves `just harness` and runs `percy snapshot` on each seed of `.agents/data/harness.md` at 1280 px wide in Chrome only; it fails without `PERCY_TOKEN`, when the harness never answers, when Percy fails, or when its output has no build link, and writes that link to the job summary.

**L37 Copilot attribution.** A commit with no `Author-Agent` is authored by `copilot` when it has the Copilot Autofix `Co-authored-by` trailer, GitHub committed it, and its signature verifies against GitHub's web-flow key in `loop/web-flow.asc` and no other key; anything short of all three still needs `Author-Agent`, and `copilot` can never be the approver.

**L42 delta.** `delta <base-dir> <head-dir>` prints `<step> <id> fixed|regressed|still-failing|still-passing` per check and fails on any `regressed`; a check missing on one side is exit 2, never a pass.

**L46 merge-ready.** `merge-ready <pr>` prints `ready <head SHA>` only when the PR is open, not a draft and based on `main`; it touches nothing under `.github/` (the user merges those, since a PR's own workflow files decide its `check` and `rules`); `check` and `rules`, and `percy` for `apps/desktop/src/`, passed on that exact head, where a skipped run counts for nothing; every commit passes L2; fewer than two rejects stand (the second goes to the user); no reject blocks the head; a `VERDICT: approve` names the head, or an ancestor followed only by clean merges of `main` (L54); and a Code PR (`apps/`, `crates/`, `contracts/` or a Build file: `justfile`, a Cargo or pnpm manifest or lockfile, `rust-toolchain.toml`, `tsconfig.json`, `.oxlintrc.json`, `.fallowrc.json`, `.cargo/`, `tools/`) has a `Scenarios:` line. A `crates/desktop/` PR needs a `macOS:` line. A verdict counts only from `github-actions[bot]` or a commenter with write access, and never from an author.

**L54 clean merge.** `clean-merge <commit>` passes for a merge of `main` that conflicts nowhere and changes nothing beyond the trial merge; such a merge needs no `Author-Agent`, and an approve of its first parent still covers it, so a human can merge `main` in from GitHub.

**L78 auto-merge.** The merge-ready workflow disarms auto-merge on a PR touching `.github/` (L46) only when it is enabled, and fails closed on a read or disarm error.

**L79 needs the user.** When any line of `merge-ready <pr>`'s output holds a reason only the user clears (a PR touching `.github/`, a second reject, a missing `macOS:` line), the merge-ready workflow labels the PR `flag:needs-user`, assigns the repository owner and keeps one comment, marked `<!-- needs-user -->`, asking each reason as a question; a later run edits that comment only when its questions change. A run with none of those reasons takes the label and the owner off and leaves other labels and assignees alone. On a draft or closed PR only L81's reason counts.

**L80 status.** `status.yml` runs each hour, after each `build` and `review` run, and on dispatch. `status.sh issue` prints the number of the Status issue, the one open issue labelled `loop:status`; none or two exit 1. `status.sh page` prints its body: a marker, the time, and one table row each for Merged (PRs merged since 00:00 UTC and over 7 days), Tokens per merged product PR, Needs you (each open PR labelled `flag:needs-user`, with the questions of merge-ready's `<!-- needs-user -->` comment, L79), Blocked (each open PR, neither a draft nor labelled `flag:needs-user`, whose `merge-ready` status is not success and which nothing updated for 6 hours, with that status's description) and Watch (a `main` whose last push `check` did not succeed; a Claim with no open PR and no Builder job; failed, timed-out or unstarted `build`, `review` and `retro` runs of the last 24 hours, per workflow); an empty row reads `nothing`. Only `page --cost` counts tokens, by `retro.sh cost <since>` over 7 days with L27's weights and kinds; without it the page keeps the Tokens row of the previous body on stdin. The workflow writes the page as the issue's body, which notifies no one; at 08:03 UTC, or on dispatch with `daily`, it counts the tokens and also posts the page as one comment, which notifies the user the issue is assigned to. A `gh` or `git` failure exits 4 and leaves the body as it was.

**L81 stopped.** A Builder that stops on a question only the user can answer leaves its PR a draft with `Stopped: <the question>`. After a Builder or fix run ends, however it ends, `runs.sh stopped <branch>…` starts a fix run (L82) for each branch's open draft PR with no `Stopped:` line, a run cut off by its time or turns; a branch with no open PR, or a ready one, is left alone, and a `gh` failure exits 4. A spent retry, L82's fix runs or L24's rerun, makes its PR a draft with `Stopped: <what was tried>` and dispatches merge-ready. `merge-ready` fails a draft with a `Stopped:` line with `the Builder stopped: <why>`, and the merge-ready workflow asks it as `The Builder stopped (<why>): will you finish it, or close it and delete its branch to build it again?` (L79). On a draft or closed PR it asks nothing else, so a draft touching `.github/` pings no one until it is ready. Only jobs after the agent's job edit the PR or dispatch merge-ready; the agent's job gets no write scope.

**L82 fix runs.** A PR gets at most two fix runs, whatever starts them: a first reject (L24), `check` failing on the head of a ready PR from a `build/` branch, or a Builder run cut off before marking its PR ready (L81). `runs.sh fix <pr> <cause>` drops any `Stopped:` line, posts one comment marked `<!-- fix-run -->` naming the cause, and dispatches the fix run, its task holding the reject, the failed step's last 200 log lines or the cut-off run's link; with two such comments on the PR it starts none and stops the PR with `Stopped: two fix runs spent, then <cause>` (L81). A `gh` failure exits 4.

**L83 spend cap.** The repository variable `LOOP_DAILY_TOKENS` caps the weighted tokens (L27's weights) of every Ledger run of the last 24 hours. `retro.sh spent` prints that sum from one listing of the `ledger-*` artifacts, whose names carry each run's weighted tokens (L29), downloading none; `gh` failing exits 4, and the variable unset or no number exits 2, so nothing builds uncapped. While the sum is at or above the cap, `runs.sh queue` claims no row and the Status issue's Watch row says `spend cap reached: <sum> of <cap>`. Fix and review runs of open PRs still run, so no open PR waits on the cap.

**L84 Linux Builders.** Build and fix runs move to `ubuntu-latest` once a push to `main` passes `just check` there. `.github/actions/setup` installs Tauri's Linux packages (`libwebkit2gtk-4.1-dev`, `build-essential`, `libxdo-dev`, `libssl-dev`, `libayatana-appindicator3-dev`, `librsvg2-dev`) on Linux and GNU coreutils on macOS, and keys the Rust cache by the runner's OS. Each push to `main` also runs `just check` on `ubuntu-latest`, which saves the Linux cache; when it fails, the Status issue's Watch row says so. `check` on a PR stays on `macos-latest`, where the App ships, so no Linux green merges alone.

**L85 row time.** `status.sh page` adds a Row time row: the median and p90 hours, over the rows merged in the last 7 days, from a row's ready time to the merge of the PR naming its ids. A row's ready time is the later of the commit adding its ids' headings and the first commit adding a test of its last `After` id.

**L82 pipefail.** Every workflow under `.github/workflows/` sets `defaults.run.shell: bash`, so GitHub runs each `run` step under `bash -eo pipefail` and a failing command left of a pipe fails the step.

**L86 journey priority.** Given `.agents/data/journey.md` with one `Priority: ` line of space-separated scenario ids, `runs.sh queue` ranks eligible rows by their earliest listed id before taking the available slots. Unlisted rows keep their relative order after listed rows. A waiting row, open PR, Claim or occupied slot is never overridden. No journey file keeps the existing order; a present file without exactly one valid priority line exits 2 before any network call. Tests: `L86` in `loop/runs.test.sh`. The document's rendered and behavioral observers determine journey completion; L34's test-name bookkeeping does not. After a successful Builder matrix delivers at least one ready open PR from its claimed rows, `build.yml` dispatches another queue run; an empty queue, failed matrix or matrix delivering no ready PR does not dispatch, so idle ticks do not loop. Entry points remain `schedule` and `workflow_dispatch`: the Claude Action rejects `push` events.
