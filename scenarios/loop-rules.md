# Loop rules

Module: `loop/rules.sh`, `loop/runs.sh`, `loop/retro.sh`, `loop/status.sh`, `loop/percy.sh` for L36, and the workflows each id names. Each id's cases are its `L<n>` tests in `loop/rules.test.sh`, `loop/merge-ready.test.sh`, `loop/percy.test.sh`, `loop/runs.test.sh`, `loop/retro.test.sh` and `loop/status.test.sh`.

| Exit | Means |
|---|---|
| 0 | holds |
| 1 | a rule is broken; stderr names it |
| 2 | bad input or usage, before any network call |
| 4 | `gh`, `git` or Jev failed, or `gh` exceeded `LOOP_GH_TIMEOUT` (20 s, fractions allowed); never read as a pass |

**L2 authorship.** `ci-trailers <pr>` passes when every commit carries `Author-Agent`, except a clean merge of `main` (L54) or a Copilot Autofix commit (L37), and no commit carries `Reviewed-by-Agent`: an approval is a verdict comment.

**L3 vocabulary.** `vocab` fails naming the word when a public Rust item, TS export or `contracts/` name holds a `GLOSSARY.md` _Avoid_ word, except under `crates/agents/claude_code/`.

**L23 Builder runs.** `build.yml` claims ready Work rows on dispatch and every five minutes, with at most four cloud Builders across ticks. Each row runs in `build-row.yml`, and its own completion job releases an unused Claim, records an interrupted draft and dispatches L88 reconciliation without waiting for sibling rows. A dispatch with a PR number uses L88 to repair current conflicts, rejects, failed checks or interrupted drafts; stale dispatches start no agent. Claims remain atomic and an empty queue ends the chain.

**L24 review.** `check` skips a draft's heads, so a Builder's red pushes hold no macOS runner, and runs on push to `main`. After `check` succeeds on a same-repo PR head, `runs.sh review-due <pr> <head>` exits 0 and prints the review run's task only when the PR is open at that head, is not a draft, has no verdict covering the head; else 1 naming why, and 4 on a `gh` failure. The task holds the body's `Scenarios:`, `Moves:` and `macOS:` lines, for `apps/desktop/src/`, `percy-review` on the head's Percy build (`percy.sh build <sha>`, waiting up to 10 minutes; none is a `NOTE`, a Percy API failure exits 4) against the scenarios' then-clauses and the `Moves:` checks, never the author's intent, and earlier verdicts; never the rest of the body. The review run is a Builder run, `.agents/builder.md` byte for byte and then the task, on Opus with a read-only token, answering `{verdict, findings}`. Its checkout of the head holds `main`'s `AGENTS.md`, `CLAUDE.md`, `.claude/`, `.agents/` and `loop/` in place of the head's, and no other `CLAUDE.md` or `AGENTS.md`, so no PR instructs its own review; it reads the PR's changes to them through `gh pr diff`. `runs.sh verdict` posts the answer as `VERDICT:`, `Head:`, the findings and `Reviewed-by-Agent: reviewer-<run id>`, drops any findings line that would forge one of those fields, dispatches merge-ready, and on a first reject starts a fix run (L82). A review run that ends with no verdict runs once more on that head, counted by one comment marked `<!-- review-rerun <head> -->`; a second with none stops the PR (L81).

**L27 retro.** `retro.yml` runs daily. `retro.sh due` exits 0 when 20 PRs merged since the last merged `retro/` PR (or since `loop/retro.sh` was committed) and no `retro/` PR is open, else 1 naming the count. `report` prints the Retro's input: merged PRs by kind (product touches code, loop touches loop machinery, the rest spec), Ledger runs, failures, turns and weighted tokens by role and model (input 1, cache write 1.25, cache read 0.1, output 5), weighted tokens per merged product PR, each reject of a product PR classified, each PR whose verdicts it could not read, and the five costliest runs. `classify` asks Jev (`jev-1.13.0`) two Choices per reject, its kind (real defect, wording, process rule) and its failure class, each time with the options in a fresh random order, and prints each choice with its confidence; a Jev failure or an answer without choices exits 4. The Retro opens one PR on a `retro/` branch; it merges after independent review and required checks.

**L29 ledger.** Every Builder, Reviewer and Retro run, finished or not, leaves the artifact `ledger-<run id>-<attempt>-<role>-<slug>` holding one row `{role, subject, run, model, turns, exit, input, output, cache_write, cache_read, usage}` written by `main`'s `retro.sh ledger`: from the run's `result` entry, else from its assistant messages, each message id once; missing execution output reads `missing-output`, not proof the model never ran. `usage` is `recorded` when all token fields are present, `partial` when only some are present, and `unavailable` when none are present; actual zero is recorded.

**L33 base.** `base <pr>` passes only when the PR's base is `main`.

**L34 ready.** `ready` prints each `## Work` row of `scenarios/*.md` as the first that holds of `done` (every id has a test), `in-flight #<pr>` (the leading id list in an open PR's title names an id; ids mentioned later in the description reserve no work; gh missing, failing or slower than `LOOP_GH_TIMEOUT` exits 4, and `--offline` skips gh), `unspecified` (an id has no heading, or the `After` cell holds anything but ids and `—`), `waiting` (an `After` id is not done) or `ready`.

**L36 Percy build.** On every PR touching `apps/desktop/src/`, and on each such push to `main` as Percy's baseline, the `visual` workflow's `percy` job (`percy.sh snapshot`) pins the build's commit to the PR head (`PERCY_COMMIT`), so L24 finds it by that SHA, serves `just harness` and runs `percy snapshot` on each seed of `.agents/data/harness.md` at 1280 px wide in Chrome only; it fails without `PERCY_TOKEN`, when the harness never answers, when Percy fails, or when its output has no build link, and writes that link to the job summary.

**L37 Copilot attribution.** A commit with no `Author-Agent` is authored by `copilot` when it has the Copilot Autofix `Co-authored-by` trailer, GitHub committed it, and its signature verifies against GitHub's web-flow key in `loop/web-flow.asc` and no other key; anything short of all three still needs `Author-Agent`, and `copilot` can never be the approver.

**L42 delta.** `delta <base-dir> <head-dir>` prints `<step> <id> fixed|regressed|still-failing|still-passing` per check and fails on any `regressed`; a check missing on one side is exit 2, never a pass.

**L46 merge-ready.** `merge-ready <pr>` prints `ready <head SHA>` only when the PR is open, not a draft and based on `main`; `check` and `rules`, and `percy` for `apps/desktop/src/`, passed on that exact head, where a skipped run counts for nothing; every commit passes L2; no reject blocks the head; a `VERDICT: approve` names the head, or an ancestor followed only by clean merges of `main` (L54); and a Code or Loop PR has a `Scenarios:` line. A Code PR (`apps/`, `crates/`, `contracts/` or a Build file: `justfile`, a Cargo or pnpm manifest or lockfile, `rust-toolchain.toml`, `tsconfig.json`, `.oxlintrc.json`, `.fallowrc.json`, `.cargo/`, `tools/`) or Loop PR requires an independent current-head approval. A `crates/desktop/` PR needs a `macOS:` line. A verdict counts only from `github-actions[bot]` or a commenter with write access, and never from an author.

**L54 clean merge.** `clean-merge <commit>` passes for a merge of `main` that conflicts nowhere and changes nothing beyond the trial merge; such a merge needs no `Author-Agent`, and an approve of its first parent still covers it, so a human can merge `main` in from GitHub.

**L78 auto-merge.** Loop paths, including `.github/`, retain auto-merge and pass the same required checks plus independent current-head approval. A ready Loop-only PR is dispatched for review. Main’s instructions and skills are installed before the reviewer reads the proposed diff. Historical rejects never veto a corrected, independently approved head.

**L79 needs the user.** When any line of `merge-ready <pr>`'s output holds a reason only the user clears (a missing `macOS:` line), the merge-ready workflow labels the PR `flag:needs-user`, assigns the repository owner and keeps one comment, marked `<!-- needs-user -->`, asking each reason as a question; a later run edits that comment only when its questions change. A run with none of those reasons takes the label and the owner off and leaves other labels and assignees alone. On a draft or closed PR only L81's reason counts.

**L80 status.** `status.yml` runs every five minutes, on requested/in-progress/completed build, review, reconcile, QA, Retro and CI runs, and on dispatch. `status.sh issue` prints the number of the Status issue, the one open issue labelled `loop:status`; none or two exit 1. `status.sh page` prints its body: a marker, the time, and one table row each for Merged (PRs merged since 00:00 UTC and over 7 days), Tokens per merged product PR, Needs you (each open PR labelled `flag:needs-user`, with the questions of merge-ready's `<!-- needs-user -->` comment, L79), Blocked (each open PR, neither a draft nor labelled `flag:needs-user`, whose `merge-ready` status is not success and which nothing updated for 6 hours, with that status's description) Running / queued (active jobs with direct run links, and exhausted L88 attempts needing investigation) and Watch (a `main` whose last push `check` did not succeed; a Claim with no open PR and no Builder job; failed, timed-out or unstarted `build`, `review` and `retro` runs of the last 24 hours, per workflow); an empty row reads `nothing`. A missing Ledger displays unavailable, never zero. Small nonzero token totals remain visible. Recorded weighted tokens per product PR are a lower bound with the product-PR denominator, usage-record count and partial-coverage label; they exclude unrecorded runs and local sessions and are not a monetary bill. Only `page --cost` counts tokens, by `retro.sh cost <since>` over 7 days with L27's weights and kinds; without it the page keeps the Tokens row of the previous body on stdin. The workflow writes the page as the issue's body, which notifies no one; at 08:03 UTC, or on dispatch with `daily`, it counts the tokens and also posts the page as one comment, which notifies the user the issue is assigned to. A `gh` or `git` failure exits 4 and leaves the body as it was.

**L81 stopped.** A Builder that stops on a product question leaves a draft with `Stopped: <the question>`, its consequence and a recommendation; merge-ready asks that question (L79). After a Builder or fix run ends, `runs.sh stopped <branch>…` gives an open draft with no Stopped line a marker naming the interrupted run and dispatches merge-ready. That interrupted-run marker triggers L88 repair without a needs-user notification. Ready PRs and explicit questions are left alone. A spent repair budget is visible on Status with the last run link; it is an engineering investigation, not a new product question. GitHub failures exit 4.

**L82 fix runs.** A PR gets at most two started repair attempts across all causes and heads, recorded in its durable L88 Claim. A review preserves that repair count. Acquiring a Claim or failing setup before the model step starts consumes no repair attempt; failed setup waits at least five minutes before retrying. A fix task names the current reject, failed check, conflict or interrupted work. Two spent repairs start no more agents and appear on Status with the last run link. Earlier rejects do not veto a corrected head. The Claim, not comments or workflow success alone, owns and counts work.

**L83 spend cap.** The repository variable `LOOP_DAILY_TOKENS` caps the weighted tokens (L27's weights) of every Ledger run of the last 24 hours. `retro.sh spent` prints that sum from one listing of the `ledger-*` artifacts, whose names carry each run's weighted tokens (L29), downloading none; `gh` failing exits 4, and the variable unset or no number exits 2, so nothing builds uncapped. While the sum is at or above the cap, `runs.sh queue` claims no row and the Status issue's Watch row says `spend cap reached: <sum> of <cap>`. Fix and review runs of open PRs still run, so no open PR waits on the cap.

**L84 Linux Builders.** Build and fix runs move to `ubuntu-latest` once a push to `main` passes `just check` there. `.github/actions/setup` installs Tauri's Linux packages (`libwebkit2gtk-4.1-dev`, `build-essential`, `libxdo-dev`, `libssl-dev`, `libayatana-appindicator3-dev`, `librsvg2-dev`) on Linux and GNU coreutils on macOS, and keys the Rust cache by the runner's OS. Each push to `main` also runs `just check` on `ubuntu-latest`, which saves the Linux cache; when it fails, the Status issue's Watch row says so. `check` on a PR stays on `macos-latest`, where the App ships, so no Linux green merges alone.

**L85 row time.** `status.sh page` adds a Row time row: the median and p90 hours, over the rows merged in the last 7 days, from a row's ready time to the merge of the PR naming its ids. A row's ready time is the later of the commit adding its ids' headings and the first commit adding a test of its last `After` id.

**L82 pipefail.** Every workflow under `.github/workflows/` sets `defaults.run.shell: bash`, so GitHub runs each `run` step under `bash -eo pipefail` and a failing command left of a pipe fails the step.

**L86 journey priority.** Given `.agents/data/journey.md` with one `Priority: ` line of space-separated scenario ids, `runs.sh queue` ranks eligible rows by their earliest listed id before taking the available slots. Unlisted rows keep their relative order after listed rows. A waiting row, open PR, Claim or occupied slot is never overridden. No journey file keeps the existing order; a present file without exactly one valid priority line exits 2 before any network call. Tests: `L86` in `loop/runs.test.sh`. The document's rendered and behavioral observers determine journey completion; L34's test-name bookkeeping does not. Each Builder row has its own completion job, which releases an unused Claim and dispatches reconciliation even if that row failed or its PR already merged. A slow sibling does not delay refill; an empty queue starts no further Builder run. Entry points remain `schedule` and `workflow_dispatch`: the Claude Action rejects `push` events.

**L87 Codex Builder.** When `LOOP_CODEX_ENABLED=true`, one local Codex service adds a fifth Builder slot alongside the four GitHub Claude Builders. The service checks every five minutes, takes at most one eligible row through L23's queue and atomic Claim, and uses the same Builder prompt, journey priorities and PR gates. It asks L23 for a maximum of five, takes only its first eligible row, and waits if five GitHub Builders are already running. A local file lock prevents overlapping ticks; a recorded interrupted run is recovered before another Claim. The controller uses its own clean checkout of main and each Attempt its own clone; no user worktree changes. Login must be ChatGPT; API-key environment variables are removed from Codex. Each run ends within two hours, preserves its output and token counts locally, and succeeds only with a ready PR. A failure retains a PR or releases its Claim, retries at most twice per row and main SHA, and waits an hour between failures. API failures remain failures. An expired login, sleeping Mac or disabled service leaves Claude’s four slots running; disabling the variable prevents the next local Attempt. `LOOP_CODEX_STATUS` records its last timestamp, row and result on the Status issue; a running record expires after the run deadline. Tests: `loop/codex.test.sh`. Codex token counts are separate from the GitHub artifact Ledger and do not imply plan quota remaining.

**L88 prompt ownership and recovery.** A reconciliation runs on PR changes, main pushes, completed check/loop/build/review/visual runs and every five minutes. It dispatches review for an open ready same-repository Code or Loop PR with successful exact-head check, rules and (for UI) percy jobs and no current verdict; a merge conflict, current reject, failed check or interrupted draft on a `build/` branch dispatches repair. Other branches remain under their author’s control. Initial Builders and live local Codex Claims keep ownership until they finish. Every review and repair acquires the same durable per-PR Claim before invoking a model. A non-force ref update permits one owner; duplicate or stale dispatches invoke no agent. A completed owner permits at most two started repairs per PR across all causes and heads, and at most two review attempts per head; preflight/setup failures do not spend that budget. A stale reviewer posts no verdict on a newer head. Builder checkouts install a prepare-commit-msg hook from main that supplies a missing Author-Agent trailer and preserves existing attribution; rules failures are repaired before review, so metadata omissions do not spend review rejects. Earlier rejects do not block reviewing a corrected head; explicit product questions retain their existing gates. Conflicts merge main without force-pushing. Each Builder row reconciles at completion without waiting for its matrix siblings; reconciliation refills free build slots; empty queues do not continue the dispatch chain. Interrupted-run markers trigger repair without asking the user; explicit product questions retain the needs-user path. The Status issue links running and queued jobs and names exhausted attempts. Tests: `loop/dispatch.test.py`.

**L89 parallel CI.** `just check` remains the union of `check-rust` and `check-web`. CI runs those recipes concurrently, keeps Rust and the daemon smoke test on macOS, and runs web checks on Linux. The required `check` job succeeds only if both lanes succeed, and a draft invokes neither. Motivation: run 37831870531 spent about 105 seconds in Rust checks followed by 93 seconds in frontend tests. Tests: `loop/dispatch.test.py`; observer: both CI lanes and the final gate on the PR.
