# Terminals serve Agents and one quick command (X11, X12, U164, U165)

Module: `crates/terminal`, `crates/agents`, `crates/contracts`, `crates/rupd`, `crates/rup`, `contracts/generated/` and `apps/desktop`. Ids: X11, X12, U164, U165. Found by the user's report #391: Terminals should mostly hold what Agents run, so the user can watch it, and the user must still be able, at any point, to run one command and close it, which need not be a Terminal in the Rail. Decided here, where #391 left it to the build run: an Agent's Terminals sit inline under that Agent in the Rail (no new panel); the quick command is an overlay on `⌘T`; a quick command is kept as a Terminal only when the user asks; the Workstream's inside line no longer offers `+ terminal`. Blocked by #369 (`workstream.md`, which this file narrows and whose Workstream these ids use) and #389 (`orders.md`). Contract change (the Contract recipe of `.agents/builder.md`, rule 4): `agent.run`, `terminal.quick`, `terminal.closeQuick`, `rail.keepQuick`, `TerminalInfo.quick` and the MCP tool `agent_run`, with every caller in the same PR. New terms in `GLOSSARY.md`: **Run**, **Quick command**; **Terminal** is reworded.

A Run is a Terminal started by an Agent and shown under it. A Terminal whose Rail `parent` is an Agent is a Run; no new Rail field is added. `rail.move` and `rail.spawnTerminal` under an Agent stay `CONFLICT` (A6), so only `agent.run` makes one.

**X11 an Agent's Run.** Given an Agent `a` with a live Terminal, then:
- `agent.run {id: "a", command: ["/bin/sh","-c","echo hi"], cwd?: string}` starts a Terminal with X1's behaviour (cwd and env as X7; `cwd` defaults to the Agent's Worktree, else its cwd), adds a Rail node of Kind `terminal` last under `a`, emits `rail.changed`, and returns `{id, terminal_id}`. The node's name is `command[0]`'s basename. The Agent's own Status, Terminal and Attempt do not change, and the Run's exit never changes the Agent's Status (A3).
- An id that is not an Agent is `NOT_FOUND` when unknown and `INVALID_PARAMS` when a Workstream or Terminal; an empty `command` is `INVALID_PARAMS`; an Agent already holding 8 running Runs gets `CONFLICT`, and an exited Run frees its place.
- The MCP tool `agent_run` (M1's naming and schema rule) takes `command` and `cwd?` and runs under the calling Agent: the shim fills `id` with its own, so an Agent cannot start a Run under another. The call is a Touch by that Agent.
- A Run is a Terminal in every other way: `terminal.write`, `resize`, `kill`, `snapshot` and its events work (X1 to X10), and the user may type into it. Removing the Agent (`rail.remove`) kills and removes its Runs; killing a Run leaves its node, exited, as X6 says, until the user removes that node.
- A Rail stored by an earlier Daemon has no Run, and a stored Run reopens as an exited Terminal under its Agent (A8's rule for Terminals).

**X12 a quick command leaves nothing behind.** Given a Workstream `w`, then:
- `terminal.quick {workstream: "w", command: string}` starts the user's login shell as `$SHELL -l -c <command>` in the Workstream's cwd and returns `{id}`. It is a Terminal for X1 to X10, with `terminal.list` showing `quick: true` on it (a new `TerminalInfo.quick` field, `false` for all others). It adds no Rail node, emits no `rail.changed` and is in no Agent's or Workstream's membership. An empty or whitespace `command` is `INVALID_PARAMS`; an unknown `workstream` is `NOT_FOUND` and one that is not a Workstream is `INVALID_PARAMS` (as X11); more than 4 live quick Terminals is `CONFLICT`.
- `terminal.closeQuick {id}` kills it if running and forgets it: it is absent from `terminal.list`, and every later call on its id (`write`, `kill`, `snapshot`, a second `closeQuick`) is `NOT_FOUND`. It never leaves an exited Terminal behind (the difference from X6). On a Terminal that is not quick it is `INVALID_PARAMS` and the Terminal is untouched.
- `rail.keepQuick {id, parent}` turns a quick Terminal, running or exited, into a Rail node of Kind `terminal` last under Workstream `parent` (CONFLICT under an Agent or Terminal, as A6), with the same `terminal_id`, its screen and output offset intact; `terminal.list` then shows `quick: false`. A Terminal that is not quick is `INVALID_PARAMS`.
- A quick Terminal is closed, as `closeQuick` does, when the connection that opened it ends, and no quick Terminal survives a Daemon restart. A quick Terminal that was kept is unaffected by both.

**U164 Runs show under their Agent.** Narrows U32, U33 and U56 (Rail rows); changes no Token and no App seam command. Given an Agent row with Runs, then:
- Its Runs are its child rows, indented one step as a Workstream's children are (U6), in start order, named as X11 says, each with the Terminal's mark and its running or exited state (no Status, since a Terminal has none). The Agent's own row is unchanged except for a count `· <n>` after its name when it has Runs, in `--grey`, `<n>` the number of running Runs, hidden at zero.
- Runs are shown while the Agent's row is expanded; the Agent row is expanded by default while any Run is running and keeps the user's choice after that (the disclosure of a Group, U3 and U100). Selecting a Run opens its pane (U14) read as any Terminal: the user may type into it. A Run that exits stays, exited, until the user removes it (the Rail's remove, U56 and A16); a Run appearing never moves the selection or the focus.
- A Run never appears outside its Agent: not under the Workstream, not in the Switcher's list without its Agent's name (`<run> · <agent>`, U51), and the arrow keys walk Agent, then its Runs, then the next sibling (U31).

**U165 the quick command.** Narrows U32, U33, U47, U54, U56, U162, U163 and K3; adds no App seam command and no Token. Given a selected Workstream, or an Agent or Terminal inside one, then:
- `⌘T` (U32's chord rules: the webview handles it, Caps Lock does not change it, other modifiers do nothing) and nothing else opens the overlay, over the centre pane as the Switcher does (U51), with one focused text field with `aria-label="command"` and its hint `run a command · ⏎ run · ⌘⏎ keep · esc close`. The Rail and Shelf stay visible and are not resized. With nothing selected, or on an empty Project, `⌘T` does nothing and the overlay is not offered; `+ terminal` is gone from the Rail's pinned line, the inside line of U162 (it reads `+ agent` alone) and every menu; `⌘T` is named wherever U163's chord list names it (`⌘N` stays before it). U54's Help line `⌘T  new terminal` reads `⌘T  run a command`. K3 (`scenarios/perf.md`) starts on an empty Project, so it first presses `+ new Workstream` (U162: one `rail.createWorkstream`, the row selected, one `rail.startDoor`), then presses `⌘T`, types `cat` and presses `⌘⏎` (the perf `SHELL` script ignores its arguments), then selects the kept Terminal's row, in place of pressing `+ terminal`; the Door that U162 starts is not expected to run under the perf `SHELL` and K3 neither waits for it nor reads it (policy: a stopped Door does not hide the Workstream or `⌘T`, U162), `apps/desktop/src/perf/run.ts` changes in the same PR.
- `⏎` with a non-blank command calls `terminal.quick` for the selected Workstream (the Workstream above an Agent or Terminal) and shows its output in the overlay as a pane (U11's emulator); while the command runs the field is replaced by that pane, which takes the keys (the user may answer a prompt). `esc` closes: one call to `terminal.closeQuick`, then focus returns to what held it before (U40). Closing never leaves a Rail row, a count, a Switcher entry or an entry in `terminal.list`. When the command has exited, the pane stays readable with its exit code on one line (`exit <code>`) until closed; `⏎` then runs a new command in the field.
- `⌘⏎` keeps it: one call to `rail.keepQuick` under the Workstream, the overlay closes, the new Terminal row is selected and its pane opens with the same screen (U82 keeps the last screen). It works while the command runs and after it exited. A blank command, or a failed `terminal.quick`, shows the failure line (U80) in the overlay and runs nothing; `rail.keepQuick` failing keeps the overlay open with that line.
- The overlay opens once whatever the number of presses, is closed by `esc` on every path (U40), and while open the window's other chords (`⌘N`, `⌘K`, `⌘J`) do nothing. A webview reload (U103) while it is open closes the quick Terminal through the Daemon's connection rule of X12.
