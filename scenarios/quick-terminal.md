# Terminals float as bubbles over the centre pane (X11, X12, U164, U165)

Module: `crates/terminal`, `crates/agents`, `crates/contracts`, `crates/rupd`, `crates/rup`, `contracts/generated/` and `apps/desktop`. Ids: X11, X12, U164, U165. Found by the user's report #391: Terminals should mostly hold what Agents run, so the user can watch it, and the user must be able, at any point, to run a command in a Terminal and close it. Decided by the user (2026-10-10): a Terminal is a floating **bubble**, never a persisted Rail row like an Agent. Each live Terminal is a bubble over the centre pane that the user can move, resize, minimise to a chip, restore and make more or less transparent; a bubble ends with its Terminal; no Terminal is stored to come back after a restart; an Agent's Runs are bubbles tied to that Agent. Only Workstreams and Agents are Rail rows. Decided here, where #391 left them to the spec run (each is a numbered engineering call, changed only by a later scenario):

1. **Stored Terminal rows.** A Rail stored by an earlier Daemon may hold nodes of Kind `terminal`. `Agents::open` drops each one (its program is gone, A8 starts no program) and the next write stores none; no bubble replaces it.
2. **What persists.** A bubble's transparency persists per Project path in the webview's storage (as U100 keeps the Rail's layout). Its place, size and minimised state persist for the Daemon's life only: they are kept per Terminal id across a webview reload (U103), and forgotten at `daemon-exited` (U37) and for an id that `terminal.list` no longer holds.
3. **What shows.** A bubble shows while the selection resolves (U145's resolution) to its owner: an Agent's Runs show with that Agent, and a Workstream's Terminals show whenever the selection is that Workstream or any row under it. A bubble that is not shown keeps running and is not closed; the Agent's row carries the count of its running Runs.
4. **Keys.** `⌘T` opens a Terminal, `⌘B` and `⇧⌘B` cycle focus, `⌘.` minimises or restores the focused bubble and `⇧⌘⌫` closes it, all under U32's chord rules. `⇧⌘⌫` and not `⌘⌫`: the plain chord is the line-delete a shell user presses, and closing kills the program.
5. **Transparency against contrast.** Transparency fades only the bubble's ground; its text, header and controls stay opaque. The default is 8 %, the range 0 to 60 %.

The vocabulary: a **Terminal** is a shell or program roundup started with a screen the user can watch; a **bubble** is how the App shows one over the centre pane; a **Run** is a Terminal an Agent started; a Terminal the user opens is owned by a Workstream. Contract change (the Contract recipe of `.agents/builder.md`, rule 4), with every caller in the same PR: new `agent.run`, `terminal.open`, `terminal.close`, the event `terminal.changed`, `TerminalInfo.owner` and the MCP tool `agent_run`; removed `rail.spawnTerminal` (it answers `METHOD_NOT_FOUND` after) and `NodeKind::Terminal` (a node of Kind `"terminal"` is never produced). `terminal.spawn` (X1) stays as the raw, ownerless spawn; an ownerless Terminal has no bubble. No App seam command and no Token changes, but the surface rules of U134 and `docs/design-system.md` (lines 84, 98 to 105) narrow: a bubble is the one surface that casts no shadow, has a hairline border on every edge (the Drawer's has one edge) and may be translucent over the terminal, by its ground's opacity and never by `backdrop-filter`; D8 reads `only the Drawer has a shadow` with "(a bubble has none)" added, and the Rail, Shelf, pane and Drawer keep U134. Test: `u164_u134_allows_the_bubble_border_and_translucent_ground_and_nothing_else`. New and reworded terms in `GLOSSARY.md`: **Bubble**, **Run**, **Terminal**, **Rail**; **Quick command** goes. Replaces the earlier X11 (a Rail node under the Agent and a stored Run), X12 (`rail.keepQuick`), U164, U165 (`⌘⏎ keep`), A10's Rail node and `rail.spawnTerminal`, and U162's `+ terminal`; the clauses it changes in A6, A8, A10, A15, A16, A18, G2, F5, U9, U32, U33, U44, U47, U51, U54, U56, U81, U100, U143, U162, U163, K3 and `docs/wireframes.md` are edited in the same PR that adds this file, and they read as this file says. Blocked by #369 (`workstream.md`, whose Workstream these ids use) and #389 (`orders.md`).

**X11 an Agent's Run.** Given an Agent `a` with a live Terminal, then:
- `agent.run {id: "a", command: ["/bin/sh","-c","echo hi"], cwd?: string}` starts a Terminal with X1's behaviour (cwd and env as X7; `cwd` defaults to the Agent's Worktree, else its cwd), owned by `a`, emits `terminal.changed`, and returns `{terminal_id}`. `terminal.list` shows `owner: "a"` on it. It adds no Rail node and changes no Rail row, so `rail.changed` is not emitted. The Agent's own Status, Terminal and Attempt do not change, and the Run's exit never changes the Agent's Status (A3). Test: `x11_agent_run_starts_an_owned_terminal_and_adds_no_rail_node`, `x11_the_run_prints_and_the_agent_status_is_unchanged`, `x11_a_run_exit_never_changes_the_agent_status`.
- An id that is not an Agent is `NOT_FOUND` when unknown and `INVALID_PARAMS` when a Workstream; an empty `command` is `INVALID_PARAMS`. Test: `x11_an_unknown_workstream_or_empty_command_is_refused`.
- At most 8 Terminals are owned by one node, running or exited. A ninth `agent.run` (or `terminal.open`) forgets that owner's oldest exited Terminal and starts; when all 8 are running it is `CONFLICT` and starts nothing. Test: `x11_the_ninth_forgets_the_oldest_exited_and_conflicts_when_all_run`.
- The MCP tool `agent_run` (M1's naming and schema rule) takes `command` and `cwd?` and runs under the calling Agent: the shim fills `id` with its own, so an Agent cannot start a Run under another. The call is a Touch by that Agent. Test: `x11_agent_run_over_mcp_runs_under_the_caller`.
- A Run is a Terminal in every other way: `terminal.write`, `resize`, `kill`, `snapshot` and its events work (X1 to X10), and the user may type into its bubble. `rail.remove` of the Agent kills and forgets its Runs (`terminal.changed` once). Killing a Run leaves it, exited, in `terminal.list` (X6) until `terminal.close`. Test: `x11_remove_the_agent_forgets_its_runs`, `x11_a_killed_run_stays_exited_until_closed`.
- No Run survives a Daemon restart: a reopened Daemon's `terminal.list` holds none, and a Rail stored by an earlier Daemon opens without a node of Kind `terminal` (engineering call 1). Test: `x11_no_run_survives_a_restart`, `x11_a_stored_terminal_node_is_dropped_on_open`, `x11_rail_spawn_terminal_and_a_kind_terminal_no_longer_exist`.

Tests (`x11_`, Rust, in `crates/agents/tests/scenarios/` and `crates/rup/tests/`), the ones named above plus a generated-contract case that regenerating changes nothing. Observer: `just check`, `loop/rules.sh vocab`, and the real-Daemon run (the U144 harness) in which a fake `claude` calls `agent_run` and the Run appears in `terminal.list` with `owner` set and in no `rail.tree` node.

**X12 a Terminal the user opens, and closing any.** Given a Workstream `w`, then:
- `terminal.open {workstream: "w"}` starts the user's login shell (`$SHELL -l`, else `/bin/sh -l`) in the Project folder with X7's environment and no Worktree (G2), owned by `w`, and returns `{terminal_id}`. It adds no Rail node, emits `terminal.changed` and no `rail.changed`, and `terminal.list` shows `owner: "w"`. The caps and the ninth rule are X11's. An unknown `workstream` is `NOT_FOUND`; an id that is not a Workstream is `INVALID_PARAMS`. Test: `x12_open_starts_the_login_shell_owned_by_the_workstream_with_no_rail_node`, `x12_an_unknown_or_non_workstream_owner_is_refused`.
- `terminal.close {id}` kills it if running, forgets it and emits `terminal.changed`: it is absent from `terminal.list`, and every later call on its id (`write`, `kill`, `snapshot`, a second `close`) is `NOT_FOUND`. Unlike X6 it never leaves an exited Terminal behind. On a Terminal with no `owner` (an Agent's own, a Door's or one from `terminal.spawn`) it is `INVALID_PARAMS` and the Terminal is untouched. Test: `x12_close_kills_and_forgets_an_owned_terminal`, `x12_close_on_an_ownerless_terminal_is_refused_and_leaves_it`.
- `rail.remove` of the owning Workstream closes its Terminals as `terminal.close` does; A16's lifting of children does not touch them (they are not children). Test: `x12_removing_the_workstream_closes_its_terminals`.
- A webview or a connection ending closes nothing: the Terminals belong to the Daemon, and a reloaded webview shows them again from `terminal.list` (U103). A Daemon restart ends them all (X11). Test: `x12_a_connection_ending_closes_nothing`.

Tests (`x12_`, Rust, in `crates/terminal/tests/`, `crates/agents/tests/scenarios/` and `crates/rupd/tests/`): the ones named above plus a generated-contract case. Observer: `just check` and the real-Daemon run (the U144 harness) that opens a Terminal, writes `echo hi`, reads it back, closes it, and shows the id gone from `terminal.list`.

**U164 a bubble floats over the centre pane.** Narrows U5, U11, U13, U14, U51 and U56; changes no App seam command and no Token. Given an Agent or a Workstream with Terminals (X11, X12), then:
- Each shown Terminal (engineering call 3) is a bubble over the centre pane: a header, an emulator (U11) fitted to the body (U13: one `terminal.resize` per size change, at most once per frame), and a ground of `--ground` under the text and one `1px solid var(--hairline)` border on all four edges. It adds no Rail row, no Switcher entry (U51) and no menu (U56); the Rail holds Workstreams and Agents only. The pane under it does not resize (U5: its size observer reports nothing). Test: `u164_a_bubble_floats_over_the_pane_and_adds_no_rail_row_or_switcher_entry`, `u164_opening_a_bubble_does_not_resize_the_pane`.
- The header shows the Terminal's name (the basename of `command[0]`, else of `$SHELL`) and its state, `running` or `exit <code>`, then a transparency slider, `minimise` and `close`. The header is draggable by the pointer; a bubble resizes from its bottom-right corner; each is also reachable by the keyboard: with the header focused `←` `↑` `→` `↓` move it one space step and `⇧` with an arrow resizes it one step, and every control is a native element Tab reaches with a visible focus ring (U31). A bubble stays inside the centre pane and is never smaller than 24 columns by 6 rows or larger than the pane. Test: `u164_the_header_drags_and_the_corner_resizes_and_stay_inside_the_pane`, `u164_arrow_keys_on_the_header_move_and_shift_arrows_resize`, `u164_a_resize_calls_terminal_resize_once_per_frame`.
- `minimise` folds the bubble to a chip in a dock along the pane's bottom edge (name and a running or exited mark, a click target at least 24 px high, D6); activating the chip restores the bubble at its place and size. The Terminal runs on while minimised. A chip never resizes the pane. Test: `u164_minimise_folds_to_a_chip_and_restore_returns_the_same_place_and_size`.
- The slider (`aria-label="transparency"`, 0 to 60 %, step 5, default 8, its value text `8%`) fades only the ground: at `t` % the ground has opacity `100 - t` %, the text, header, slider, chip and focus ring stay opaque, and no `backdrop-filter` is used (D8). The value applies to every bubble, persists per Project path (engineering call 2), and a stored value the webview cannot read is the default. Test: `u164_transparency_fades_the_ground_only_and_persists_per_project`, `u164_an_unreadable_stored_transparency_is_the_default`.
- A bubble keeps its text at 4.5:1 (U87, `scenarios/ui-surfaces.md:21`, D5) at the default setting against the worst ground behind it: the check composites the bubble's `--ground` over the darkest and the lightest colour the pane can hold (the `--text` and `--ground` Tokens) and measures the text colour on each, in light and dark. Below the default the user chose it; the header, slider and chip keep 4.5:1 at every setting. Test: `u164_text_reads_at_4_5_to_1_at_the_default_over_ink_and_paper`, `u164_the_header_slider_and_chip_keep_4_5_to_1_at_every_setting`.
- A Run's bubble appears when `terminal.changed` brings it (U3), open and unfocused, and never moves the selection or the focus. A bubble whose Terminal exited keeps its screen (U82), shows `exit <code>` and stays until the user closes it or its owner is removed. `close` calls `terminal.close` once and the bubble goes at once; a failed call keeps the bubble and shows U80's failure line. A bubble opened by the user takes focus (U165). Test: `u164_a_new_run_bubble_never_moves_selection_or_focus`, `u164_an_exited_bubble_stays_readable_with_its_code_until_closed`, `u164_close_calls_terminal_close_once_and_a_failure_keeps_the_bubble`.
- Selection decides what shows (engineering call 3): selecting an Agent shows its Runs and its Workstream's Terminals; selecting another Agent swaps the Runs; selecting a row outside the Workstream shows that one's. A hidden bubble keeps running, keeps its place, size and minimised state, and returns as it was. The Agent's row gains a count `· <n>` after its name, in `--grey`, of its running Runs, hidden at zero; nothing else on the row changes. Test: `u164_selection_shows_the_agents_runs_and_the_workstreams_terminals`, `u164_a_hidden_bubble_returns_as_it_was`, `u164_the_agent_row_counts_running_runs_and_hides_zero`.
- A reload (U103) shows each bubble again from `terminal.list`, its screen from `terminal.snapshot`, at its stored place and size; an id not in `terminal.list` is ignored and `daemon-exited` clears the stored places (engineering call 2). After `daemon-exited` a bubble is read-only as the pane is (U25). Test: `u164_a_reload_restores_the_bubbles_from_the_list_and_snapshot`, `u164_daemon_exited_clears_places_and_makes_bubbles_read_only`.

Tests (`u164_`, Vitest against the fake App, in `apps/desktop/src/bubbles/`), the ones named above. Observer: the U26 harness, isolated agent-browser at 1280 by 800 and 700 by 800, light and dark, on a new seed `bubbles` (an Agent with one running and one exited Run, a Workstream with one Terminal, one bubble minimised) and its densest case (8 Runs, one with a 200-column line and one named with 60 characters), with the transparency at 8 % and 60 %; `window.__checks()` must not regress against `main` for D1, D2, D5, D6 and D8, and shows D5's reading at 8 % over both grounds; captures go to `artifacts/ux/U164/`. Moves: D2, D5, D6.

**U165 the keys for bubbles.** Narrows U32, U33, U41, U47, U54 and K3; adds no App seam command and no Token. Given a selection that resolves to a Workstream (U145), then:
- `⌘T` (U32's chord rules: the webview handles it, Caps Lock does not change it, other modifiers do nothing, a key repeat acts once) calls `terminal.open` for that Workstream, once, and the new bubble opens focused at the default place with its emulator taking the keys. With nothing selected, or on an empty Project, `⌘T` does nothing. It does nothing while a call is in flight or after `daemon-exited`, and a failed call shows U9's `✕ <message>` line (U80) and opens nothing. `+ terminal` is gone from the Rail's pinned line, the inside line of U162 (it reads `+ agent` alone) and every menu. Test: `u165_cmd_t_opens_a_focused_bubble_in_the_workstream_and_does_nothing_outside_one`, `u165_holding_cmd_t_opens_one_bubble`, `u165_a_failed_open_shows_the_failure_line_and_opens_nothing`, `u165_no_plus_terminal_is_in_the_pinned_line_the_inside_line_or_any_menu`.
- `⌘B` moves focus to the next shown bubble or chip in start order and, after the last, to the pane; `⇧⌘B` goes the other way. A chip takes focus and a bubble's emulator takes the keys. The chords never reach a Terminal. With nothing shown they do nothing. Test: `u165_cmd_b_cycles_bubbles_then_the_pane_and_shift_goes_back`.
- `⌘.` minimises the focused bubble to its chip, or restores the focused chip; with the focus elsewhere it does nothing. `⇧⌘⌫` closes the focused bubble or chip with one `terminal.close` and returns focus to what held it before the bubble took it (U40), else the pane. Neither is a key of the program inside. Test: `u165_cmd_dot_minimises_and_restores_the_focused_bubble`, `u165_shift_cmd_backspace_closes_with_one_call_and_returns_focus`.
- Every other key typed in a focused bubble goes to its Terminal (`terminal.write`), including `esc`, and none reaches the Rail or the pane. U54's Help keeps `⌘T  new terminal` after `⌘N` (U163) and gains, after it, `⌘B  next bubble`, `⌘.  minimise or restore the bubble` and `⇧⌘⌫  close the bubble`. Test: `u165_other_keys_reach_the_terminal_and_help_lists_the_bubble_chords`.
- K3 (`scenarios/perf.md`) starts on an empty Project, so it first presses `+ new Workstream` (U162: one `rail.createWorkstream`, the row selected, one `rail.startDoor`), then presses `⌘T`, then waits for the program's `ready` line in the focused bubble (the perf `SHELL` script ignores its arguments and prints `ready`), in place of pressing `+ terminal` and selecting a row; the Door that U162 starts is not expected to run under the perf `SHELL` and K3 neither waits for it nor reads it (policy). `apps/desktop/src/perf/run.ts` changes in the same PR. Test: `u165_k3_opens_its_terminal_with_cmd_t_after_new_workstream`.
