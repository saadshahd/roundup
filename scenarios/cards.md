# Permission Cards

A Claude Code permission prompt becomes a Card the user answers from the App. Read `docs/permission-cards.md`, ADR 0006 and the Card entry in `CONTEXT.md` first. Claude Code's hook reply is read from `spikes/hooks-permission/` (H1), never from memory. Tests run with a fake `claude` that calls the hook command in its `--settings` file the way Claude Code does (the payload on stdin, the reply read from stdout); no test needs the real one.

**H1 the reply is recorded from the real tool.** Given the installed `claude` and a throwaway directory, when the spike script runs one prompt that needs a permission with a `PermissionRequest` command hook that prints a fixed decision, then `spikes/hooks-permission/REPORT.md` and one `*.jsonl` per run state, from those runs: the payload fields the hook receives; the exact stdout that makes the tool run, and the exact stdout that stops it, with the message the deny shows if there is one; whether the dialog is drawn while the hook is still running; what happens to a running hook when the user answers the dialog in the Terminal first; the largest `timeout` the hook setting accepts; and what the tool does when the hook exits non-zero or prints nothing. Each finding is a line `finding <n>: <text>` and cites the `*.jsonl` that shows it, and the report names the `claude --version` it ran against. The scripts need a login and a network, so this is a spike and not part of `just check`; the tests of H2 to H9 replay its files. No other H scenario starts before it merges, because H3, H6, H7 and H9 take their exact strings from it.

**H2 a permission request opens one Card.** Given an Agent whose per-Agent settings run `rup permission <agent-id>` for `PermissionRequest` (H9), when the fake `claude` runs that command with the payload on stdin and it stays open, then the Daemon opens exactly one Card for the Agent: `card.list` returns `{id, agent, tool, args, opened_at}`, where `tool` is the payload's tool name and `args` is its tool input as text, cut at 2000 characters with a final `…` when longer, and one `card.opened` event carries the same Card. The Agent's Kind is `needs-you` with the label A1 gives, from that open Card and not from a Signal. A second request from the same Agent while a Card is open replaces the Card (a new `id`, `card.opened`, and the old Card gets `card.cleared` with outcome `replaced`), and the first `rup permission` exits 1 with `superseded` on stderr and nothing on stdout, so Claude Code falls back to its own dialog. The tests use `card.list`, the events and the exit code. Contract change (the committee approves it): `agent.permission {id, payload}` (called by `rup permission`; it returns when the Card is answered or cleared, with `{output}` for stdout or an error), `card.list` (no params, returns the open Cards), the events `card.opened` and `card.cleared`, and the `Card` type; see H3 for `card.answer`.

**H3 the user's answer goes through the hook.** Given an open Card, when the user calls `card.answer {id, answer}` with `allow` or `deny`, then `rup permission` prints on stdout exactly the reply `spikes/hooks-permission/` records for that answer, nothing else, and exits 0; the Card is gone from `card.list`; `card.cleared` carries outcome `allow` or `deny`; and the Agent's Kind leaves `needs-you` as A1 gives for a `PostToolUse` or a new prompt (no Kind of its own is set by the answer). `card.answer` is called as the user: an Actor of kind `user`. An unknown or already cleared `id` is `NOT_FOUND`; an `answer` that is neither word is `INVALID_PARAMS`. The reply text is built in `crates/agents/src/claude_code/` and `rup` prints it unchanged, so nothing outside that module names a vendor string. Contract change: `card.answer {id, answer}` returns `null`.

**H4 nothing answers a Card but the user.** Given an open Card, then each of these leaves it open and its `rup permission` still waiting: `card.answer` called by an Actor of kind `agent` or `ext` (error `FORBIDDEN`); a Signal or a `terminal.write` or an MCP tool call from any Agent, whatever its text says; and an hour of an injected clock passing. The `rup mcp` server lists no tool that answers or lists Cards. The Daemon never calls `card.answer` itself and has no setting that does (the test greps `crates/` for a second caller). A `deny` or `allow` exists only as the value of a `card.answer` from the user.

**H5 an open Card survives a webview reload.** Given an open Card and a client that disconnects (a reloaded webview) and a new client that connects and calls `card.list`, then it returns the same Card, with the same `id` and `opened_at`, and `card.answer` from the new client prints the reply on the still-waiting `rup permission`. The Daemon keeps Cards in memory only. Quitting the App ends the Daemon and every Agent with it (D1, S3), and with the Agent the hook that waits for the answer, so no Card can outlive the App and none is written to disk; a Daemon started by S5 holds no Card. The test replaces the client, not the Daemon, and a second test starts a new Daemon and finds `card.list` empty.

**H6 an Agent that ends clears its Cards.** Given an open Card, when its Agent's Terminal exits or `agent.stop` is called (A3, A7), then within the bound the test names the Card is cleared with outcome `agent-gone`, `card.cleared` is emitted once, `card.list` no longer has it, and the waiting `rup permission` exits 1 with `the Agent ended` on stderr and nothing on stdout.

**H7 an answer given elsewhere clears the Card.** Given an open Card, when the `rup permission` that opened it exits or its connection closes before any `card.answer` (the user answered the dialog in the Terminal and Claude Code ended the hook, as H1 records), then the Card is cleared with outcome `terminal` and `card.cleared` is emitted once; a later `card.answer` for it is `NOT_FOUND`. The test closes the connection from the fake `claude` side.

**H8 the hook fails loud and never allows.** Given `rup permission <agent-id>`, when `RUPD_SOCKET` is unset or no Daemon listens, the payload on stdin is not JSON, or the Daemon answers `NOT_FOUND` for the id, then it prints one line on stderr naming the cause, prints nothing on stdout, and exits 1, whichever it was; Claude Code then shows its own dialog as H1 records. A Daemon that stops answering is not waited on past the hook's own `timeout`; the command exits 1 with `rupd did not answer` when the connection closes. It never exits 2 and never prints a decision it did not receive from the Daemon. The tests run the built `rup` against each case.

**H9 the Agent's settings route the request.** Given `agent.spawn` (A4), when the Daemon writes the per-Agent settings, then `PermissionRequest` runs `<rup> permission <agent-id>` with the `timeout` H1 records as the largest accepted, every other event in A4's list still runs `rup signal <agent-id>` with the 5-second timeout, and a `PermissionRequest` payload arriving through `rup signal` or `agent.signal` is ignored and opens no Card. This amends A4 (the hook line), A1 and D2: for `PermissionRequest` the fake `claude` calls the hook for it, the client sees `needs-you` while it waits, and the status order of D2 holds once the test answers the Card with `card.answer`. Tests of A1, A4 and D2 named for that line are narrowed to it; the others are unchanged.
