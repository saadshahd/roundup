**U80 one failure line.** Given any `✕ <message>` the webview shows for a failed call (U2, U9, U14, U16, U19, U21, U32, U35, U56) or a failed write (U12), then it is one line: the mark `✕` and the message up to its first line break, cut with `…` when it is wider than its place, and the whole message, line breaks kept, is the line's `title`, so the last lines of a Daemon's stderr (S1) never grow the Rail or the centre. Every place shows it the same way: in Ink, with `role="alert"` so a screen reader announces it once, with class `ink` and no other class, in the same frame as the failure, with no fade, slide or shake (`docs/motion.md` has no row for it); under `prefers-reduced-motion` nothing differs. It never clears on a timer; each place's own rule clears it (U9 and U35: the next click). Two failures in one place show the newer one only. It narrows the tests that assert the message text of these lines, which must now also pass with a message of three lines: `u2_a_failed_open_project_shows_the_message_in_ink_in_place_of_the_prompt`, `u2_a_failed_open_project_is_the_only_ink_in_the_window`, `u2_a_failed_chooser_shows_the_message_in_ink`, `u3_a_failed_rail_refetch_shows_the_message_in_ink_in_the_centre`, `u9_a_failed_call_shows_one_ink_line_until_the_next_click`, `u9_the_failure_line_sits_above_the_actions`, `u32_a_failed_chord_spawn_shows_the_error_line`, `u12_a_failed_write_shows_its_message`, `u16_a_failed_create_shows_the_message_in_place_of_the_field`, `u21_an_export_error_shows_the_message_in_the_drawer`, `u35_a_failed_complete_shows_its_message_in_place_of_the_second_line`, `u14_a_failed_stop_shows_its_message` and `u14_an_error_line_never_changes_the_height_of_the_slot_that_holds_it`; their assertions on text and class stay as written. **U3704 state rides with the name, apart from the actions.** _Amended only as listed by U3789e (`ui-shelf.md`); U3789a–d govern those replacement clauses._ Rule: a *state* tells what a thing is doing (a Kind glyph, the needs-you count, the folded Agents' glyphs, a plain Terminal tab's unseen-output dot); an *action* is what the user can do to it (`+ Agent`, clear, Retry, close, minimise, Collapse). State sits beside the name; actions group at the trailing edge, apart from state; state never looks or behaves like a control. Narrows every earlier scenario that places a state in a row's trailing group (the Workstream's Door glyph in `.row-tail`, U2340d's tab bar, U164's Bubble bar); their other clauses stand. Given the U26 seeds `tree-40`, `agents-10`, `door-stopped`, `tabs-8` and `bubbles` at 1512×950, light and dark for behavioral observers and dark only for captures and critic Check readings (U3725), with a Rail row of every Kind, a Workstream collapsed and expanded, a failed Door, the Shelf, the Terminal tab bar, the Bubble bar and the switcher open, then for every row, tab, bar and entry holding a state, in rest, hover and focus:

1. *Marked.* Every non-decorative `KindGlyph`, every `.ink-count` and every `.folded-agents` carries `data-state`; the test finds states only by that attribute and fails a surface where it finds none. A decorative glyph (`decorative`) is not a state and needs no mark.
2. *With its name.* No action's box lies between a state's box and its name's, and the horizontal gap from the name's box to the state's is at most `var(--space-2)`.
3. *Apart.* A state's distance to the nearest action in that row is at least twice the gap between two adjacent actions in the same row (the row's own spacing when it has one action), and at least `var(--space-3)`.
4. *Actions trail.* Every action's box lies right of every state's box. Two exceptions: the leading disclosure chevron, and a native tick box whose value is the state. A Workstream's own state sits after its chevron, before its name, in the column its Agents' states take (same left edge, same size), so a Workstream's state and name line up with those of its Agents. A Workstream's states (its Kind glyph, the folded Agents' glyphs, the needs-you count) are on screen at rest, on hover and on focus, each at one position; hover and focus show or hide only its actions, whose room stays reserved at rest on a Workstream row, the only row with states after its name (hidden, out of the Tab order, not clickable; an Agent row's hidden actions take no room, as U426 says), no wider than the visible actions need, so a name is cut at the same place in every condition and a name that fits beside its states reads in full at rest. A Workstream's actions are icon-only 24 px buttons: the add is a `+` whose accessible name is `Add Agent` (U378's `+ Agent` label goes).
5. *Never a control.* A state has no `button` role, no tab stop (`tabindex` absent or `-1`, and not a button, link or input), computed `cursor` other than `pointer`, an unchanged `background-color` on hover, and a box whose width and height differ from the row's icon buttons' (24 px hit area) so a state never reads as one.
6. *Never swaps.* On hover and on focus of the row, tab or bar, every state's box keeps its position and size and stays visible (`display` not `none`, `visibility` visible, `opacity` above 0, no `clip`); this holds for a Workstream's Kind glyph, folded Agents' glyphs and needs-you count too, measured by the left edge of each box.

It forces: the Workstream's Door glyph moves from `.row-tail` to right after the chevron and before the name, in its Agents' glyph column (`⌄ ○ workstream …… + Agent ⌫`); the folded Agents' glyphs and the needs-you count sit beside the name and stay visible while the row's actions show, the name giving way to both (they hid before; the Pads control, an action, still yields to the row's actions); a failed Door shows `✕` beside the name and Retry stays an action to the right; a Terminal tab's unseen-output dot never turns into its `×` on hover or focus, and the `×` is an action at the tab's trailing edge; the Bubble bar holds no status at all. Every Rail row's name is `--text-row` (14 px, the owner's addition of 2026-10-18, a Token in `docs/design-system.md`) with a line height of 1.15 (1 clips descenders under the ellipsis) at rest and on hover, so no name changes size on hover. No other Token, App seam command or contract changes (policy: only Tokens give look values, `var(--space-2)` and `var(--space-3)` as they are); Ink and U80's rules are unchanged.

*A plain Terminal shows no state, only unseen output (the owner's order of 2026-10-18).* A plain Terminal (a shell opened with `+ Terminal` or ⌘T, shown as a Bubble and a tab; not an Agent's or a Door's) has no state glyph: not on its tab, not on its Bubble's bar, nowhere else, because roundup cannot read a shell's state (it always read as running, in the accent). An Agent keeps its Kind glyph in the Rail as before. Instead the tab shows a small static dot, `data-state`, right after the name, in `--grey`, when the Terminal has produced output since the user last viewed it: its Bubble was folded or its owner was not selected when the bytes came. Viewing it (its Bubble open) clears the dot. The dot has no animation, never the accent, amber or red, is never a control, and checks 5 and 6 hold for it. A Terminal that has exited shows nothing either. The webview learns of output from a watch on `terminal.output` that ends at the first byte, so no Daemon method or contract changes.
