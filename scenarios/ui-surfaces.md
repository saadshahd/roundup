# UI surfaces

What the webview shows when something fails, takes a moment, has ended or has no room. Ids U80 to U85. It adds to `ui.md` and changes none of it; the empty states (U38), first run (U2, U52), Daemon gone and reopen (U25, U37), a removal that fails (U56) and an exited Terminal that takes no input (U12) are already specified there and are not repeated. Tests run in Vitest with jsdom against the fake App seam, with the injected clock and emulator (`ui.md` header), except U85's window size, which a Rust test reads. Every rule here is a value a test can read: a string, a token, a duration, a call that is or is not made. Ink stays what `CONTEXT.md` says: bold plus colour for `error` and `needs-you` only, and text keeps U4's 4.5:1.

**U80 one failure line.** Given any `✕ <message>` the webview shows for a failed call (U2, U9, U16, U19, U21, U35, U56, a failed write in U12), then it is one line: the mark `✕` and the message up to its first line break, cut with `…` when it is wider than its place, and the whole message, line breaks kept, is the line's `title`, so the last lines of a Daemon's stderr (S1) never grow the Rail or the centre. It is the same element everywhere, in Ink, with `role="alert"` so a screen reader announces it once; it appears in the same frame as the failure, with no fade, slide or shake (`docs/motion.md` has no row for it), and under `prefers-reduced-motion` nothing differs. It never clears on a timer; each place's own rule clears it (U9 and U35: the next click). Two failures in one place show the newer one only. Owns `apps/desktop/src/ink/ErrorLine.tsx` and its test. No existing test is narrowed: `u2_a_failed_open_project_shows_the_message_in_ink_in_place_of_the_prompt`, `u2_a_failed_open_project_is_the_only_ink_in_the_window`, `u13_a_failed_rail_refetch_line_sits_in_the_panes_fixed_slot` and `u12_a_failed_write_shows_its_message` keep passing as written. May stack on anything; after U52 if both are merging, since U52 adds a second `✕` line to the first-run centre.

**U81 a spawn that takes a moment.** Given an open Project, when `agent.spawn`, `rail.spawnTerminal` or `rail.createGroup` has been in flight for 500 ms of the injected clock, then a light line (`--grey`, never Ink) takes the place above `+ agent  + terminal  + group` where U9's failure line sits, reading `starting agent…`, `starting terminal…` or `adding group…`. A call that settles in under 500 ms shows nothing, so a fast spawn never flashes. While the call is in flight the pressed word has `aria-busy="true"`, and the three words keep their place and width; no spinner, no pulse and no movement is added (`docs/motion.md`: no spinner). The line goes in the same frame the call settles: on success it is gone and the new row is selected (U9, U47); on failure it is replaced by U9's `✕ <message>`; never both. The same line serves the prompt field (U33) when Enter has called `agent.spawn`, and the field keeps its text as U33 says. Owns `apps/desktop/src/rail/pending/**` and one mount line in `Rail.tsx`; after U33 and U56, which also own `Rail.tsx`. `u32_a_second_chord_while_a_spawn_is_in_flight_calls_nothing` and the `u9_` failure-line tests keep passing as written.

**U82 the last screen outlives the program.** Given a selected Agent or Terminal whose program exits (`terminal.exited`, so Kind `error` or `done` by A3, or an exited Terminal), then its pane keeps the screen it had: the emulator for that Terminal is not disposed, cleared or reset, its scrollback (U34) stays scrollable and selectable, and `terminal.output` that arrived before the exit is still all there after selecting another row and back. The cursor is not drawn once the program has exited. Nothing is added to the pane: no `✕`, no header (U57) and no message, because how it ended already reads in the Rail (U7: `exited <code>`, `exited by signal`, with Ink for `error`). The pane sends no `terminal.write` and no `terminal.resize` for it from then on (U12, U13). Owns `apps/desktop/src/terminal/**`; after U57 and U59. `u12_an_exited_terminal_takes_no_input` and `u12_a_terminal_that_exits_while_shown_stops_taking_input` keep passing as written.

**U83 a node from an earlier run has no output to show.** Given a Rail node of kind Agent or Terminal whose `terminal_id` is `null` (A8, A12: an earlier Daemon run's Agent comes back `done`, its Terminal gone), when the user selects it, then the pane reads `no output kept from an earlier run`, centred, in `--grey`, never in Ink, since nothing failed. The pane makes no `terminal.write`, no `terminal.resize` and no emulator for it, and the Rail row reads as U6 and U7 say.  A node with a `terminal_id` never shows this line, even before any output has arrived. This narrows U57's "the pane shows only the terminal" for a node that has no Terminal, as U38 narrows it for no selection. Owns `apps/desktop/src/terminal/**`; after U57 and U38. `u14_with_nothing_selected_the_pane_is_empty` and its U38 successor are unchanged.

**U84 the cursor and the selection stay calm.** Given any selected Terminal (U59), then the emulator is built with a cursor that does not blink, and with the cursor drawn as an outline, not a block, whenever the pane does not hold keyboard focus, as when a Drawer holds it (U40) or the Rail does (U41). The selection's background is `--lightest` and its foreground `--text`, so selected text keeps at least 4.5:1 (U4) whatever ANSI colour it was printed in; the test computes the ratio from the two tokens. No token is added or changed. The options are asserted on what the injected emulator was built with, as U34 asserts its scrollback bound. Owns `apps/desktop/src/terminal/**`; after U59, which sets the cursor's colour and the palette, and keeps every one of its clauses.

**U85 the smallest window.** Given the App's window, then its minimum size is 640 by 400 px (`minWidth`, `minHeight` in `crates/desktop/tauri.conf.json`), so the user cannot drag it to a size the layout does not define. At 640 by 400, the layout function U23 tests returns the Rail at 252 px, the Shelf under it (U24), the terminal at 388 px, and a Drawer no wider than 388 px, so no region overlaps another. Owns the window entry in `crates/desktop/tauri.conf.json` with one test in `crates/desktop/tests/app.rs`, and new cases in `apps/desktop/src/app/u23_layout.test.ts`. The tests that read `devUrl` and `frontendDist` keep passing as written, and no existing test is narrowed. Independent of every open PR.
